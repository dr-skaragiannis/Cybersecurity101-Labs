> Διαβάστε **πριν** από τα Μηχανήματα 1, 2, 4, 7, 9, 11 και 13. Καλύπτει τι είναι ένα αρχείο
> λίστας λέξεων, τη διαφορά μεταξύ κωδικοποίησης/κατακερματισμού/κρυπτογράφησης, και πώς

## 1. Τι είναι ένα «αρχείο λίστας λέξεων» (wordlist)

**Ένα απλό αρχείο κειμένου. Μία υποψήφια τιμή ανά γραμμή.** Τίποτα περισσότερο.

```text
password
123456
admin
letmein
qwerty
```

Όλες οι επιθέσεις λεξικού σε αυτή τη διαδρομή — **περιεχόμενο web, κωδικοί, ονόματα χρηστών,
ονόματα αρχείων** — είναι η ίδια ιδέα: *πάρε κάθε γραμμή του αρχείου και δοκίμασέ τη*. Το
εργαλείο αλλάζει· η αρχή όχι.

### 1.1 Οι κατηγορίες

| Κατηγορία | Παράδειγμα | Πότε |
| --- | --- | --- |
| **Γενική** | `rockyou.txt` (14,3 εκ.) | Πρώτη προσπάθεια. Περιέχει **πραγματικούς** κωδικούς από διαρροή του 2009 |
| **Συχνές** | `fasttrack.txt` (222) | **Πρώτα απ' όλα.** `admin`, `root`, `password`, `changeme` |
| **Στοχευμένη** | **Φτιαγμένη με `cewl` από το ίδιο το site** | Όταν το μηχάνημα είναι **θεματικό** (Μηχανήματα 4, 12, 13) |
| **Κανόνες** | `best64.rule`, `rockyou-30000.rule` | Μετασχηματισμοί πάνω σε υπάρχουσα λίστα |
| **Ονόματα χρηστών** | `usernames.txt`, `SecLists/Usernames/` | Spraying, απαρίθμηση SMTP/SMB |
| **Περιεχόμενο web** | `dirb/big.txt`, `SecLists/Discovery/Web-Content/` | Εύρεση διαδρομών |

### 1.2 Οι δύο κανόνες που οι αρχάριοι παραβιάζουν

**Κανόνας 1: από μικρή σε μεγάλη.** Μια λίστα 222 λέξεων τρέχει σε **χιλιοστά του δευτερολέπτου**.
Μια λίστα 14 εκατομμυρίων σε ώρες. **Πάντα** δοκιμάζετε τις πιθανότερες πρώτα. Στο Μηχάνημα 1 το
`admin:admin` βρίσκεται στο `fasttrack.txt` και πέφτει αμέσως· το `rockyou` θα χρειαζόταν λεπτά.

**Κανόνας 2: αφαιρέστε τα διπλότυπα πριν επιτεθείτε.**

```bash
sort -u -o list.txt list.txt
wc -l list.txt
```

```text
11451 list.txt
```

Στο Μηχάνημα 7 η λίστα του στόχου έχει **858.160** γραμμές και μετά το `sort -u` μένουν
**11.451** — **75 φορές λιγότερη δουλειά για ακριβώς το ίδιο αποτέλεσμα**, και 75 φορές λιγότερος
θόρυβος στα αρχεία καταγραφής του στόχου.

> **Προσοχή:** `sort -u f > f` **καταστρέφει** το αρχείο. Το κέλυφος ανοίγει (και μηδενίζει) το
> αρχείο εξόδου **πριν** εκτελεστεί η `sort`. Η σωστή μορφή είναι **`sort -u -o f f`**.

### 1.3 `cewl` — χτίζοντας λίστα από τον ίδιο τον στόχο

```bash
cewl -w words.txt -d 2 -m 5 http://TARGET/
cewl --with-numbers -e -c 2 -w words.txt http://TARGET/
```

| Σημαία | Σημασία |
| --- | --- |
| `-w FILE` | Εγγραφή της λίστας |
| `-d N` | **Βάθος** αναζήτησης (πόσους συνδέσμους να ακολουθήσει) |
| `-m N` | **Ελάχιστο μήκος** λέξης — το μεγαλύτερο φίλτρο θορύβου |
| `--with-numbers` | Δέξου και αλφαριθμητικούς «κωδικούς» |
| `-e` | Συμπερίλαβε και **διευθύνσεις email** |
| `-c N` | Κράτα μόνο λέξεις που εμφανίζονται **τουλάχιστον N φορές** |

**Γιατί είναι τόσο ισχυρό:** οι άνθρωποι επιλέγουν κωδικούς από το **περιβάλλον** τους. Ένα
μηχάνημα που λέγεται «Narak» και η αρχική σελίδα του είναι γεμάτη σανσκριτικές λέξεις για την
κόλαση → ο κωδικός είναι σχεδόν σίγουρα μία από αυτές. **Το `rockyou` δεν τις περιέχει.**
Το Μηχάνημα 4 (DC-2) απαιτεί `cewl` — αλλιώς η επίθεση απλώς δεν τελειώνει.

## 2. Κωδικοποίηση, κατακερματισμός, κρυπτογράφηση

Οι τρεις όροι συγχέονται συνεχώς, και η σύγχυση κοστίζει ώρες.

| | **Κωδικοποίηση** | **Κατακερματισμός** | **Κρυπτογράφηση** |
| --- | --- | --- | --- |
| **Σκοπός** | Αναπαράσταση σε άλλη **μορφή** | Απόδειξη ακεραιότητας / αποθήκευση κωδικών | **Εμπιστευτικότητα** |
| **Αντιστρέψιμο;** | **Ναι — τετριμμένα, χωρίς κλειδί** | **Όχι** (μόνο με μαντέψεις) | Ναι, **με το κλειδί** |
| **Κλειδί** | Κανένα | Κανένα | **Υπάρχει** |
| **Παραδείγματα** | base64, hex, URL-encoding, ROT13, brainfuck | MD5, SHA-256, bcrypt, phpass | AES, ChaCha20, RSA |
| **Τι κάνετε** | `base64 -d` | **Σπάσιμο** με λεξικό | **Βρείτε το κλειδί** |

> ### 📖 Το συμπέρασμα που πρέπει να μείνει
>
> **Το base64 δεν είναι μυστικό.** Υπάρχει για να επιζούν δυαδικά δεδομένα σε μέσα που
> μεταφέρουν μόνο κείμενο (συνημμένα email, κεφαλίδες HTTP, JSON). Το να βλέπετε base64 να
> «προστατεύει» έναν κωδικό είναι **εύρημα, όχι άμυνα**. Στο Μηχάνημα 2 ολόκληρο το μηχάνημα
> στηρίζεται σε αυτή τη σύγχυση: «η απόκρυψη δεν είναι εμπιστευτικότητα».

### 2.1 Αναγνώριση μορφής — με το μάτι και με εργαλείο

| Μορφή | Αναγνώριση | Παράδειγμα |
| --- | --- | --- |
| **MD5** | 32 δεκαεξαδικοί | `c3fcd3d76192e4007dfb496cca67e13b` |
| **SHA-1** | 40 δεκαεξαδικοί | `5baa61e4c9b93f3f0682250b6cf8331b7ee68fd8` |
| **SHA-256** | 64 δεκαεξαδικοί | `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855` |
| **NTLM** | 32 δεκαεξαδικοί — **ιδίων διαστάσεων με το MD5!** | Αμφισβητήσιμο χωρίς πλαίσιο |
| **MD5-crypt** | `$1$salt$hash` | `$1$ignite$XpO6y1nK1vB0yG0yQ3m0o0` |
| **SHA-256-crypt** | `$5$salt$hash` | — |
| **SHA-512-crypt** | `$6$salt$hash` (106–138 χαρακτήρες) | Προεπιλογή σε παλιά Ubuntu |
| **bcrypt** | `$2a$`, `$2b$`, `$2y$` + cost | `$2y$12$…` |
| **phpass** | `$P$` ή `$H$` (WordPress) ή `$S$` (Drupal) | — |
| **yescrypt** | `$y$` | **Προεπιλογή σε Debian 11+ / Ubuntu 22.04+** |
| **base64** | `A–Z a–z 0–9 + /` + `=` ή `==` | `YWRtaW46YWRtaW4=` |

```bash
hash-identifier
```
```text
-------------------------------------------------------------------------
 HASH: c3fcd3d76192e4007dfb496cca67e13b

Possible Hashs:
[+] MD5
[+] Domain Cached Credentials - MD4(MD4(($pass) . ($user)))
[+] MD5(WordPress)
[+] NTLM
…
-------------------------------------------------------------------------
```

**Διαβάστε το έτσι:** το εργαλείο **δεν μπορεί να ξέρει**. Δίνει **πιθανότητες** με βάση το
**μήκος και το σύνολο χαρακτήρων**. Το MD5 και το NTLM είναι **και τα δύο 32 δεκαεξαδικοί** —
αδιάκριτα χωρίς πλαίσιο. **Το πλαίσιο είναι που αποφασίζει:** αν το πήρατε από `/etc/shadow`,
είναι crypt· αν από Active Directory ή `secretsdump`, είναι NTLM· αν από WordPress, είναι
phpass.

> **Ο αλγόριθμος δεν αρκεί — χρειάζεστε και τη μορφή.** Ένα bare `c3fcd3d7…` μπορεί να δοθεί
> στο John ως `Raw-MD5` **ή** ως `NT` **ή** ως `md5crypt`, και **μόνο ένα είναι σωστό**. Το
> `--format=` δεν είναι λεπτομέρεια.

## 3. Πώς σπάνε πραγματικά τα hashes

### 3.1 Ο μηχανισμός

Ο κατακερματισμός κωδικών είναι **μονής κατεύθυνσης**: δεν «ξεδίνετε» το hash. Αντίθετα:

```text
για κάθε υποψήφιο κωδικό w στη λίστα:
    h = hash(w)          (ή hash(w + salt))
    αν h == το hash που έχουμε:  ΒΡΕΘΗΚΕ → w
```

**Αυτό σημαίνει ότι το κόστος = (αριθμός υποψηφίων) × (κόστος ενός hash).** Και οι δύο
παράγοντες είναι ό,τι ελέγχει ο αμυνόμενος.

### 3.2 Οι τέσσερις μέθοδοι επίθεσης

| Μέθοδος | Τι κάνει | hashcat `-a` | Πότε |
| --- | --- | --- | --- |
| **Λεξικό (straight)** | Κάθε γραμμή της λίστας, αυτούσια | `-a 0` | **Πρώτα. Πάντα.** |
| **Συνδυασμός** | Κάθε ζεύγος λέξεων από τη λίστα | `-a 1` | Δεύτερη προσπάθεια |
| **Μάσκα** | `?l?l?l?d?d?d` = 3 πεζά + 3 ψηφία | `-a 3` | Όταν ξέρετε το μοτίβο |
| **Υβριδική** | Λέξη + μάσκα (`word?d?d`) | `-a 6` / `-a 7` | Ισχυρή |
| **Κανόνες** | Μετασχηματισμοί πάνω σε λεξικό | `-a 0 -r rules/best64.rule` | **Η καλύτερη σχέση κόστους/απόδοσης** |

**Οι χαρακτήρες μάσκας:** `?l` πεζά · `?u` κεφαλαία · `?d` ψηφία · `?s` σύμβολα · `?a` όλα ·
`?b` 0x00–0xff. Άρα `?l?l?l?l?l?l` = 26⁶ = **308 εκατομμύρια** συνδυασμοί — πολύ για CPU,
εύκολο για GPU.

### 3.3 Οι κανόνες — γιατί αλλάζουν τα πάντα

Ένας **κανόνας** είναι μια συνταγή μετασχηματισμού. Το `best64.rule` περιέχει 64
μετασχηματισμούς: κεφαλαίο το πρώτο γράμμα, προσθήκη `123`, προσθήκη `!`, αντιστροφή,
`l33t`-μετάφραση (`a`→`4`).

```text
password  →  Password, PASSWORD, password1, password123, p@ssw0rd, drowssap, password!, …
```

**Ένα λεξικό που απέτυχε, πολύ συχνά πετυχαίνει με κανόνες** — με κόστος 64×. Στο Μηχάνημα 13
ο κωδικός είναι `john` (λέξη λεξικού) αλλά **σε άλλο μηχάνημα** το ίδιο `john` μπορεί να είναι
`John2020!` — και τότε μόνο οι κανόνες το βρίσκουν.

### 3.4 Γιατί τα salts και οι γύροι υπάρχουν

| Άμυνα | Τι κάνει | Αποτέλεσμα για εσάς |
| --- | --- | --- |
| **Salt** | Μοναδική τυχαία τιμή **ανά χρήστη**, προστίθεται πριν το hash | **Δύο χρήστες με τον ίδιο κωδικό έχουν διαφορετικό hash** → **δεν μπορείτε να χρησιμοποιήσετε πίνακες rainbow**, και κάθε hash πρέπει να σπαστεί **ξεχωριστά** |
| **Γύροι (iterations/cost)** | Το hash υπολογίζεται **χιλιάδες φορές** | Κάθε μαντέα κοστίζει χιλιάδες φορές περισσότερο |

**Αυτό εξηγεί τα πάντα όσον αφορά ταχύτητες:**

| Αλγόριθμος | Γύροι | Ταχύτητα σε σύγχρονη GPU |
| --- | --- | --- |
| **MD5 ακατάστατο** (`-m 0`) | 1 | **~22 GH/s** (δισεκατομμύρια/δευτ.) |
| **NTLM** (`-m 1000`) | 1 | ~20 GH/s |
| **SHA-256 ακατάστατο** (`-m 1400`) | 1 | ~7 GH/s |
| **MD5-crypt** (`-m 500`) | 1.000 | ~5 MH/s |
| **SHA-512-crypt** (`-m 1800`) | 5.000 | ~1 MH/s |
| **phpass / bcrypt** (`-m 400` / `3200`) | **8.192 / 4.096** | **~5–20 kH/s** (χιλιάδες!) |
| **Argon2id** | Μεγάλο κόστος μνήμης | Πολύ χαμηλά |

**Διαφορά 1.000.000× μεταξύ MD5 και bcrypt.** Ένας κωδικός 8 χαρακτήρων που σπάει σε
δευτερόλεπτα με MD5, με bcrypt χρειάζεται **δεκαετίες**. Αυτός είναι ολόκληρος ο λόγος που το
«σπασμένο MD5» είναι εύρημα υψηλής σοβαρότητας και το bcrypt όχι.

## 4. Οι επιθέσεις δικτύου — όταν δεν έχετε hash

Μερικές φορές δεν έχετε hash να σπάσετε, αλλά **υπηρεσία να δοκιμάσετε**.

| Πρωτόκολλο | Εργαλείο | Σημείωση |
| --- | --- | --- |
| **SSH** | `hydra -l user -P pass.txt ssh://TARGET` | Αργό — το SSH καθυστερεί επίτηδες |
| **FTP** | `hydra -l anonymous -P pass.txt ftp://TARGET` | Δοκιμάστε πρώτα `anonymous:anonymous` |
| **HTTP form** | `hydra -L users.txt -P pass.txt TARGET http-post-form "…"` | Χρειάζεται την ακριβή μορφή |
| **HTTP Basic** | `hydra -l admin -P pass.txt TARGET http-get /admin/` | — |
| **SMB** | `crackmapexec smb TARGET -u users.txt -p pass.txt` | **Καλύτερο** από hydra για SMB |
| **RDP** | `crowbar -b rdp -s TARGET/32 -u user -C pass.txt` | Το hydra δεν υποστηρίζει καλά RDP |
| **VNC** | `hydra -P pass.txt vnc://TARGET` | Χωρίς username |

### 4.1 Η διαφορά μεταξύ brute force, spraying και stuffing

| Τεχνική | Τι κάνει | Ανίχνευση |
| --- | --- | --- |
| **Brute force** | **Ένας** χρήστης, **όλοι** οι κωδικοί | **Πολύ θορυβώδης** — κλειδώνει τον λογαριασμό |
| **Password spraying** | **Όλοι** οι χρήστες, **ένας** κωδικός τη φορά | **Πολύ δυσκολότερη** στην ανίχνευση — κατανέμεται |
| **Credential stuffing** | Ζεύγη από **πραγματικές διαρροές** | Μεσαία |
| **Επανάχρηση** | Ο **ίδιος** κωδικός από τη βάση στο σύστημα | Καμία — είναι έγκυρη σύνδεση |

> **Σε αυτή τη διαδρομή η επανάχρηση κερδίζει περισσότερο από το brute force.** Μηχάνημα 1
> (`admin:admin`), 3 (κωδικός βάσης → λογαριασμός), 9 (`masteradmin` DB → `cengover` SSH),
> 11 (`babygirl` Koken → `daisa` σύστημα), 12 (`qwerty` από το `attention.txt` → SMB → SSH),
> 13 (`123456` container → host). **Έξι από τα δεκατρία μηχανήματα.**

### 4.2 `hydra` για HTTP φόρμα — η σημαία που μπερδεύει

```bash
hydra -L users.txt -P pass.txt TARGET \
  http-post-form "/login.php:username=^USER^&password=^PASS^:Invalid credentials"
```

| Μέρος | Σημασία |
| --- | --- |
| `-L users.txt` | **Λίστα** χρηστών |
| `-l user` | **Ένας** χρήστης |
| `-P pass.txt` | **Λίστα** κωδικών |
| `-p pass` | **Ένας** κωδικός |
| `-e nsr` | Δοκίμασε **n**ull (κενός κωδικός), **s**ame (κωδικός = username), **r**everse (αντεστραμμένος username) |
| `-t 4` | Νήματα — **χαμηλά για SSH**, υψηλά για HTTP |
| `-f` | **Σταμάτα στην πρώτη επιτυχία** |
| `-v` / `-V` | Δείχνει κάθε προσπάθεια |
| `-o out.txt` | Αποθήκευση |

**Η τριάδα του `http-post-form`, με `:` ως διαχωριστή:**

```text
/login.php  :  username=^USER^&password=^PASS^  :  Invalid credentials
   διαδρομή            το σώμα POST                  η συνθήκη αποτυχίας
```

- **Διαδρομή** — πού στέλνεται η φόρμα (`action` της `<form>`).
- **Σώμα** — οι παράμετροι, με **`^USER^`** και **`^PASS^`** ως placeholders.
- **Συνθήκη** — **τι εμφανίζεται στην απόκριση όταν ΑΠΟΤΥΓΧΑΝΕΙ**. Μπορεί να είναι κείμενο
  (`Invalid credentials`), κωδικός (`F=302` για ανακατεύθυνση, `S=302` για επιτυχία), ή
  `H=Location: /dashboard` για κεφαλίδα.

**Το πιο συχνό σφάλμα:** να γράψετε τη συνθήκη **επιτυχίας** όταν η σημαία περιμένει
**αποτυχία** (ή αντίστροφα). **Κοιτάξτε την πραγματική σελίδα:** στείλτε έναν λάθος κωδικό με
`curl` και δείτε τι τυπώνει.

```bash
curl -s --data "username=admin&password=wrong" http://TARGET/login.php | grep -i 'invalid\|error\|denied'
```

### 4.3 Ένα ολοκληρωμένο παράδειγμα ψεκασμού

```bash
# 1. Πήρατε χρήστες από το SMB
enum4linux -a TARGET | grep -oP 'user:\[\K[^\]]+' | sort -u > users.txt

# 2. Μικρή λίστα πιθανών κωδικών
printf '%s\n' 'Password1' 'Winter2023' 'Summer2023' 'Company1' 'qwerty' 'admin' > spray.txt

# 3. Ψεκασμός — ένας κωδικός για όλους
crackmapexec smb TARGET -u users.txt -p spray.txt --no-bruteforce
```

```text
SMB   192.168.56.101  445  SYMFONOS  [-] symfonos.local\helios:Password1 STATUS_LOGON_FAILURE
SMB   192.168.56.101  445  SYMFONOS  [-] symfonos.local\zeus:Password1 STATUS_LOGON_FAILURE
SMB   192.168.56.101  445  SYMFONOS  [+] symfonos.local\helios:qwerty
```

`grep -oP 'user:\[\K[^\]]+'` = Perl-regex με **`\K`** («ξέχνα ό,τι ταίριαξε πριν») — έτσι
παίρνετε **μόνο** τα ονόματα, χωρίς το `user:[`. Το `--no-bruteforce` δοκιμάζει **ζεύγη**
και όχι κάθε συνδυασμό: 6 χρήστες × 5 κωδικοί = **30 αιτήσεις**, όχι 6×5=30 συνδυασμούς σε
κάθε χρήστη.

**`STATUS_LOGON_FAILURE`** = λάθος κωδικός (όχι κλειδωμένος λογαριασμός, που θα ήταν
`STATUS_ACCOUNT_LOCKED_OUT`). **Πάντα ελέγχετε την πολιτική κλειδώματος πριν επιτεθείτε**
(`enum4linux` την τυπώνει).

## Ασκήσεις

1. **Αποδείξτε τη μονοδρομικότητα.** Κάντε hash σε έναν κωδικό με `md5sum` και μετά προσπαθήστε να τον ανακτήσετε με οποιαδήποτε μέθοδο εκτός από μαντεψιά. Γράψτε γιατί δεν μπορείτε.
2. **Κωδικοποίηση vs hashing.** Πάρτε το string `admin:password`, κωδικοποιήστε το σε base64 και μετά κάντε το MD5. Αντιστρέψτε και τα δύο. Καταγράψτε ποιο αντιστρέψατε χωρίς κλειδί.
3. **Χτίστε στοχευμένη λίστα λέξεων.** Στρέψτε το `cewl` σε οποιονδήποτε δημόσιο ιστότοπο σας ανήκει ή σε τοπική εφαρμογή, με `-m 4 --with-numbers -e`. Πόσες λέξεις; Πόσες μοιάζουν με πιθανούς κωδικούς;
4. **Σπάστε πραγματική μορφή.** Δημιουργήστε έναν δοκιμαστικό χρήστη σε Kali VM, κάντε `unshadow` στα αρχεία και σπάστε το με `john`. Μετά επιβάλλετε λάθος `--format=` και παρατηρήστε το σφάλμα.
5. **Μετρήστε το κόστος του αλγορίθμου.** Σπάστε τον ίδιο κωδικό αποθηκευμένο ως MD5 και ως bcrypt με hashcat και συγκρίνετε τα `H/s`. Εξηγήστε τη διαφορά σε μία πρόταση.

## 5. Έλεγχος γνώσεων

<details>
<summary><b>1.</b> Ένα hash είναι 32 δεκαεξαδικοί χαρακτήρες. Είναι MD5 ή NTLM;</summary>

**Δεν μπορείτε να ξέρετε από το ίδιο το hash.** Και τα δύο είναι 128 bit = 32 δεκαεξαδικοί.
Αποφασίζει **το πλαίσιο**: από `/etc/shadow` → crypt· από WordPress → phpass; από Active
Directory / `secretsdump` / `mimikatz` → NTLM; από URL ή API → συνήθως MD5.
</details>

<details>
<summary><b>2.</b> Τι προσφέρει το salt και τι ΔΕΝ προσφέρει;</summary>

**Προσφέρει:** (α) δύο χρήστες με τον ίδιο κωδικό έχουν **διαφορετικό hash**, άρα οι πίνακες
rainbow είναι άχρηστοι· (β) κάθε hash πρέπει να σπαστεί **ξεχωριστά**, άρα μια λίστα
δοκιμάζεται N φορές αντί μία. **ΔΕΝ προσφέρει:** δεν κάνει τον **κάθε μεμονωμένο** κωδικό πιο
δύσκολο. Ένα salted MD5 με δυνατό GPU σπάει σχεδόν το ίδιο γρήγορα με ένα unsalted — αυτό που
χρειάζεστε είναι **γύροι**, όχι μόνο salt.
</details>

<details>
<summary><b>3.</b> Γιατί το <code>Cost 1 (iteration count) is 5000</code> στο John είναι σημαντική πληροφορία;</b></summary>

Είναι το **work factor**: το hash υπολογίζεται 5.000 φορές για κάθε μαντέα. Αυτό καθορίζει τον
ρυθμό σας — αν το μηχάνημά σας κάνει 5.000 hash/s αντί για 5.000.000, μια λίστα 14 εκατομμυρίων
χρειάζεται **45 λεπτά** αντί για 3 δευτερόλεπτα. Σας λέει αν αξίζει να περιμένετε ή αν πρέπει
να μειώσετε τη λίστα.
</details>

<details>
<summary><b>4.</b> Ποια η διαφορά brute force και password spraying;</summary>

**Brute force:** ένας χρήστης × πολλοί κωδικοί → **κλειδώνει τον λογαριασμό** και φαίνεται
αμέσως. **Spraying:** πολλοί χρήστες × ένας (ή λίγοι) κωδικοί → **κάθε λογαριασμός βλέπει
μόνο 1–2 αποτυχίες**, κάτω από το όριο κλειδώματος, και η επίθεση κατανέμεται σε βάθος χρόνου.
</details>

<details>
<summary><b>5.</b> Τι κάνει η <code>-e nsr</code> στην hydra;</summary>

Προσθέτει τρεις **ιδιαίτερα πιθανούς** υποψήφιους χωρίς να τους έχετε στη λίστα: **n** = κενός
κωδικός, **s** = κωδικός **ίδιος με το username**, **r** = **αντεστραμμένο** username. Και οι
τρεις είναι από τους συνηθέστερους κωδικούς στην πραγματικότητα (ειδικά το «ίδιο με το
username»).
</details>

<details>
<summary><b>6.</b> Γιατί πρέπει να δοκιμάσετε μια μικρή λίστα πριν από το <code>rockyou.txt</code>;</summary>

Γιατί το κόστος είναι γραμμικό στο μήκος της λίστας και το `fasttrack.txt` (222 λέξεις)
περιέχει τους **πιθανότερους** κωδικούς υπηρεσιών. Στο Μηχάνημα 1 το `admin:admin` βρίσκεται
εκεί και πέφτει σε **δευτερόλεπτα**, ενώ με 14,3 εκατομμύρια λέξεις θα περιμένατε πολύ για το
ίδιο αποτέλεσμα — και θα γεμίζατε τα αρχεία καταγραφής του στόχου.
</details>

δώσετε μόνο το hash, το John τυπώνει `2g …` χωρίς λογαριασμό και δεν ξέρετε σε ποιον ανήκει.

```bash

```

**υποχρεωτικό όταν το hash είναι αμφίσημο** (32 hex). `--rules=` εφαρμόζει μετασχηματισμούς.
`--list=formats` δείχνει **όλες** τις μορφές που υποστηρίζει η έκδοσή σας.

### 6.2 `unshadow` — γιατί υπάρχει

```bash
grep -v '^[^:]*:[!*]' /etc/shadow > shadow.txt
unshadow /etc/passwd shadow.txt > combined.txt
john --wordlist=/usr/share/wordlists/rockyou.txt combined.txt
```

```text
root:$6$Xy9…:18920:0:99999:7:::
marlinspike:$6$Ab3…:18920:0:99999:7:::
```

Το σύγχρονο Linux χωρίζει τα στοιχεία: το **`/etc/passwd`** έχει τα **ονόματα** και `x` στη θέση
του hash· το **`/etc/shadow`** έχει τα **hashes** χωρίς ονόματα. Το **`unshadow` τα ενώνει** στην
παλιά μορφή ενός αρχείου, ώστε το **όνομα χρήστη να βρίσκεται δίπλα στο hash**.

**Γιατί αυτό έχει πρακτική αξία:** με το όνομα δίπλα, το John μπορεί να δοκιμάσει
**«ο κωδικός είναι ίδιος με το username»** — και αυτός είναι από τους συνηθέστερους κωδικούς
στον κόσμο. Χωρίς `unshadow`, το `marlinspike (marlinspike)` δεν θα βρισκόταν ποτέ.

### 6.8 Οι τέσσερις επιθέσεις της `hydra` σε ένα μηχάνημα

# 3. Ψεκασμός: πολλοί χρήστες, μικρή λίστα

> **Προειδοποίηση για SSH:** το SSH **επιβραδύνει επίτηδες** κάθε προσπάθεια (anti-brute-force).
> Με `-t 16` θα μπλοκαριστείτε ή θα πάρετε ψευδείς αποτυχίες. **`-t 4` είναι το ανώτατο όριο για
> SSH**· για HTTP μπορείτε άνετα 32–64.

### 6.9 Από την έξοδο του hashcat στο επόμενο βήμα

```bash
# Το hashcat έδωσε: root:$1$nW4r1F0L$hBn3…:john
# Τι κάνετε με αυτό;

# 1. Αν είναι λογαριασμός συστήματος → su ή ssh
su root
ssh root@TARGET

# 2. Αν είναι λογαριασμός web → σύνδεση στο admin panel
# 3. Αν είναι κωδικός βάσης → mysqldump
# 4. Αν είναι passphrase κλειδιού → ssh -i
ssh -i id_rsa user@TARGET

# 5. ΠΑΝΤΑ: δοκιμάστε τον ίδιο κωδικό σε ΟΛΕΣ τις υπηρεσίες
crackmapexec smb  TARGET -u root    -p john
crackmapexec ssh  TARGET -u root    -p john
hydra -l root -p john ftp://TARGET
```

**Το βήμα 5 είναι η επανάχρηση, και είναι το πιο παραγωγικό βήμα ολόκληρου του κεφαλαίου.**
Ένας κωδικός που σπάσατε σε **ένα** σύστημα είναι υποψήφιος για **όλα**. Στο Μηχάνημα 13 το
`123456` είναι κωδικός χρήστη στο container **και** του λογαριασμού στον οικοδεσπότη.
