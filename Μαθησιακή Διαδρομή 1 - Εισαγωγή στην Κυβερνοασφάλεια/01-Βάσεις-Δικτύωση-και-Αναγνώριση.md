# 01 — Βάσεις: Δικτύωση και Αναγνώριση

> Διαβάστε **πριν** από τα Μηχανήματα 1 έως 5. Αυτό το κεφάλαιο εξηγεί τι είναι μια θύρα, τι
> συμβαίνει πραγματικά όταν το `nmap` «βλέπει» μια ανοιχτή θύρα, και πώς να διαβάζετε το
> αποτέλεσμα μιας σάρωσης γραμμή προς γραμμή.

---

## 1. Τι είναι αναγνώριση και τι είναι απαρίθμηση

Οι δύο όροι χρησιμοποιούνται ως συνώνυμα και δεν είναι.

| | **Αναγνώριση** (Reconnaissance) | **Απαρίθμηση** (Enumeration) |
| --- | --- | --- |
| **Ερώτηση** | «Τι υπάρχει;» | «Τι τρέχει, ποια έκδοση, και τι μου επιτρέπει να κάνω;» |
| **Μιλάτε στον στόχο;** | Σχεδόν ποτέ | **Ναι, συνεχώς** |
| **Πηγές** | Μητρώα WHOIS, Certificate Transparency, Shodan, Google, GitHub, LinkedIn, αρχεία DNS | Απαντήσεις TCP/UDP, HTTP headers, SMB, SNMP, βάσεις δεδομένων |
| **Ίχνη** | Ελάχιστες | **Πολλές** — μένετε στα αρχεία καταγραφής |
| **Παράδειγμα** | «Η εταιρεία κατέχει τα 203.0.113.0/24 και χρησιμοποιεί WordPress» | «Η θύρα 443 τρέχει Apache 2.4.49 με `/server-status` ανοιχτό» |

**Στο εργαστήριο η αναγνώριση είναι σχεδόν ασήμαντη** — ξέρετε ήδη τη διεύθυνση IP, γιατί εσείς
ανοίξατε το VM. Στην πραγματική δουλειά είναι το 60% του χρόνου. Η **απαρίθμηση** όμως είναι το
ίδιο κρίσιμη και στις δύο περιπτώσεις, και είναι αυτή στην οποία θα αφιερώσετε τον περισσότερο
κόπο σε αυτή τη διαδρομή.

> ### 📖 Σύνοψη — Γιατί η απαρίθμηση κερδίζει τα περισσότερα μηχανήματα
>
> Σχεδόν κάθε επιτυχία σε αυτή τη διαδρομή ήρθε από **καλύτερη απαρίθμηση**, όχι από πιο
> έξυπνο exploit. Το Μηχάνημα 8 κερδίζεται από ένα `getcap`. Το Μηχάνημα 12 από μια θύρα 25 που
> κανείς δεν κοίταξε. Το Μηχάνημα 13 από μια θύρα 8000 που δεν υπάρχει στη λίστα των 1.000
> συνηθισμένων θυρών του nmap. **Ο επιτιθέμενος που ψάχνει περισσότερο κερδίζει.**

## 2. IP, MAC, ARP — τα τρία επίπεδα που χρειάζεστε

### 2.1 Διευθύνσεις IP

```text
192.168.56.101
└──┬──┘ └─┬─┘
  δίκτυο  ξενιστής        (με /24: 24 bit δίκτυο, 8 bit ξενιστής)
```

| Εύρος | Τι είναι | Πού το βλέπετε |
| --- | --- | --- |
| `10.0.0.0/8` | Ιδιωτικό, τάξη Α | Εταιρικά δίκτυα, Docker |
| `172.16.0.0/12` | Ιδιωτικό, τάξη Β | Docker (`172.17.0.0/16`) |
| `192.168.0.0/16` | Ιδιωτικό, τάξη Γ | **Το σπίτι σας και το VirtualBox** |
| `169.254.0.0/16` | Link-local (APIPA) | **Αποτυχία DHCP** — αν τη δείτε, δεν πήρατε διεύθυνση |
| `127.0.0.0/8` | Loopback | «Εγώ ο ίδιος» |

**Η `169.254.x.x` είναι διαγνωστική.** Αν ο Kali σας δείξει τέτοια διεύθυνση στο `eth1`, το
host-only δίκτυο δεν υπάρχει ή ο adapter δεν είναι πάνω.

### 2.2 MAC και το πρωτόκολλο ARP

Η **MAC** είναι η φυσική διεύθυνση της κάρτας δικτύου, 48 bit, γραμμένη στο υλικό:
`08:00:27:3d:9a:52`. Τα πρώτα 24 bit είναι το **OUI** — ο κωδικός του κατασκευαστή.

Το **ARP** γεφυρώνει τα δύο επίπεδα: ρωτάει «ποιος έχει το 192.168.56.101; πες μου τη MAC σου»
και όλοι στο τοπικό δίκτυο ακούνε.

```bash
arp -a
ip neigh
```

```text
? (192.168.56.101) at 08:00:27:3d:9a:52 [ether] on eth1
? (192.168.56.1) at 0a:00:27:00:00:0e [ether] on eth1
```

**Γιατί έχει σημασία για εσάς:**
1. Το ARP **δεν περνάει router** → λειτουργεί μόνο μέσα στο εργαστήριο, και γι' αυτό η εύρεση
   ξενιστών με ARP είναι απόλυτα αξιόπιστη εκεί.
2. Το OUI αποκαλύπτει τον κατασκευαστή → `08:00:27` = Oracle/VirtualBox = **εικονική μηχανή**.
3. Μια **δεύτερη MAC για την ίδια IP** σημαίνει ARP poisoning — δηλαδή επίθεση σε εξέλιξη.
4. Το ARP **δεν μπορεί να μπλοκαριστεί** από firewall του ξενιστή: απαντάει ο πυρήνας.

## 3. Θύρες, πρωτόκολλα, και η χειραψία TCP

### 3.1 Τι είναι θύρα

Μια διεύθυνση IP βρίσκει τον **υπολογιστή**· μια θύρα βρίσκει το **πρόγραμμα** μέσα του. Ένας
υπολογιστής με μία IP μπορεί να εξυπηρετεί web (80), SSH (22) και MySQL (3306) ταυτόχρονα,
επειδή το καθένα ακούει σε άλλη θύρα.

| Εύρος | Όνομα | Παράδειγμα |
| --- | --- | --- |
| 0–1023 | **Well-known / προνομιούχες** | 21 FTP, 22 SSH, 25 SMTP, 53 DNS, 80 HTTP, 139/445 SMB, 443 HTTPS |
| 1024–49151 | **Καταχωρημένες** | 3306 MySQL, 3389 RDP, 5432 Postgres, 8000/8080 εναλλακτικά HTTP, 8443, 10000 Webmin, 20000 Usermin |
| 49152–65535 | **Εφήμερες (ephemeral)** | Τις παίρνει ο **πελάτης** για κάθε σύνδεση |

**Χρειάζεστε `sudo` για να ακούσετε σε θύρα < 1024.** Γι' αυτό το `nc -lvnp 80` αποτυγχάνει
χωρίς δικαιώματα root, ενώ το `nc -lvnp 4444` δουλεύει.

**Οι θύρες που κερδίζουν CTF είναι σχεδόν πάντα μη τυπικές:** 8000, 8080, 8888, 31337, 10000,
20000. Αυτό σημαίνει ότι **`-p-` (όλες οι θύρες) δεν είναι πολυτέλεια, είναι απαραίτητο.**

### 3.2 Η χειραψία τριών βημάτων

```text
Πελάτης                              Εξυπηρετητής
   │  ── SYN (seq=x) ───────────────►  │   «θέλω να μιλήσουμε»
   │  ◄── SYN+ACK (seq=y, ack=x+1) ──  │   «ναι, κι εγώ»
   │  ── ACK (ack=y+1) ─────────────►  │   «ωραία, ξεκινάμε»
   │  ◄══════ δεδομένα ═════════════►  │
```

Και η **άρνηση**:

```text
   │  ── SYN ───────────────────────►  │
   │  ◄── RST+ACK ───────────────────  │   «κανείς δεν ακούει εκεί»
```

Και η **σίγαση** (firewall):

```text
   │  ── SYN ───────────────────────►  │
   │         (τίποτα, ξανά, ξανά…)     │   «το πακέτο πετάχτηκε»
```

**Αυτές οι τρεις αποκρίσεις είναι ακριβώς οι τρεις καταστάσεις που τυπώνει το nmap.** Τώρα
ξέρετε τι σημαίνουν πραγματικά.

### 3.3 Οι έξι καταστάσεις του nmap — και τι σημαίνει η καθεμία

| Κατάσταση | Τι συνέβη | Τι σημαίνει για εσάς |
| --- | --- | --- |
| **`open`** | Ήρθε SYN+ACK | **Υπάρχει υπηρεσία.** Εδώ δουλεύετε |
| **`closed`** | Ήρθε RST | Ο ξενιστής είναι **πάνω**, αλλά κανείς δεν ακούει. Χρήσιμη πληροφορία! |
| **`filtered`** | Καμία απάντηση ή ICMP unreachable | **Firewall** πέταξε το πακέτο. Δεν ξέρετε αν υπάρχει υπηρεσία |
| **`unfiltered`** | Απάντηση RST σε σάρωση ACK | Το φίλτρο επιτρέπει την πρόσβαση· άλλη τεχνική χρειάζεται |
| **`open\|filtered`** | Καμία απάντηση σε **UDP** | Δεν μπορείτε να ξεχωρίσετε — δείτε §4.3 |
| **`closed\|filtered`** | Καμία απάντηση σε σάρωση IP protocol | Σπάνιο |

**Η διαφορά `closed` vs `filtered` είναι διαγνωστική.** `closed` = το μηχάνημα απαντά και είναι
ζωντανό, απλώς δεν έχει τίποτα εκεί → **χωρίς firewall**. `filtered` = κάτι ανάμεσα σε εσάς και
στον στόχο πετάει πακέτα → **θα χρειαστείτε άλλη μέθοδο** (slow scan, διαφορετική τεχνική,
πηγή από άλλο δίκτυο).

## 4. Πώς δουλεύει το nmap

Το `nmap` δεν είναι μαγεία. Στέλνει πακέτα, κοιτάζει τι γύρισε, και συμπεραίνει. Η
**τεχνική σάρωσης** καθορίζει τι πακέτο στέλνει.

### 4.1 Οι τεχνικές που θα χρησιμοποιήσετε

| Σημαία | Τεχνική | Πακέτα | Χρειάζεται root; | Πότε |
| --- | --- | --- | --- | --- |
| `-sS` | **SYN / half-open** | SYN μόνο· **δεν ολοκληρώνει** τη χειραψία | **Ναι** | **Προεπιλογή με sudo.** Γρήγορη, λιγότερο θορυβώδης |
| `-sT` | **Connect** | Πλήρης χειραψία μέσω του λειτουργικού | Όχι | Όταν δεν έχετε root |
| `-sU` | **UDP** | Κενό πακέτο UDP | Ναι | Για DNS, SNMP, TFTP |
| `-sV` | **Έκδοση** | Συνδέεται και διαβάζει το banner | Ναι για θύρες <1024 | **Πάντα** |
| `-sC` | **Scripts (default)** | NSE scripts | — | **Πάντα** |
| `-sn` | **Ping sweep** | Μόνο ανακάλυψη ξενιστών | Ναι | Για να βρείτε το VM |
| `-sA` | ACK | Μόνο ACK | Ναι | Ανίχνευση φίλτρου |
| `-O` | OS detection | Ανάλυση TCP stack | Ναι | Λιγότερο αξιόπιστο από το banner |

**Γιατί η `-sS` είναι προτιμότερη:** δεν ολοκληρώνει τη χειραψία, άρα η εφαρμογή **δεν
καταγράφει ποτέ τη σύνδεση** — μόνο το λειτουργικό βλέπει το SYN και το κλείνει με RST. Σε
πραγματικό pentest αυτό είναι η διαφορά μεταξύ «δεν φάνηκε τίποτα» και «ο διαχειριστής είδε
10.000 συνδέσεις».

### 4.2 `-sV` και `-sC` — πώς βρίσκει την έκδοση

Το `-sV` κάνει κάτι απλό και ισχυρό: **συνδέεται και διαβάζει ό,τι λέει η υπηρεσία.**

```text
220 (vsFTPd 3.0.3)          ← FTP: το banner δίνει την έκδοση δωρεάν
HTTP/1.1 200 OK
Server: Apache/2.4.38        ← HTTP: η κεφαλίδα Server
220 deb10 ESMTP Postfix      ← SMTP: η ταυτότητα του εξυπηρετητή
```

Όταν δεν υπάρχει banner, το nmap **ρωτάει**: στέλνει συγκεκριμένα probes (ένα `GET /` HTTP,
ένα `NULL` SMB, μια χειραψία SSL) και **συγκρίνει την απάντηση με χιλιάδες υπογραφές** στη βάση
`nmap-service-probes`. Γι' αυτό μερικές φορές γράφει `(Debian)` ή `Ubuntu 18.04` — το αναγνώρισε
από τον συνδυασμό headers, όχι από κάποια δήλωση.

Το `-sC` τρέχει τα **NSE scripts** της κατηγορίας `default`: ασφαλή, γρήγορα, και πολύ
πληροφοριακά. Παραδείγματα: `http-robots.txt` (διαβάζει το robots.txt για εσάς), `ftp-anon`
(δοκιμάζει ανώνυμη σύνδεση), `ssh-hostkey` (εμφανίζει τα κλειδιά), `smb-os-discovery`.

> ### 📖 Σύνοψη — Τι είναι «banner» και γιατί το banner grabbing είναι το πρώτο βήμα
>
> Πολλές υπηρεσίες **ανακοινώνουν την έκδοσή τους** στην πρώτη γραμμή της σύνδεσης, γιατί έτσι
> σχεδιάστηκαν (βοηθάει στη διάγνωση). Αυτό λέγεται **banner**. Μπορείτε να το διαβάσετε μόνοι
> σας χωρίς nmap:
>
> ```bash
> nc TARGET 21          # FTP
> nc TARGET 25          # SMTP
> curl -sI http://TARGET/  # HTTP headers
> openssl s_client -connect TARGET:443 2>/dev/null | head
> ```
>
> **Η έκδοση είναι το κλειδί όλης της διαδρομής.** Μόλις ξέρετε «Apache 1.3.20 με mod_ssl
> 2.8.4», το exploit δεν είναι εξυπνάδα — είναι **αναζήτηση**.

### 4.3 UDP — γιατί βλέπετε `open|filtered`

```bash
sudo nmap -sU --top-ports 50 TARGET
```

```text
PORT    STATE         SERVICE
53/udp  open|filtered domain
68/udp  open|filtered dhcpc
123/udp open|filtered ntp
137/udp open|filtered netbios-ns
161/udp open|filtered snmp
```

**Το UDP είναι πρωτόκολλο χωρίς σύνδεση** — δεν υπάρχει χειραψία, άρα δεν υπάρχει «άνοιγμα»
που να μπορείς να επιβεβαιώσεις. Η λογική του nmap:

| Απόκριση UDP | Συμπέρασμα |
| --- | --- |
| Ήρθε κάποιο πακέτο UDP πίσω | **`open`** — σίγουρα |
| Ήρθε ICMP *port unreachable* | **`closed`** — σίγουρα |
| **Τίποτα** | **`open|filtered`** — **δεν μπορώ να ξέρω** |

Η τρίτη περίπτωση είναι η συνήθης, και **δεν σημαίνει «ανοιχτή»**. Σημαίνει «ή ανοιχτή και
σιωπηλή, ή μπλοκαρισμένη». Για να αποφανθείτε: `sudo nmap -sU -p 161 --version-intensity 9 TARGET`
ή δοκιμάστε το πρωτόκολλο με το δικό του εργαλείο (`snmpwalk`, `dig`).

## 5. Οι τυπικές θύρες που θα συναντήσετε

| Θύρα | Υπηρεσία | Τι απαριθμείτε | Τι ψάχνετε |
| --- | --- | --- | --- |
| **21** | FTP | `ftp`, `curl ftp://`, `nmap --script ftp-anon` | **Ανώνυμη σύνδεση**, εκδόσεις με backdoor, `.ftpaccess` |
| **22** | SSH | banner, `ssh-audit` | Παλιά πρωτόκολλα (SSHv1), αδύναμα κλειδιά, χρήστες |
| **25** | SMTP | `nc`, `smtp-user-enum`, VRFY/EXPN | **Εύρεση χρηστών**, ανοιχτή αναμετάδοση, **δηλητηρίαση αρχείου καταγραφής** |
| **53** | DNS | `dig`, `dnsrecon` | Μεταφορά ζώνης (AXFR), subdomains |
| **80/443/8000/8080** | HTTP(S) | `dirb`, `gobuster`, `ffuf`, `nikto`, `whatweb` | **Τα πάντα.** Το μεγαλύτερο attack surface |
| **111** | RPCbind | `rpcinfo -p` | NFS, mountd |
| **139/445** | SMB | `smbclient`, `smbmap`, `enum4linux`, `crackmapexec` | **Ανώνυμα κοινόχρηστα**, χρήστες, εκδόσεις Samba |
| **161** | SNMP | `snmpwalk -v2c -c public` | Το community string `public`, πλήρης παραμετροποίηση |
| **2049** | NFS | `showmount -e` | `no_root_squash`, εγγράψιμες εξαγωγές |
| **3306/5432** | MySQL/Postgres | `mysql -h`, `psql` | Κενός κωδικός, `root:root`, έκθεση στο δίκτυο |
| **8009** | AJP | `ajp_shooter.py` | Ghostcat (CVE-2020-1938) |
| **10000/20000** | Webmin/Usermin | HTTP + έρευνα έκδοσης | CVEs, **κονσόλα εντολών** |

## Ασκήσεις

Κάντε τις πριν το Μηχάνημα 1. Δεν χρειάζονται VM-στόχο.

1. **Διαβάστε το δικό σας δίκτυο.** Τρέξτε `ip -br a`, `ip route`, `arp -a` και `cat /etc/resolv.conf`. Σημειώστε τι σας λέει το καθένα. Ποια διεπαφή θα χρησιμοποιούσατε για σάρωση εργαστηρίου;
2. **Σαρώστε τον εαυτό σας.** `sudo nmap -sV -p- 127.0.0.1`, μετά το ίδιο με `--reason`. Εξηγήστε κάθε γραμμή εξόδου. Τώρα τρέξτε `sudo nmap -sS` και σημειώστε τι αλλάζει.
3. **Αποδείξτε τη χειραψία στον εαυτό σας.** Ξεκινήστε έναν ακροατή (`python3 -m http.server 8000`) και σε άλλο τερματικό τρέξτε `sudo nmap -p 8000 --reason 127.0.0.1` — δείτε τον server να καταγράφει το αίτημα. Σκοτώστε τον server και ξανασαρώστε: η κατάσταση αλλάζει από `open` σε `closed`. Εξηγήστε γιατί, με όρους SYN/SYN-ACK/RST.
4. **Βρείτε μια φιλτραρισμένη θύρα.** Με το firewall του λειτουργικού σας απορρίψτε (DROP, όχι REJECT) μια θύρα, σαρώστε την και παρατηρήστε `filtered`. Τι έστειλε πραγματικά πίσω ο στόχος;
5. **Απαριθμήστε έναν πραγματικό ιστότοπο — μόνο ανάγνωση και ευγενικά.** Διαλέξτε έναν ιστότοπο που σας ανήκει ή έναν σκόπιμα ευπαθή στόχο εξάσκησης όπως το [OWASP Juice Shop](https://owasp.org/www-project-juice-shop/) τοπικά σε Docker. Τρέξτε `curl -sI`, διαβάστε κάθε κεφαλίδα και σημειώστε τι αποκαλύπτει. **Μη σαρώνετε, μην κάνετε brute force και μην επιτίθεστε σε ιστότοπο που δεν σας ανήκει.**

## 6. Έλεγχος γνώσεων

<details>
<summary><b>1.</b> Ποια η διαφορά μεταξύ <code>closed</code> και <code>filtered</code>, και γιατί σας νοιάζει;</summary>

`closed` = ο ξενιστής απάντησε με **RST**: είναι πάνω, δεν υπάρχει υπηρεσία στη θύρα, και **δεν
υπάρχει firewall** ανάμεσα. `filtered` = **καμία απάντηση**: κάτι πετάει τα πακέτα, άρα δεν
ξέρετε αν υπάρχει υπηρεσία. Σας νοιάζει γιατί καθορίζει τη μέθοδο: με `filtered` χρειάζεστε
αργότερη σάρωση, άλλη τεχνική (`-sA`, `-sU`), ή πρόσβαση από άλλο δίκτυο.
</details>

<details>
<summary><b>2.</b> Γιατί η <code>-sS</code> λέγεται «half-open» και γιατί είναι προτιμότερη;</summary>

Στέλνει SYN, παίρνει SYN+ACK, και **στέλνει RST αντί για το τελικό ACK** — άρα η χειραψία δεν
ολοκληρώνεται ποτέ. Επειδή η σύνδεση δεν φτάνει σε επίπεδο εφαρμογής, **η εφαρμογή δεν την
καταγράφει**. Είναι επίσης ταχύτερη, γιατί δεν περιμένει πλήρη διαπραγμάτευση.
</details>

<details>
<summary><b>3.</b> Τι σημαίνει <code>open|filtered</code> σε θύρα UDP;</summary>

Ότι το nmap **δεν πήρε καμία απάντηση**. Θα μπορούσε να είναι ανοιχτή υπηρεσία που απλώς δεν
ανταποκρίθηκε στο κενό probe, ή θα μπορούσε να είναι μπλοκαρισμένη. **Δεν είναι επιβεβαίωση**
— χρειάζεται έλεγχος με το πρωτόκολλο (π.χ. `dig` για 53, `snmpwalk` για 161).
</details>

<details>
<summary><b>4.</b> Πώς βρίσκει το nmap την έκδοση μιας υπηρεσίας που δεν τυπώνει banner;</summary>

Στέλνει **προκαθορισμένα probes** από τη βάση `nmap-service-probes` (ένα HTTP GET, ένα SMB
NULL session, μια TLS χειραψία κ.λπ.) και **συγκρίνει την απάντηση με χιλιάδες υπογραφές**.
Όταν αναγνωρίσει τον συνδυασμό, τυπώνει την έκδοση και συχνά το λειτουργικό (π.χ. `(Ubuntu)`).
</details>

<details>
<summary><b>5.</b> Γιατί το <code>-p-</code> είναι απαραίτητο και όχι πολυτέλεια;</summary>

Γιατί η προεπιλογή του nmap είναι οι **1.000 συνηθέστερες** θύρες, και τα μηχανήματα CTF
κρύβουν συστηματικά τις υπηρεσίες τους εκτός αυτής της λίστας: 8000, 8080, 7744, 31337,
10000, 20000. Το Μηχάνημα 4 έχει SSH στο **7744**· το Μηχάνημα 13 δεν έχει θύρα 80 **καθόλου**,
μόνο 8000. Χωρίς `-p-` θα συμπεραίνατε λανθασμένα ότι δεν υπάρχει επίθετη επιφάνεια.
</details>

<details>
<summary><b>6.</b> Τι σας λέει το <code>ttl=64</code> σε ένα ping;</summary>

Το **Time To Live** αρχίζει από μια χαρακτηριστική τιμή ανά λειτουργικό: 64 για Linux/Unix,
128 για Windows, 255 για Cisco/συσκευές δικτύου. Κάθε δρομολογητής το μειώνει κατά 1. Άρα
`ttl=64` σε τοπικό δίκτυο = **Linux, 0 δρομολογητές μακριά**. Αν δείτε `ttl=62`, είναι Linux
δύο άλματα μακριά.
</details>

### 7.1 `ip -br a` — η κατάσταση του δικτύου μου σε μία γραμμή

```bash

```

```text

eth0             UP             10.0.2.15/24 fe80::a00:27ff:fe4e:66a1/64
```

> `Failed to open normal output file` αν δεν έχετε κάνει `mkdir -p scans` πρώτα.

**Ανάγνωση γραμμή προς γραμμή:**

1. **`Not shown: 65531 closed tcp ports (conn-refused)`** — αυτή η γραμμή είναι **πληροφορία,
   όχι θόρυβος**. `65535 − 65531 = 4` θύρες ενδιαφέρουσες. Το `conn-refused` σημαίνει ότι ήρθε
   **RST**, δηλαδή **δεν υπάρχει firewall**. Αν έλεγε `filtered (no-response)`, η στρατηγική σας
   θα έπρεπε να αλλάξει εντελώς.
2. **`21/tcp open ftp ProFTPD 1.3.3c`** — τέσσερα πεδία: θύρα/πρωτόκολλο, κατάσταση, όνομα
   υπηρεσίας από τη λίστα του nmap, **έκδοση από το banner**. Η έκδοση είναι αυτή που ψάχνετε.
3. **`ftp-anon: Anonymous FTP login allowed (FTP code 230)`** — NSE finding. Το **230 είναι ο
   κωδικός «επιτυχής σύνδεση» του FTP**, άρα η ανώνυμη πρόσβαση είναι πραγματικά ανοιχτή, όχι
   απλώς πιθανή.
4. **`|-rw-r--r-- 1 0 0 1477 Dec 07 2017 deets.txt`** — το script μπήκε κιόλας μέσα και
   τυπώνει τη λίστα. Δείτε ότι ο **ιδιοκτήτης είναι `0`** (δηλαδή **root**) — αρχείο root σε
   ανώνυμο FTP.
5. **`OpenSSH 7.2p2 Ubuntu 4ubuntu2.4`** — διπλή πληροφορία: έκδοση OpenSSH **και** πακέτο
   Ubuntu. Το `4ubuntu2.4` σημαίνει **Ubuntu 16.04**, που σας δίνει και την ηλικία του kernel.
6. **`ssh-hostkey: 2048 … (RSA)`** — τύπος και μέγεθος κλειδιού ξενιστή. Ένα κλειδί **1024-bit
   DSA** είναι εύρημα από μόνο του (το DSA περιορίζεται στα 1024 bit από το πρότυπο και έχει
   απενεργοποιηθεί).
7. **`Service Info: Hosts: 127.0.1.1, LAB`** — **διαρροή ονόματος ξενιστή**. Το `LAB` πρέπει να
   μπει στο `/etc/hosts` σας, γιατί πολλές εφαρμογές (WordPress, Koken) είναι ρυθμισμένες με
   το δικό τους hostname και συμπεριφέρονται παράξενα όταν τις καλείτε με IP.
8. **`scanned in 128.44 seconds`** — δύο λεπτά για όλες τις θύρες με `-T4`. Αν δείτε πάνω από
   20 λεπτά, κάτι μπλοκάρει: συνήθως το VM δεν έχει δεύτερο adapter, ή έχετε ξεχάσει το `sudo`.

### 7.7 `curl -sI` — ανάγνωση κεφαλίδων

```bash
curl -sI http://TARGET/
```

```text
HTTP/1.1 200 OK
Date: Sat, 11 May 2024 09:55:12 GMT
Server: Apache/2.4.38 (Debian)
X-Powered-By: PHP/7.3.33-1~deb10u1
Set-Cookie: PHPSESSID=q3f8l7k9v2m5n1b4; path=/
Content-Type: text/html; charset=UTF-8
```

`-s` = **silent** (χωρίς μπάρα προόδου), `-I` = **μόνο οι κεφαλίδες** (μέθοδος HEAD).

**Τι διαβάζετε:**
- **`Server:`** — ο διακομιστής και συχνά το λειτουργικό. Εδώ `Apache/2.4.38 (Debian)` →
  **Debian 10**.
- **`X-Powered-By:`** — η γλώσσα και η **ακριβής έκδοση**. `PHP/7.3.33` σας λέει ποια CVEs
  ισχύουν.
- **`Set-Cookie:`** — το όνομα του session cookie είναι **αποτύπωμα πλαισίου**: `PHPSESSID` =
  σκέτη PHP, `JSESSIONID` = Java, `ASP.NET_SessionId` = .NET, `koken_session_ci` = Koken CMS.
- **`HTTP/1.1 200 OK`** — ο κωδικός κατάστασης (δείτε §7.8).

**Και το αρνητικό είναι πληροφορία:** αν **λείπει** το `Server:`, κάποιος έκανε
`ServerTokens Prod` — δηλαδή υπάρχει διαχειριστής που ξέρει τι κάνει, και η εφαρμογή μπορεί να
είναι καλύτερα συντηρημένη από ό,τι περιμένατε.

### 7.8 Οι κωδικοί κατάστασης HTTP που πρέπει να γνωρίζετε

| Κωδικός | Όνομα | Τι σημαίνει στην πράξη |
| --- | --- | --- |
| **200** | OK | Υπάρχει και σερβίρεται |
| **201** | Created | Η μεταφόρτωση **πέτυχε** — διαβάστε το body για τη διαδρομή |
| **301** | Moved Permanently | Μετακόμισε **μόνιμα**. Δείτε το `Location:` — συχνά αποκαλύπτει hostname |
| **302** | Found (προσωρινή) | **Ανακατεύθυνση σε login** = πίσω από πιστοποίηση. Ή **σε σφάλμα** = η φόρμα απέρριψε την είσοδό σας |
| **400** | Bad Request | Η αίτησή σας ήταν λανθασμένη (συχνά: κακό URL-encoding) |
| **401** | Unauthorized | **Χρειάζεται πιστοποίηση** (και δεν δώσατε) |
| **403** | Forbidden | **Υπάρχει αλλά απαγορεύεται.** Πολύ ενδιαφέρον — δοκιμάστε άλλη μέθοδο ή άλλη διαδρομή |
| **404** | Not Found | Δεν υπάρχει… **ή υπάρχει και το έκρυψαν** |
| **500** | Internal Server Error | **Σφάλμα στην εφαρμογή.** Μετά από `'` ή `"` = **πιθανότατα SQL injection** |

> **Η κρίσιμη διάκριση 401 vs 403:** το **401** λέει «δεν ξέρω ποιος είσαι»· το **403** λέει
> «ξέρω ποιος είσαι και δεν επιτρέπεται». Σε μια σάρωση περιεχομένου, ένα **403** σε
> `/admin/config.php` είναι *πολύ* πιο ενδιαφέρον από ένα 404 — το αρχείο υπάρχει.

### 7.11 `/etc/hosts` — γιατί τα CMS το απαιτούν

```bash
echo "TARGET lab-server" | sudo tee -a /etc/hosts
getent hosts lab-server
```

```text
TARGET  lab-server
```

**`sudo tee -a` και όχι `sudo echo >>`.** Ο λόγος είναι λεπτός και σημαντικός: το κέλυφος
επεξεργάζεται την ανακατεύθυνση `>>` **πριν** εκτελέσει την εντολή, άρα το άνοιγμα του
`/etc/hosts` για εγγραφή γίνεται **με τα δικαιώματα του δικού σας χρήστη** — και παίρνετε
`Permission denied`. Η `tee` ανοίγει το αρχείο **ως root**, γιατί αυτή εκτελείται υπό sudo.

**Γιατί χρειάζεται.** Πολλές εφαρμογές (WordPress, Drupal, Koken) αποθηκεύουν το **δικό τους
base URL** στη βάση δεδομένων. Αν τις καλέσετε με IP, δημιουργούν συνδέσμους προς το hostname,
άρα οι ανακατευθύνσεις σας πετάνε σε ένα όνομα που δεν επιλύεται. Το Μηχάνημα 1 απαιτεί
`vtcsec`, το Μηχάνημα 4 `dc-2`, το Μηχάνημα 12 `symfonos.local`, το Μηχάνημα 13 `hackinos`.

### 7.12 `python3 -m http.server` — ο δικός σας εξυπηρετητής

```bash
python3 -m http.server 8000
```

```text
Serving HTTP on 0.0.0.0 port 8000 (http://0.0.0.0:8000/) ...
192.168.56.101 - - [11/May/2024 10:12:44] "GET /exploit.c HTTP/1.1" 200 -
```

`0.0.0.0` = **ακούει σε όλες τις διεπαφές**, άρα το θύμα μπορεί να σας φτάσει. Αν έλεγε
`127.0.0.1`, θα ακουγόταν μόνο τοπικά και η λήψη θα αποτύγχανε.

**Η γραμμή καταγραφής είναι η επιβεβαίωσή σας:** IP του πελάτη, ώρα, μέθοδος και διαδρομή,
**κωδικός κατάστασης**. Ένα `200` σημαίνει ότι σερβίρατε το αρχείο επιτυχώς. Ένα `404` σημαίνει
λάθος όνομα — συνήθως επειδή τρέξατε τον εξυπηρετητή από λάθος φάκελο.

Χρήσεις: μεταφορά exploit στο θύμα, φιλοξενία του δικού σας payload, **και ανίχνευση
εξερχόμενων συνδέσεων** (αν το θύμα κάνει αίτηση, ξέρετε ότι μπορεί να βγει προς τα έξω —
δηλαδή ότι ένα reverse shell θα δουλέψει).

`-O ofs.c` = αποθήκευση **με άλλο όνομα**. Διαβάστε το αποτέλεσμα: `200 OK`,
`Length: 12874` (το μέγεθος που **δήλωσε** ο εξυπηρετητής), και
`saved [12874/12874]` — **ολοκληρώθηκε, όχι μερικά**. Αν δείτε `[8192/12874]`, η λήψη
διακόπηκε και το αρχείο είναι άχρηστο.

**Η `md5sum` είναι η πειθαρχία που σώζει ώρες.** Τρέξτε την **και στις δύο πλευρές** και
συγκρίνετε. Ένα κατεβασμένο exploit με ένα byte λιγότερο δίνει σφάλμα μεταγλώττισης που
μοιάζει με bug στον κώδικα.

```bash
md5sum exploit.c ofs.c
```
```text
9f2c1e7a4b8d5f6a0e3c2b1d4f5a6b7c  exploit.c
9f2c1e7a4b8d5f6a0e3c2b1d4f5a6b7c  ofs.c
```

Ίδια τιμή = ίδιο περιεχόμενο. **Σημείωση:** το MD5 δεν είναι πια κατάλληλο για *υπογραφές*
(σπάνε με σύγκρουση), αλλά για **έλεγχο ακεραιότητας μεταφοράς** είναι μια χαρά και γρήγορο.

### 7.14 `printf '%s'` έναντι `echo`

```bash
printf '%s' 'aGVsbG8=' | base64 -d ; echo
echo 'aGVsbG8=' | base64 -d ; echo
```

```text
hello
hello
```

Εδώ και τα δύο δουλεύουν. Αλλά δεν είναι ισοδύναμα:

```bash
printf '%s' 'abc' | wc -c     # → 3
echo 'abc' | wc -c            # → 4   (τρία γράμματα + newline)
```

Η **`echo` προσθέτει πάντα ένα newline**. Για ανάγνωση βάσης-64 συνήθως δεν πειράζει· για
**δημιουργία αρχείων με ακριβή bytes, κρυπτογραφικά hashes, και συγκρίσεις** πειράζει πολύ.
**Κανόνας: για δυαδικά/ακριβή δεδομένα, `printf '%s'`.**

Επίσης: η `echo -e` και η `echo -n` συμπεριφέρονται **διαφορετικά** σε bash, dash και
διαφορετικές εκδόσεις των coreutils. Η `printf` είναι καθορισμένη από το POSIX και συμπεριφέρεται
το ίδιο παντού — γι' αυτό και τη χρησιμοποιούμε σε αυτή τη διαδρομή.
