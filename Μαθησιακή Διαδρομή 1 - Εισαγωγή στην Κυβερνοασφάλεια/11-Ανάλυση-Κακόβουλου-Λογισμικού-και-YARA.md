# Κεφάλαιο 11 — Ανάλυση Κακόβουλου Λογισμικού και YARA

> **Διαβάστε το πριν από:** τα μηχανήματα της επεκταμένης τροχιάς (DFIR) και κάθε φορά που ένα
> μηχάνημα σας δίνει ένα άγνωστο binary ή ένα συσκοτισμένο blob.
> **Γιατί υπάρχει.** Κάθε κεφάλαιο μέχρι εδώ ήταν *επιθετικό*. Αυτό γυρίζει τον φακό: δεδομένου
> ενός ύποπτου αρχείου, πώς βρίσκετε **τι κάνει** — με ασφάλεια — και πώς γράφετε έναν **κανόνα**
> που το πιάνει και αυτό και την οικογένειά του ξανά; Αυτή είναι η καθημερινή δουλειά ενός αναλυτή
> SOC/DFIR, και είναι το φυσικό αντίστοιχο όλων όσων μάθατε για κελύφη, εμμονή και κωδικοποίηση.

**Πλήρης ανάπτυξη:** [`docs/CONCEPTS.md`](../docs/CONCEPTS.md) §10 και §16.

---

## 1. Οι δύο τρόποι ανάλυσης

| | **Στατική ανάλυση** | **Δυναμική ανάλυση** |
| --- | --- | --- |
| Κοιτά | το αρχείο **χωρίς να το τρέξει** | το αρχείο **ενώ τρέχει**, απομονωμένα |
| Εργαλεία | `file`, `strings`, `binwalk`, `objdump`, `rabin2`, YARA | sandbox, `strace`, `ltrace`, `tcpdump` |
| Ασφαλής; | ναι | μόνο σε **αναλώσιμο, απομονωμένο** VM |
| Το νικούν | packing, κρυπτογράφηση, συσκότιση | anti-VM / anti-debug έλεγχοι |

**Κανόνας μηδέν: ποτέ μην τρέχετε άγνωστο κώδικα στον σταθμό εργασίας σας.** Η ανάλυση γίνεται σε
VM με snapshot και **χωρίς** διαδρομή προς το LAN ή το διαδίκτυο (η πειθαρχία του Κεφαλαίου 00
ισχύει διπλά εδώ).

---

## 2. Στατική ανάλυση, βήμα-βήμα

```bash
file sample.bin                 # τι είναι; (ELF, PE, script, archive)
sha256sum sample.bin            # το HASH είναι η ταυτότητα του αρχείου — μοιραστείτε αυτό
strings -n 8 sample.bin | head  # κείμενο: URLs, διαδρομές, εντολές
strings -e l sample.bin         # UTF-16 strings (συνηθισμένο σε malware Windows)
binwalk sample.bin              # ενσωματωμένα αρχεία / appended data
rabin2 -I sample.bin            # headers, imports, sections (radare2)
objdump -d sample.bin | head    # αποσυμβολισμός (x86)
```

Τι να ψάξετε:

| Artefact | Γιατί μετράει |
| --- | --- |
| **Hash** (MD5/SHA-256) | το IOC στο οποίο περιστρέφεστε (VirusTotal / SIEM) |
| URLs, IPs, domains | υποδομή C2 — μπλοκάρετε τα |
| Διαδρομές (`/etc/cron.d/…`, `~/.ssh/`) | μηχανισμός εμμονής (Κεφάλαιο 06) |
| `base64`, `/dev/tcp`, `nc` | dropper ή reverse shell |
| Sections με υψηλή **εντροπία** | packing/κρυπτογράφηση — η στατική θα κολλήσει |
| Ύποπτα **imports** | `execve`, `socket`, `ptrace`, crypto APIs |

> **Η κωδικοποίηση είναι το σημάδι.** `base64`, βρόχοι XOR και hex blobs μέσα σε binary είναι η ίδια
> συσκότιση που συναντήσατε στο CyberSploit και στο Lord of the Root — το malware χρησιμοποιεί τα
> ίδια κόλπα, και το ίδιο αντανακλαστικό (αποκωδικοποίησε, μετά διάβασε) δουλεύει.

## 3. Δυναμική ανάλυση, με ασφάλεια

```bash
# μέσα σε αναλώσιμο VM, χωρίς δίκτυο (ή με ψεύτικο)
strace -f -e trace=network ./sample.bin      # ποια syscalls/συνδέσεις;
ltrace ./sample.bin                          # κλήσεις βιβλιοθήκης
inetsim / fakenet                            # ψεύτικο διαδίκτυο για παρατήρηση C2
tcpdump -i any -w capture.pcap               # καταγραφή του τι προσπαθεί να φτάσει
```

Προσέξτε: αρχεία που δημιουργούνται/τροποποιούνται, νέους χρήστες/cron, εξερχόμενες συνδέσεις,
διεργασίες που ξεκινούν, και **αντι-ανάλυση** (βρόχοι ύπνου, ανίχνευση VM, self-attach `ptrace`).

## 4. YARA — περιγράφοντας το malware για να πιαστεί ξανά

Το **YARA** ταιριάζει **μοτίβα** σε αρχεία. Ένας *κανόνας* είναι: κάποια strings + μια συνθήκη. Τον
γράφετε μία φορά· βρίσκει το malware (και παραλλαγές) παντού μετά — σε δίσκο, μνήμη, pcap.

### 4.1 Ανατομία ενός κανόνα

```yara
rule Reverse_Shell_Bash
{
    meta:
        author      = "Cybersecurity101"
        description = "Bash /dev/tcp reverse shell"
        reference   = "Κεφάλαιο 06"
        severity    = "high"

    strings:
        $tcp   = "/dev/tcp/" ascii
        $sh    = "bash -i" ascii nocase
        $redir = "0>&1" ascii

    condition:
        2 of them
}
```

| Τμήμα | Σημασία |
| --- | --- |
| `meta` | ανθρώπινες σημειώσεις (συγγραφέας, περιγραφή, σοβαρότητα) — δεν ταιριάζεται |
| `strings` | τα μοτίβα, καθένα με όνομα `$…` |
| `condition` | μια **λογική έκφραση** πάνω στα strings |

### 4.2 Είδη strings και modifiers

```yara
$text  = "cmd.exe" ascii wide nocase fullword
$hex   = { 6A 40 68 00 30 00 00 }         // hex bytes, ?? = wildcard
$re    = /https?:\/\/[0-9a-zA-Z.\/]+/      // regular expression
```

| Modifier | Αποτέλεσμα |
| --- | --- |
| `ascii` / `wide` | ταιριάζει ASCII ή UTF-16 |
| `nocase` | αγνοεί πεζά/κεφαλαία |
| `fullword` | πρέπει να είναι ολόκληρη λέξη, όχι substring |
| `xor` | ταιριάζει και απλές XOR-συσκοτισμένες μορφές |

### 4.3 Συνθήκες

```yara
condition:
    $a and $b                     // και τα δύο
    2 of ($a, $b, $c)             // οποιαδήποτε δύο
    all of them                   // όλα
    any of them                   // τουλάχιστον ένα
    $a and filesize < 1MB         // string + ιδιότητα αρχείου
    #tcp > 3                      // πλήθος ταιριασμάτων του $tcp
```

### 4.4 Εκτέλεση YARA

```bash
yara rule.yar sample.bin                 # σάρωση ενός αρχείου
yara -r rules/ /path/to/dir              # αναδρομή σε κατάλογο
yara -s rule.yar sample.bin              # -s: δείξε τα strings που ταίριαξαν
yara -w rule.yar sample.bin              # -w: απόκρυψη προειδοποιήσεων
```

```text
Reverse_Shell_Bash sample.bin
```

Ένα hit είναι **υπόδειξη, όχι ετυμηγορία** — επαληθεύστε το (τα ψευδώς θετικά είναι συνηθισμένα με
κοντά strings). Αυτή η πειθαρχία είναι η ίδια με του απολογισμού: ένα αυτόματο ταίριασμα είναι
υποψήφιο· ο άνθρωπος το επιβεβαιώνει.

### 4.5 Δεύτερος κανόνας — ευρετική συσκότισης

```yara
rule Suspicious_Base64_Blob
{
    strings:
        $b64 = /[A-Za-z0-9+\/]{200,}={0,2}/   // πολύ μεγάλο base64
    condition:
        $b64
}
```

## 5. Από την ανάλυση στην άμυνα

| Βρήκατε | Αμυντικός έλεγχος |
| --- | --- |
| Hash του δείγματος | blocklist σε EDR/AV, ανίχνευση SIEM |
| Domain/IP C2 | DNS sinkhole, deny εξόδου στο τείχος (Κεφάλαιο 10) |
| Διαδρομή εμμονής | file-integrity monitoring (AIDE/Tripwire), κανόνες auditd |
| Κανόνα YARA | ανάπτυξη στον στόλο· αναδρομικό κυνήγι στο ιστορικό |
| Σκληροκωδικοποιημένο κλειδί/URL | περιστροφή του μυστικού, patch του builder |

> **Αυτό κλείνει τον κύκλο όλης της διαδρομής.** Μάθατε να *φτιάχνετε* ένα κέλυφος, να το *κρύβετε*
> (κωδικοποίηση, εμμονή), και τώρα να το *αναγνωρίζετε* και να γράφετε *ανιχνεύσεις*. Η κατανόηση
> της επίθεσης είναι αυτό που κάνει δυνατή την ανίχνευση — και η ανίχνευση κάνει τη δεξιότητα επάγγελμα.

## 6. Πού το εξασκείτε

Το αποθετήριο **δεν έχει ακόμη ειδικό μηχάνημα YARA/malware**, αλλά αυτά τα εργαστήρια εξασκούν τις
γειτονικές δεξιότητες (συσκότιση, κρυμμένα αρχεία, forensics), και δύο είναι ιδανικά για επέκταση:

| Μηχάνημα | Τι διδάσκει εδώ |
| --- | --- |
| [`2-002-cybersploit-1`](../labs/2-002-cybersploit-1/README.md) | αποκωδικοποίηση συσκοτισμένων blobs — το βασικό αντανακλαστικό στατικής ανάλυσης |
| [`5-097-tr0ll-2`](../labs/5-097-tr0ll-2/README.md) | forensics μεταδεδομένων, `binwalk`, `steghide`, `strings` |
| [`8-533-proteus-1`](../labs/8-533-proteus-1/README.md) *(stub)* | θέμα «εργαλείου ανάλυσης malware» |
| [`8-324-ha-forensics`](../labs/8-324-ha-forensics/README.md) *(stub)* | αφιερωμένο CTF cyber-forensics |
| [`8-330-ha-sherlock`](../labs/8-330-ha-sherlock/README.md) *(stub)* | CTF έρευνας forensics |

> **Προτεινόμενη άσκηση επέκτασης.** Πάρτε οποιοδήποτε reverse-shell payload από το Κεφάλαιο 06,
> γράψτε κανόνα YARA που το ανιχνεύει, μετά τρέξτε τον σε έναν φάκελο με τα walkthroughs και δείτε
> πόσα σημαίνει — και μετά συντονίστε τον κανόνα ώστε να κόψετε τα ψευδώς θετικά. Μόλις φτιάξατε και
> επικυρώσατε μια ανίχνευση.

## 7. Ασκήσεις

1. `file`, `sha256sum`, `strings`, `binwalk` σε ένα binary του `/usr/bin`· γράψτε «προφίλ» τριών
   γραμμών σαν να ήταν δείγμα.
2. Γράψτε κανόνα YARA που ταιριάζει το **base64** blob του CyberSploit και δοκιμάστε τον.
3. Γράψτε κανόνα για `nc -e` και `/dev/tcp`, και εξηγήστε πώς το `fullword` μειώνει τα ψευδώς θετικά.
4. Τρέξτε ένα αθώο πρόγραμμα υπό `strace -f -e trace=network` και απαριθμήστε κάθε δικτυακή κλήση.
5. Γράψτε κανόνα με `meta`, τρία strings και συνθήκη `2 of them`· τεκμηριώστε συγγραφέα και σοβαρότητα.

## 8. Ελέγξτε τον εαυτό σας

1. Δώστε δύο λόγους που η στατική ανάλυση κολλάει, και τι κάνετε μετά.
2. Γιατί μοιράζεστε το **hash** και όχι το ίδιο το δείγμα;
3. Ονομάστε τα τρία τμήματα ενός κανόνα YARA και τον σκοπό του καθενός.
4. Τι αλλάζει το `nocase`, και πότε είναι επικίνδυνο;
5. Γιατί ένα hit του YARA είναι «υπόδειξη, όχι ετυμηγορία»;

## 9. Σημειωμένες εντολές — κάθε είσοδος, κάθε έξοδος

### 9.1 `file`, `sha256sum`, `strings`

```bash
file /usr/bin/ls
sha256sum /usr/bin/ls
strings -n 8 /usr/bin/ls | grep -iE 'http|/tmp/|base64' | head
```

Το `file` διαβάζει **magic bytes**· το `sha256sum` δίνει την ταυτότητα· το `strings` εξάγει
εκτυπώσιμες ακολουθίες — η γρηγορότερη τριάδα triage.

### 9.2 `binwalk`

```bash
binwalk firmware.bin
binwalk -e firmware.bin     # -e: εξαγωγή ενσωματωμένων συστημάτων αρχείων
```

Αναφέρει υπογραφές κατά σειρά offset — ένα ZIP ή gzip κρυμμένο μετά από header εμφανίζεται αμέσως.

### 9.3 `yara`

```bash
yara -s rule.yar sample.bin
yara -r rules/ ~/samples/
```

```text
Reverse_Shell_Bash sample.bin
0x1a4:$tcp: /dev/tcp/
```

Με το `-s`, κάθε γραμμή hit είναι `offset:$όνομα: ταιριασμένο κείμενο` — τα ακριβή bytes που ταίριαξαν,
πώς επιβεβαιώνετε (ή διαψεύδετε) το hit.

### 9.4 `strace` (δυναμική)

```bash
strace -f -e trace=network ./sample.bin 2>&1 | grep -E 'connect|socket'
```

Οι γραμμές `connect(...)` αποκαλύπτουν κάθε προορισμό που προσπάθησε το δείγμα — η λίστα C2.
