# Κεφάλαιο 09 — Κρυπτογραφία στην Πράξη: GPG και Κρυπτογράφηση Αρχείων

> **Διαβάστε το πριν από:** το Μηχάνημα 2 (κωδικοποίηση vs κρυπτογράφηση) και τα μηχανήματα της
> επεκταμένης τροχιάς που κρύβουν μυστικά σε κρυπτογραφημένη μορφή (DC-7, Prime 1).
> **Γιατί υπάρχει.** Το Κεφάλαιο 04 ξεκαθάρισε **κωδικοποίηση vs κατακερματισμό**. Αυτό το
> κεφάλαιο προσθέτει το τρίτο σκέλος — την **κρυπτογράφηση** — και το εργαλείο που θα συναντήσετε
> στην πράξη: το **GPG**. Θα δημιουργήσετε ζεύγος κλειδιών, θα κρυπτογραφήσετε και θα υπογράψετε,
> θα αποκρυπτογραφήσετε ένα συμμετρικό αρχείο, και θα καταλάβετε γιατί ένα κρυπτογραφημένο
> αντίγραφο ασφαλείας είναι τόσο δυνατό όσο το σημείο όπου αποθηκεύεται η **φράση πρόσβασης**.
> Αυτή η τελευταία πρόταση είναι όλη η πλοκή του DC-7.

**Πλήρης ανάπτυξη:** [`docs/CONCEPTS.md`](../docs/CONCEPTS.md) §10 και §14.

---

## 1. Οι τρεις μετασχηματισμοί, για τελευταία φορά

| | **Κωδικοποίηση** | **Κατακερματισμός** | **Κρυπτογράφηση** |
| --- | --- | --- | --- |
| Σκοπός | αναπαράσταση δεδομένων | ακεραιότητα / μυστικό **μονόδρομο** | **απόκρυψη**, **αναστρέψιμα** |
| Κλειδί; | όχι | όχι (ή salt) | **ναι** |
| Αντιστρέφεται; | τετριμμένα | όχι | μόνο με το κλειδί |
| Παράδειγμα | `base64`, hex | `md5sum`, `$6$` | GPG, `openssl enc`, LUKS |
| Σημάδι σε CTF | λύνεται αμέσως | το *σπας* | χρειάζεται κλειδί |

> **Το λάθος να σκοτώσετε τώρα:** να αποκαλείτε το `base64` «κρυπτογράφηση». Το base64 **δεν έχει
> κλειδί**· δεν κρύβει τίποτα. Αν το αντιστρέφετε με μία εντολή, είναι **κωδικοποίηση**.

---

## 2. Συμμετρική κρυπτογράφηση — ένα κλειδί

Ένα μυστικό (φράση πρόσβασης) κρυπτογραφεί **και** αποκρυπτογραφεί.

### 2.1 GPG συμμετρικό

```bash
gpg --symmetric --cipher-algo AES256 secrets.tar      # γράφει secrets.tar.gpg
gpg --decrypt secrets.tar.gpg > secrets.tar
```

### 2.2 `openssl enc`

```bash
openssl enc -aes-256-cbc -pbkdf2 -salt -in plain.txt -out cipher.bin
openssl enc -d -aes-256-cbc -pbkdf2 -in cipher.bin -out plain.txt
```

> **Το κλασικό λάθος που θα εκμεταλλευτείτε.** Μερικά παλιά scripts χρησιμοποιούν
> `openssl enc -aes-256-ecb -K <hexkey>`: **ECB** mode (χωρίς IV, ντετερμινιστικά blocks — τα
> μοτίβα διαρρέουν) με **σκληροκωδικοποιημένο κλειδί**. Και τα δύο είναι αδυναμίες αναφοράς.
> Το Prime 1 σας δίνει ακριβώς αυτό, με το κλειδί μέσα στο script.

### 2.3 Κρυπτογράφηση τόμου/δίσκου

```bash
sudo cryptsetup luksFormat /dev/sdb1          # δημιουργία LUKS container
sudo cryptsetup luksOpen  /dev/sdb1 vault      # ξεκλείδωμα -> /dev/mapper/vault
sudo cryptsetup luksDump /dev/sdb1            # επιθεώρηση (χωρίς φράση πρόσβασης!)
```

Το `luksDump` διαρρέει τον αλγόριθμο, τον αριθμό key-slots και τις **επαναλήψεις** χωρίς τη φράση
πρόσβασης — χρήσιμο για αξιολόγηση κινδύνου από αμυνόμενο και για σχέδιο σπασίματος από επιτιθέμενο.

## 3. Ασύμμετρη κρυπτογράφηση — ζεύγος κλειδιών (αυτό είναι «έκδοση κλειδιών GPG»)

Δύο κλειδιά: ένα **δημόσιο** που το δίνετε, και ένα **ιδιωτικό** που δεν δίνετε ποτέ. Ό,τι κλειδώνει
το ένα, το ανοίγει μόνο το άλλο — που δίνει και **υπογραφές**.

### 3.1 Δημιουργία ζεύγους κλειδιών

```bash
gpg --full-generate-key
```

```text
Please select what kind of key you want:
   (1) RSA and RSA
   ...
   (9) ECC (sign and encrypt) *default*
Your selection? 1
What keysize do you want? 4096
Key is valid for? (0) 2y
Real name: Alice Doe
Email address: alice@example.org
```

Μόλις κάνατε **έκδοση κλειδιών**: ένα ζεύγος με ταυτότητα, αλγόριθμο, μέγεθος και **λήξη**.

```bash
gpg --list-keys
gpg --list-secret-keys --with-keygrip
```

### 3.2 Export / import — διανομή του δημόσιου κλειδιού

```bash
gpg --armor --export alice@example.org > alice.pub.asc   # μοιραστείτε το
gpg --import alice.pub.asc
gpg --fingerprint alice@example.org                      # η ταυτότητα που επαληθεύετε
```

> **Επαληθεύστε το αποτύπωμα εκτός ζώνης.** Ένα δημόσιο κλειδί είναι αξιόπιστο μόνο αν το αποτύπωμα
> ήρθε από κανάλι που δεν ελέγχει ο επιτιθέμενος. Γι' αυτό οι **keyservers από μόνοι τους δεν
> αρκούν** και υπάρχει το Web of Trust.

### 3.3 Κρυπτογράφηση, αποκρυπτογράφηση, υπογραφή, επαλήθευση

```bash
gpg --encrypt --recipient alice@example.org file.txt      # -> file.txt.gpg
gpg --decrypt file.txt.gpg > file.txt                     # χρειάζεται το ΙΔΙΩΤΙΚΟ της Alice
gpg --clearsign message.txt                               # υπογραφή, παραμένει αναγνώσιμο
gpg --detach-sign --armor file.txt                        # υπογραφή file.txt.asc
gpg --verify file.txt.asc file.txt                        # έλεγχος υπογραφής
```

| Λειτουργία | Κλειδί | Αποδεικνύει |
| --- | --- | --- |
| Κρυπτογράφηση | **δημόσιο** του παραλήπτη | μόνο ο παραλήπτης διαβάζει |
| Αποκρυπτογράφηση | **ιδιωτικό** του παραλήπτη | ότι είστε ο παραλήπτης |
| Υπογραφή | **ιδιωτικό** του υπογράφοντος | ότι το έγραψε αυτός |
| Επαλήθευση | **δημόσιο** του υπογράφοντος | ότι το μήνυμα δεν άλλαξε |

### 3.4 Η διαχείριση κλειδιών είναι η πραγματική ασφάλεια

```bash
gpg --edit-key alice@example.org      # προσθήκη UID, αλλαγή λήξης, ανάκληση
gpg --export-secret-keys --armor > backup.asc   # ΑΝΤΙΓΡΑΦΟ, μετά προστατέψτε το
```

Ένα ιδιωτικό κλειδί **χωρίς φράση πρόσβασης**, εξαγμένο σε ευανάγνωστο αρχείο, ισούται με
plaintext κωδικό. Ελέγξτε τα δικαιώματα του `~/.gnupg/` — ένας κατάλογος `.gnupg` που μπορείτε να
διαβάσετε σε έναν στόχο είναι εύρημα (Chill Hack, HA: Rudra).

## 4. Κρυπτογραφημένα αρχεία και η σύγχρονη εναλλακτική

```bash
zip -e archive.zip secret.txt          # zip με κωδικό
7z a -p -mhe=on archive.7z secret.txt  # AES-256, κρυπτογραφεί και τα ονόματα
age -r <public-key> -o out.age in.txt  # απλή, σύγχρονη κρυπτογράφηση αρχείου
age -d -i key.txt -o in.txt out.age
```

Τα `zip2john` / `7z2john` / `pdf2john` τα μετατρέπουν σε hashes προς σπάσιμο (Κεφάλαιο 04 §8.6). Μια
αδύναμη φράση αρχείου πέφτει στο `rockyou.txt` σε δευτερόλεπτα.

## 5. Πού σπάει η κρυπτογράφηση — το μάθημα του DC-7

Στο **DC: 7** η προβλεπόμενη διαδρομή **δεν** είναι «σπάσε το AES». Είναι:

1. Ένα root cron τρέχει **GPG-κρυπτογραφημένο** αντίγραφο της ιστοσελίδας.
2. Η εργασία στέλνει την έξοδό της με email — και η **φράση πρόσβασης είναι μέσα στο script**,
   που διαρρέει στο `mbox` του root (`/var/mail/…`).
3. Διαβάζετε το mail, παίρνετε τη φράση, και τρέχετε `gpg --decrypt website.sql.gpg` μόνοι σας.

> **Η αρχή, μία φορά:** *η κρυπτογράφηση προστατεύει δεδομένα **σε ηρεμία** και **εν κινήσει**· δεν
> προστατεύει από ένα κλειδί που αποθηκεύεται δίπλα στο κρυπτοκείμενο.* Η κρυπτογραφία δεν ήταν
> ποτέ το αδύναμο σημείο — η **διαχείριση κλειδιών** ήταν. Κάθε «κρυπτογραφημένο» εύρημα σε αυτά τα
> μηχανήματα είναι στην πραγματικότητα εύρημα διαχείρισης κλειδιών.

## 7. Ασκήσεις

1. Κάντε `gpg --symmetric` ένα αρχείο και αποκρυπτογραφήστε το. Σβήστε το plaintext και αποδείξτε
   ότι το κρυπτοκείμενο μόνο του είναι άχρηστο χωρίς τη φράση.
2. Δημιουργήστε ζεύγος RSA 4096 με λήξη 1 έτους, εξάγετε μόνο το **δημόσιο**, και κρυπτογραφήστε
   μήνυμα προς τον εαυτό σας από *άλλο* keyring.
3. Υπογράψτε αρχείο, αλλάξτε ένα byte, και δείξτε ότι το `gpg --verify` αποτυγχάνει.
4. Κρυπτογραφήστε με `openssl enc -aes-256-cbc -pbkdf2` και με `-aes-256-ecb`· κρυπτογραφήστε το
   *ίδιο* plaintext δύο φορές σε κάθε mode και εξηγήστε ποια έξοδος είναι ντετερμινιστική και γιατί.
5. Τρέξτε `cryptsetup luksDump` και απαριθμήστε τι αποκαλύπτει χωρίς τη φράση.

## 8. Ελέγξτε τον εαυτό σας

1. Δώστε μία εντολή που αντιστρέφει καθένα από: base64, SHA-256, GPG συμμετρικό. Τι αποδεικνύει το καθένα;
2. Στο `gpg --encrypt -r bob`, ποιου κλειδί χρησιμοποιείται, και ποιο αποκρυπτογραφεί;
3. Τι αποδεικνύει μια **αποσπώμενη υπογραφή** που δεν το κάνει ένα checksum;
4. Γιατί το ECB είναι πιο αδύναμο από το CBC με το ίδιο κλειδί;
5. Δηλώστε την αδυναμία του DC-7 σε μία πρόταση — και ονομάστε τον έλεγχο που θα τη διόρθωνε.

## 9. Σημειωμένες εντολές — κάθε είσοδος, κάθε έξοδος

### 9.1 `gpg --full-generate-key` και `--list-keys`

```bash
gpg --full-generate-key
gpg --list-keys --keyid-format long
```

```text
pub   rsa4096/3A5B7C9D2E1F0A4B 2024-05-11 [SC] [expires: 2026-05-11]
      8F2C 1D44 9A03 7B6E 5C10  3A5B 7C9D 2E1F 0A4B 6E77
uid                 [ultimate] Alice Doe <alice@example.org>
sub   rsa4096/1F0A4B6E77C9D2E1 2024-05-11 [E]
```

`pub` = δημόσιο, `sub` = υποκλειδί κρυπτογράφησης, `[SC]` = **S**ign + **C**ertify, `[E]` =
**E**ncrypt. Το **αποτύπωμα** 40 hex ψηφίων είναι η ταυτότητα που επαληθεύετε.

### 9.2 Συμμετρικός κύκλος

```bash
echo 'flag{test}' > p.txt
gpg -c --cipher-algo AES256 p.txt
file p.txt.gpg
gpg -d p.txt.gpg
```

Το `file` αναφέρει `GPG symmetrically encrypted data (AES256 cipher)` — ονομάζει τον αλγόριθμο
χωρίς τη φράση, όπως το `luksDump`.

### 9.3 `openssl enc` αδύναμο vs ισχυρό

```bash
openssl enc -aes-256-cbc -pbkdf2 -salt -in p.txt -out strong.bin
openssl enc -aes-256-ecb -K 00112233445566778899aabbccddeeff -in p.txt -out weak.bin
openssl enc -d -aes-256-ecb -K 00112233445566778899aabbccddeeff -in weak.bin
```

Το κλειδί `-K` είναι ορατό στην εντολή/script — ένα σκληροκωδικοποιημένο μυστικό δεν είναι μυστικό.

### 9.4 Επαλήθευση υπογραφής

```bash
gpg --detach-sign --armor p.txt
gpg --verify p.txt.asc p.txt
```

```text
gpg: Good signature from "Alice Doe <alice@example.org>" [ultimate]
```

`Good signature` = το μήνυμα δεν άλλαξε **και** υπογράφηκε από αυτό το κλειδί. **Δεν** λέει ότι το
κλειδί ανήκει σε όποιον ισχυρίζεται — αυτό είναι το βήμα επαλήθευσης αποτυπώματος.
